# 各ステージのタイル（工程 4）設計

作業「仲間・村・難易度・絵の仕上げ」の工程 4。2026-11-12 に依頼者と相談して決めた。

## 目的と理由

セリフでは「川の音が近づいてきた」「切りかけの石が山のように積んである」「たき火がいくつもともっている」と言っているのに、
ステージ 2〜10 のマップは、村のマスを除いて歩ける・歩けないを単色で塗り分けただけになっている。だから雰囲気が出ない（依頼者）。
この工程で、**全 10 ステージを、セリフが言っている場所に見えるタイルにする**。

## 目標

- 全 10 ステージ（今タイルが敷いてあるステージ 1 も含めて見直す）を、本物のタイルで描く
- マップの形（歩ける・歩けないの配置）を、場所らしく見えるように描き直す（依頼者が許可）
- forge に無いタイルは forge で新しく描く
- 夜の野営地は、全体を暗くし、たき火のまわりだけ明るく、ランプの光がぼうっと見えるようにする（依頼者の言葉）。うす暗い魔導士の塔も同じ見せ方にする

## 目標にしないこと

- 難易度の調整。形を描き直すと勝率が変わるが、この工程では直さない。`npm run balance` で測って記録するだけ（依頼者「別にどうもしません。後でまた調整します」）
- セリフ・敵の種類・強さ・勝利条件・時間湧きの設定・村の効果の変更
- 移動・攻撃・視線のルールの変更（水や壁が視線を遮るかなど。今の「歩けないマスは視線も遮る」のまま。下の「制約」）
- 工程 5 に入れる残課題（HANDOVER.md の一覧）には触れない

## 失敗とみなすもの

- 見た目は場所らしくなったが、セリフで言っている遊び方の骨組みが崩れた（下の表の「残す骨組み」）
- タイルの継ぎ目や反復が格子・壁紙に見える、別の物に見える（forge の tile の規約で避けてきたもの）
- 依頼者が見ていない絵・マップを、コミットや次の段階へ進める

## ステージごとの場所と、残す骨組み

「場所」はセリフからの読み取りで、依頼者が「これでよい」とした（2026-11-12）。

## 決まっている作り方

- **タイルは forge（`pixel-asset-forge/`）で描き、`sprites.json` と書き出し手順でゲームへ渡す。** forge の tile 型の規約（`types/tile/SPEC.md`）にそのまま従う: 16×16、光源は左上、全周に輪郭を回さない、シームレス。1 マスを占める物は 16px の部品 4 枚を 2×2 に組んだ 32px のセット（`sets/`）。物は地面（草など）を背景に含めて描く。1 マスを 1 つの大きな物で埋めない
- **新しいセットを作ったら、その全点を置いたレイアウトを `layouts/` に足す**（forge の決まり）。目視は `tilemap.py` で 3 通り（継ぎ目・反復・`--layout`）、締めは `--layout`
- **夜の野営地の暗さは、ゲームの描画で出す。** 画面（マップ）に暗い膜を重ね、たき火とランプの位置だけを明るく抜く。ユニットも暗くなる（依頼者に説明済み、違和感の指摘は無かった）。夜用の色でタイルを描き分ける方法は採らない
- **魔導士の塔（stage7）も同じ仕組みで暗くし、燭台のまわりだけを明るくする**（依頼者 Yes）。そのため暗さと明かりは、ステージごとの設定として持つ（暗さの無いステージは今までどおり）
- **明かりは、輪の大きさと明るさだけをゆっくり少し揺らす。たき火・ランプ・燭台の絵は止まった 1 枚のまま**（Claude の推し。依頼者が推しを尋ねた）。タイルを動かす仕組みは足さない。炎の動きが物足りなければ、工程 5 でコマ絵を足す
- **stage10 の門は、戦いの間は閉じていて、脇から回り込む**（Claude の判断。終わりのセリフが「門が開いたぞ！」なので）。門は歩けない
- **見せる区切り**（Claude の判断）: マップは、タイルを敷く前に形だけ（歩ける・歩けないと、何の場所か）を見せて承認を得てから、敵などの置き直しとタイル敷きに進む。タイルはセットごとに見せる。最後に、タイルを敷いた全ステージを見せる
- **勝率は測って記録するだけ。** 形を描き直した後に `npm run balance` を走らせ、工程 2 の結果と並べて記録する。帯から外れても直さない
- **絵とマップは、依頼者に見せてから進む。** PNG を data URI で埋め込んだ HTML を Artifact に公開してリンクを渡す（CLAUDE.md・これまでの決まり）
- **forge の確認の道具で落ちたら、道具に従って絵を直す。** 依頼者に途中で聞かない（CLAUDE.md「ドット絵の確認の道具」）

## 進め方（実装の分け方）

Claude の提案で依頼者が承認した分け方。順番の細部は計画で決める。

1. **新しいタイルを forge で描く**（砦・城の外側、石切り場、夜の野営地、川原、関所、塔など）
2. **ゲームの仕組み**（ステージごとの暗さと、揺れる明かり。必要なら 2 マス以上の物の置き方）
3. **マップの描き直し**（10 ステージの `mapRows`・`legend`、敵・開始位置・時間湧き・見張りの持ち場・村の位置の置き直し）

## 制約

- マップは 16 列 × 23 行、`cell` は 32 のまま。外周の扱い、`placement.minY`（528）、`victory.pos`（最上段）は変えない
- `legend` のキーは 1 文字。タイル画像は 16×16（1 マスに 2×2 で敷く）か 32×32（1 枚）しか使えない（`npm test` が落とす）。16px のタイルは 1 マスに同じ絵が 4 枚並ぶので、川の曲がりのように 1 マスの中で形が決まる地形は、32px のセットに組んで渡す必要がある
- 歩けないマスは視線（弓・魔法の射線、見張りの索敵）も遮る（`src/core/field.ts` の `hasLineOfSight`）。川を歩けないマスにすると、川越しには撃てない。ルールは変えないので、骨組み（stage4「向こう岸に弓兵」）は形の側で成り立たせる
- 敵・開始位置・時間湧き・見張りの持ち場は、足元の箱が歩けないマスにかからない位置に置く（起動時エラー）。村の位置は歩けるマスに置く
- `src/engine/loader.test.ts` のいくつかのテストは、歩けるかを「文字が `.` か」や `makeGrid(s.cell, s.mapRows)`（`legend` を渡さない＝`#` 以外は歩ける）で判定している。`.` 以外の歩ける文字や `#` 以外の歩けない文字を使うと、正しく判定できない。`legend` に従って判定するように直す
- `src/core/state.test.ts` に stage1 の木の位置（18 行目・13 列目）を前提にしたテストがある。stage1 の形を変えるなら合わせて直す
- `node tools/gen-placeholder-sprites.mjs` を引数なしで動かさない

## 作り手に任せること

- 各ステージの具体的な形（骨組みを残す範囲で）と、新しく描くタイル・セットの一覧と絵柄
- 2 マス以上を占める物（大きな門など）を、ゲームに仕組みを足して置くか、1 マスずつのタイルに分けて `legend` の別の文字で並べるか
- 夜の膜の暗さ、明かりの半径と色、明かりの位置の持ち方（`legend` のマスの種類に持たせるか、ステージに位置を書くか）
- 新しい色見本を足すかどうか（足すなら forge の決まりどおり `probe_colors.py` で測ってから）
- 勝率の記録の置き場所

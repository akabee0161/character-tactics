# 点数（クリアの速さ） 設計

2026-11-18 に依頼者と合意した内容です。「（Claude の判断）」と書いたものは、依頼者が決めていない点を Claude が決めたものです。

テストプレイで出た 20 件の直しの工程 6。

## 目的と背景

依頼者がテストプレイで感じたこと: **簡単にクリアしようと思ったら時間をかけて回復をすればよく、速くクリアするメリットが無い。**

そこで、クリアにかかった時間を記録し、目安の時間と比べた評価を出して、速くクリアすることに「記録が良くなる」という得を作る。

調べて分かったこと:

- 今は点数もクリアの時間も、どこにも記録していない（セーブ・結果の画面とも）
- 戦闘の時計 `state.time` は、計算が進む間だけ増える（会話・カードで止まっている間は増えない）
- 10 ステージすべての勝ちの条件が `reach` / `by: any`（誰か 1 人がゴールに着けば勝ち）。時間で評価すると、足の速い 1 人だけをゴールへ走らせるのが一番速い。空を飛ぶ仲間（ピコ）は壁を越えて一直線に行ける
- ガウの「駆け抜ける」とピコの「急降下」は届く距離に上限が無く、途中に壁が無ければ一瞬でゴールへ行ける

## 目標

1. クリアした時間を、結果の画面とステージ選択に出す。ステージごとに一番速い時間をセーブに残す
2. 時間を、ステージごとの目安の時間と比べて「金・銀・銅」の評価を出す
3. どんなクリアでも評価を出す（依頼者の指定。走り抜けも遊び方として認める）。そのかわり、**1 人でゴールへ突っ込むと敵に倒される**ように強さを調整する（依頼者の指定）
4. ガウの「駆け抜ける」とピコの「急降下」に、届く距離の上限を付ける（依頼者は「この工程でなくてもよい」。突っ込みを止める調整が技 1 回で崩れるので、この工程に含める。Claude の判断）

## 目標にしないこと

- 速さで経験値などの実利を増やすこと（依頼者が「記録だけ」を選んだ）
- 時間がたつと不利になる仕組み（敵が増える・強くなる）
- 時間以外を足した点数（倒れなかった人数など）
- 勝ちの条件を「敵を全部倒してゴール」に変えること
- 地形（マスの並び）を変えること

## してはいけないこと

- 評価の線を、測るたびに自動で動かすこと。前に取った評価の意味が変わってしまう（依頼者が案 1 を選んだ理由）
- 普通に戦う遊び方の勝率を帯の外に出すこと。`npm run balance -- --check`（40 シード）が終了コード 0 であること

## 進め方の比較

目安の時間をどこで決めるか。

| 案 | 中身 | 長所 | 短所 |
|---|---|---|---|
| **1（採用）** | 各ステージの JSON に金・銀・銅の目安の時間（秒）を書く。最初の値は Claude が測った時間から案を出し、依頼者が表で決める | 遊んで合わなければ数字を 1 つ直すだけ | ステージを足すたびに書く手間がある |
| 2 | `npm run balance` が測ったボットの時間から、毎回計算する | 書く手間が無い | ボットは急がないので線が甘い。調整のたびに線が動き、前の記録の評価が変わる |

依頼者は 1 を選んだ。

記録の形は「時間だけ」「時間＋評価」「点数（時間以外も足す）」から、依頼者が「時間＋評価」を選んだ。速さの得は「記録だけ」「経験値が増える」「遅いと不利」から、依頼者が「記録だけ」を選んだ。走り抜けの扱いは「敵を全部倒したときだけ評価」「どんなクリアでも評価」「勝ちの条件を変える」から、依頼者が「どんなクリアでも評価、ただし 1 人の突っ込みは倒されるように調整」を選んだ。突っ込みの止め方は、依頼者が「敵の配置を変えてよい」を選んだ（数字だけでは、遠くの敵が足の速い仲間に追いつけず止めきれない）。

## 決めたこと

### 時間の測り方

- 戦闘の時計 `state.time` で測る。会話・カード・倒れたときの帯で止まっている間は数えない（Claude の判断）
- 配置の場面は数えない。「始める」を押してからゴールに着くまで
- 記録するのは勝ったときだけ。負けた回の時間は残さない（Claude の判断）
- 画面には秒の端数を切り捨てて「2分14秒」のように出す。1 分未満は「48秒」（Claude の判断）

### 目安の時間と評価

- ステージの JSON に目安の時間を書く。金・銀・銅の 3 つ（秒、整数）。金 < 銀 < 銅 でなければ起動時エラー（Claude の判断）
- 時間が金の目安以下なら金、銀以下なら銀、銅以下なら銅。銅より遅いときは評価を出さず、時間だけ出す（Claude の判断）
- 評価は、セーブの時間と JSON の目安からその場で出す。目安を直すと、前の記録の評価も合わせて変わる（Claude の判断。評価そのものはセーブに書かない）
- 最初の値の決め方（Claude の判断）: 調整を終えた後のステージで、ボットのクリアの時間（`BattleOutcome.seconds`）と、Claude が手で急いで遊んだ時間を測る。それを元に 10 ステージぶんの金・銀・銅の案を表にして Artifact で依頼者に見せ、依頼者が決めた値を JSON に書く
- 手で急いで遊ぶときは、どんな勝ち方でもよい（敵を残して抜けてもよい）。依頼者が「どんなクリアでも評価」と決めたので、金はその遊び方で届く速さに合わせる。表には、ボットの時間（敵を全部倒す）と手の時間（急いだ勝ち方）を並べて出す（Claude の判断）
- 評価の見え方は「金」「銀」「銅」の文字と、それぞれの色（Claude の判断）

### セーブ

- ステージごとの一番速い時間（秒）をセーブに残す。今までのセーブ（この欄が無いもの）は、記録なしとして読む。壊れた値はその項目だけ捨てる（今の `reconcile` の考え方と同じ）
- 一番速い時間より速く勝ったときだけ書き換える

### 結果の画面

- 今の「敵の 本拠地に 到達！」の下に、今回の時間と評価、一番速い記録を出す。一番速い記録を縮めたときは「記録更新」を出す（Claude の判断）
- 仲間の行（8 行）と「次へ」の位置は崩さない

### ステージ選択

- クリア済みのステージの枠に、一番速い時間と評価を出す（今の「クリア済み」の近く）（Claude の判断）

### 1 人の突っ込みを止める

- 各ステージのゴールの手前に、持ち場を離れない見張り（`ai.kind: "guard"`）を置く、または今の敵を移す（依頼者の指定「配置を変えてよい」）。空を飛ぶ仲間を止めるため、弓兵かまじない師を入れる
- 1 ステージの敵の上限 16 体（時間湧きを含む。説得の相手は数えない）は守る。足すより、今の敵を移すのを先に考える（Claude の判断）
- 地形は変えない
- README の「帯に入れるために動かしてよいもの」に、ゴールの手前の敵の配置を足す。正典の決まり「地形・敵の配置・数は動かさない」を、この工程の依頼者の決定に合わせて直す

### 突っ込みの測り方（Claude の判断）

- 止めるのは、普通に進めたレベル（ボットが通しでそのステージに着いたときのセーブのレベル）の仲間まで（依頼者の指定）。育ててから突っ込めば抜けられてよい。育てた場合（+3）では突っ込みを測らない
- `npm run balance` に「突っ込み」の測り方を足す。出撃した仲間のうち 1 人だけをゴールへまっすぐ走らせ、残りは開始位置で待たせる（突っ込む仲間は技も使い、行き先はゴールの方向）。走らせる仲間は、次の 3 通りをそれぞれ測る
  - 飛行でない仲間のうち、一番足の速い仲間
  - 飛行の仲間（出撃していれば）
  - ガウ（出撃していれば。「駆け抜ける」でゴールへ向かう）
- 表に、ステージごとの「突っ込みで勝った割合」を出す。目標は 0%。`--check` は、突っ込みで勝った割合がどれか 1 つでも上限（`RUSH_MAX`、最初の案は 10%）を超えたら終了コード 1
- 所要時間が今の約 4 分から大きく延びないよう、突っ込みは通しのシード数より少ない回数で測ってよい（回数は実装で決める）

### 技の届く距離

- 「駆け抜ける」と「急降下」に、届く距離の上限を `assets/skills.json` の `params` に足す（最初の案は 4 マス = 128px）。上限より遠くを指したら、指した向きに上限の距離だけ進んだ所を行き先にする。その所が歩けない（飛行でない場合）・壁を通る場合は、今と同じく技が出ない（Claude の判断）
- カードの技の一言にも、届く距離が分かる言い方を入れる（Claude の判断）
- 狙う所の表示（技を構えている間の線・丸）も、上限で止めた所に出す（Claude の判断）

### 見せるもの（依頼者に確かめてもらう順）

1. 突っ込みを止めるための各ステージの敵の配置（変える前と後のマップの画像）と、技の距離の上限
2. 目安の時間の表（金・銀・銅、10 ステージ）
3. 結果の画面とステージ選択の見え方（README の CDP 手順で撮った画像）

どれも、PNG を data URI で埋め込んだ HTML を Artifact で見せ、承認を得てからコミット・次の段階へ進む。

## 勝率

- 敵の配置と技の距離を変えるので、普通の勝率も変わる。`npm run balance -- --check`（40 シード）が終了コード 0 であること（通しの帯 `TARGET_BANDS`・育てた場合の帯 `GROWN_BAND`・突っ込みの上限 `RUSH_MAX`）
- 帯に戻すために動かしてよいのは、今の決まり（能力の数字・伸び・`enemyLevel`・加わったときのレベル・技の基本量・経験値・`bowDamageCap`）と、ゴールの手前の敵の配置
- 突っ込みの上限・普通の勝率の帯・敵 16 体の上限・「加わる頃の仲間が 1 発で倒れない」を同時に満たせないステージが出たら、決まりを緩めたり範囲の外を動かしたりせず、測った数字と案を添えて依頼者に戻す（Claude の判断）

## 実装する人に任せること

- セーブの欄の名前・形と、`SAVE_VERSION` を上げるかどうか
- 目安の時間を書く JSON の欄の名前・形
- 結果の画面とステージ選択の文字の大きさ・位置（見せて承認を得る）
- 突っ込みの測り方の回数と、ボットの細かな動き
- 各ステージのゴールの手前に置く敵の種類と位置（見せて承認を得る）

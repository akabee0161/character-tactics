# 森で移動が遅くなる（issue #6 の⑤）設計

作成: 2026-09-29

## 目的

pixel-asset-forge の issue #6「移動できないタイルとは別に、移動速度が遅くなるタイルを作りたい。森は移動速度が遅くなる」への、ゲーム側の対応。
通れるが遅くなるマス（森）を作り、stage1 に置いて確かめる。

## 決めたこと

依頼者の判断:

- 仕組みを作り、stage1 に森を実際に置いて動作を確かめる
- 森の中の速さは 0.5倍。ステージの `legend` の項目に倍率を書く
- 森を避けた方が早く着くなら回り道する。森を通るのが最短なら通る
- 回り道の決め方は「まっすぐの道が森にかかるときだけフローフィールドに従う」（下記。時間を比べる案・Theta* などの案は採らない）

前提（依頼者に示して異論なし）:

- 敵も味方も同じく遅くなる。敵の追跡も同じ仕組みで回り道する
- どのマスにいるかは足元の点（`u.pos`）で決める。足元の箱が森にかかっていても、足元の点が森の外なら遅くならない
- 倍率は 0 より大きく 1 以下だけ認める（速くなるマスは作らない）
- 詰め寄り（`closeIn`）は今どおり相手へまっすぐ進み、森では遅くなるだけ
- かけぬける（`kakenukeru`）は一瞬で移る技なので森の影響を受けない

## 1. データ（legend と Grid）

- `LegendEntry`（`src/engine/schema.ts`）に `speed`（省略可）を足す。例: `{ "tile": "tile-forest.png", "walkable": true, "speed": 0.5 }`
  - 省略時は 1
  - 検査: 0 より大きく 1 以下の数。外れたら起動時エラー（今の legend の検査と同じ書き方・同じ文体のメッセージ）
  - `walkable: false` の項目に `speed` を書いたらエラー（意味が無い値を黙って受け入れない）
- `Grid`（`src/core/types.ts`）に `speed: number[]`（マスごとの倍率）を足し、`makeGrid` が legend から埋める。legend が無いステージ・legend に `speed` が無い項目は 1
- `DEFAULT_LEGEND` は変えない

## 2. 移動と道の選び方

### 速さ

- `src/core/field.ts` に `speedAt(grid, pos)`（足元の点のマスの倍率）を足す
- 1歩の長さを `u.speed * speedAt(grid, u.pos) * dt` にする。使う場所は `src/core/sim.ts` の `moveTowardGoal` と `closeIn` の2か所。倍率はその tick の始めにいるマスで決める

### フローフィールドのコスト

- 隣のマスへ移るコストを「半分は出るマス、半分は入るマスを進む」とみなし、
  `基本コスト / 2 ÷ 出るマスの倍率 + 基本コスト / 2 ÷ 入るマスの倍率` を丸めた整数にする（基本コストは今の `ORTHO_COST` 10・`DIAG_COST` 14）
  - 縦横: 草→草 10、草↔森 15、森→森 20
  - 斜め: 草→草 14、草↔森 21、森→森 28
- 向きで値が変わらないので、ゴールから逆向きにたどる今の `computeFlowField` の計算がそのまま正しい
- `flowDirection` は変えない（隣のマスのうち距離が最も小さいものへ向かう）

### 直行するかどうか

- 今の `moveTowardGoal` は、足元の箱ごとまっすぐ行ける（`hasClearPath`）か、目的地と同じマスにいるなら、フローフィールドを使わず直行する
- ここに「**足元の点から目的地への線が、倍率1でないマスを1つも通らない**」を足す。まっすぐ行けても線が森を通るなら、フローフィールドに従う。同じマスにいるときは今どおり直行する
- 線が通るマスを調べる処理は `hasLineOfSight` の DDA と同じ。「線が通るマスがすべて条件を満たすか」を調べる関数に切り出し、`hasLineOfSight`（通れるか）と新しい判定（倍率1か）の両方から使う。`hasLineOfSight` の挙動は変えない
- 敵の追跡も `moveTowardGoal` を通るので、同じように回り道する

弱点: 森の中や森の近くでは、マスの中心をたどるのでカクカク曲がって進む（依頼者と合意済み）。

## 3. ステージ・絵

### stage1 に森を置く

- `legend` に `"F": { "tile": "tile-forest.png", "walkable": true, "speed": 0.5 }` を足す
- **9〜12行目・4〜10列目**（0始まり。横7×縦4マス）を `F` にする。左右に草の通り道が残る。既存の木（列2・行11、列13・行18）、岩（列11・行9）、村（列3・行4）、敵（列4・行14、列10・行14、列7・行7）とは重ならない
- この形だと、開始位置（列4・7）からゴール（列7）へ指示すると、森を横切る（コスト 210）より列3へ回る（202）方が安く、回り道する
- 回り道が見て分かるかは画面で確かめる。分かりにくければ森の位置と大きさを調整する（依頼者に画面を見せて決める）

### 絵

- forge の `build/tile/forest.png`（16px。上下左右に継ぎ目なくつながる樹冠）を `assets/images/tile-forest.png` としてコピーする。1マスに 2×2 で敷かれる
- 森の端が四角く切れる点は、依頼者が「いずれ解消する」としていて範囲外

## 4. テスト（TDD）

- スキーマ: `speed` の省略時 1／0 以下・1 より大きい・数でない・`walkable: false` と一緒ならエラー
- `makeGrid`・`speedAt`: legend の倍率がマスに入る。legend が無ければ 1
- `computeFlowField`: 草↔森・森→森のコストが上の値になる／森を横切るより回る方が安いときに回る向きを出す／森の中のゴールにも向かう
- sim:
  - 森の中では1歩が半分になる（`moveTowardGoal` と `closeIn`）
  - まっすぐの線が森にかかると直行せず、フローフィールドに従う
  - 森にかからなければ今までどおり直行する
- 既存のテストはそのまま通ること

## 5. 画面の確認

README の CDP 手順で stage1 を開き、次を撮って依頼者に見せる。

- 森が描かれていること
- ゴールへ指示したとき森を回る動き
- 森の中を指示したとき、森に入って遅くなる動き

## 6. 正典

- README「コンテンツの足しかた」の `legend` の説明に `speed` を書く
- HANDOVER の⑤を更新する

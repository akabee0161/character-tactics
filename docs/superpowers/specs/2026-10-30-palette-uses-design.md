# パレットを「色見本」と「用途の色」に分ける（設計）

2026-10-30。D 敵の組み直し1回目（`docs/superpowers/plans/2026-10-27-enemy-rebuild-1.md`）の Task 4 で、確認の道具が正しい絵を落とした件から始まった。対象は `pixel-asset-forge/`（以下、パスは断りが無ければ forge の直下から）。

## なぜ

Task 4 で、短剣の敵4体を部品から組んで `unit_rules.py` にかけたところ、次の3件が落ちた。

1. `weapon_check` が、ベルトを短剣の柄と取り違えた。ベルトと柄が同じ `wood_base` という色の名前で塗られていて、道具は色の名前で武器を見つけるため。
2. `part_outline` が、ベルト・ぼろ布の当て布・素の髪の、体の上にある縁を「輪郭が無い」と落とした。どれも体の上に描く物で、輪郭が無いのが正しい。
3. `eye_check` が、目の位置を設定ファイルに手で書く作りで、斜めの目（E2）を書けず、兜に完全に隠れた目（knight）も落とした。

依頼者の判断（2026-10-29）: 1 は道具の問題ではなく、**武器を武器と区別できるように塗っていない絵の問題**。武器を確かめる専用の道具があるなら、武器の色は武器専用の色だと分かる形で管理し、描くときもその色を使う決まりが要る（以前にも同じ指摘をしている）。さらに、色の名前で区別するのではなく、**色ごとに説明と属性を書いた管理リスト**を作る。範囲や規模が大きくなってもよいので、あるべき管理方法にする。

今のパレットの実態（2026-10-30 に数えた）:

- `palette/master.json` は「色の名前 → 色の値」だけの70色（2色は未使用）。18本の道具が `gridfile.load_palette()` 経由で読む
- 名前は、最初に使った地形・素材から付いている。ユニットが使う44色のうち、角付きの兜は `floor_*`、バンダナは `carpet_*`、剣の握りは `roof_*`。名前を見ても、何に使う色か分からない
- 23色を、unit と tile・item・face が同じ名前で共有している
- 色の名前を直接書いている所: `tools/compose.py`・`hand_outline.py`・`weapon_check.py`・`compose_page.py`・`parts_export.py`、`checks/*.json`（`weapon_check` の色、手の色）、`enemy/*.json` 17本（`recolor`）、`types/item/SPEC.md` の素材ごとの割り当て表、README・CLAUDE.md
- グリッドは 1317 枚（`validate.py` の数）

## 目的

- 絵が使う色の名前から、**何に使う色か**が分かる。色ごとに説明と種類（属性）が書いてある
- 確認の道具は、色の名前を並べた設定ではなく、**種類**を読んで物（武器・手・髪・装飾品など）を見分ける
- 描く決まり（武器は武器の色だけで塗る、など）が、パレットの種類と `validate.py` で機械的に守られる
- 上の3件（武器・装飾品・目）が、例外を作らずに正しく通る

## 目的でないもの

- 色の値を変えること。**見た目は1画素も変えない**
- 新しい色を足すこと（用途を分けるための、値が同じ項目を足すのは除く）
- ゲーム側（`src/`）の変更。ゲームは書き出した PNG を読むだけ
- D 敵の1回目の Task 4 の残り（4体の組み直し）。この作業の後に、新しい用途の色で行う

## やってはいけないこと（失敗とみなす）

- 書き出した PNG が1つでも変わる
- 色の値を2か所に持つ（同じ値を `swatches` と `uses` の両方に書くなど）。値は色見本だけが持つ
- 道具が、色の名前の付け方（接頭辞など）で種類を推測する。種類は必ずパレットのファイルから読む
- 落ちた絵を例外（`exceptions`）や `open_chars` で通す

## 構成（依頼者と合意）

```
palette/
  swatches.json      # 色見本: 色の値だけ。今の master.json の役
  kinds.json         # 種類の一覧と説明。道具が何をどう扱うかを書く
  uses/              # 用途の色: 絵が実際に使う名前。型ごとのファイル
    common.json      #   型をまたいで使う色（輪郭など）
    unit.json
    tile.json
    face.json
    item.json
```

- `swatches.json`: `{"<名前>": {"hex": "#rrggbb", "note": "<説明>"}}`。`probe_colors.py`・`check_colors.py` で見分けを測るのはこの段
- `kinds.json`: `{"<種類>": {"note": "<説明と、道具がどう扱うか>"}}`
- `uses/<型>.json`: `{"<用途の名前>": {"swatch": "<色見本の名前>", "kind": "<種類>", "note": "<説明>"}}`
- **同じ値でも、用途が違えば別の項目にする**（短剣の刃と兜は、値が同じ色見本でも別の項目）
- 用途の色のファイルは**型ごとに1つで、その型のすべてのアセットが共有する**。ユニット1体ごとのパレットは作らない（依頼者に確認済み）
- 絵のファイルの形（`# map: o=outline s=weapon_blade_hi`）は変えない。`map` の右側が用途の色の名前になる
- 範囲は **unit・tile・face・item のすべて**（依頼者）

## 種類と、道具の扱い（依頼者と合意）

| 種類 | 何に使う | 道具の扱い |
|---|---|---|
| 武器 | 武器の部品（`assets/part/equip/`）、item の武器のアイコン | 武器の部品は輪郭と武器の種類だけで塗る。武器でない部品・芯は武器の種類を使わない（`validate.py`）。`weapon_check` は武器の種類の画素を武器として読む |
| 肌 | 肌・拳 | `weapon_check` と `compose.py` の `hand` は、肌の種類を手として読む |
| 髪 | 髪 | `part_outline` で、縁の隣が芯（体）の上なら輪郭が無くてよい |
| 装飾品 | ベルト・当て布・ピアス・メガネのような、体や服の上に付ける小物 | 髪と同じく、体の上の縁は輪郭が無くてよい。体の外にはみ出た縁は落とす |
| 被り物 | 兜・バンダナ・頭巾。兜の鼻当ても被り物（依頼者） | 縁はすべて輪郭で閉じる |
| 輪郭 | 輪郭・目 | 今までどおり |

**盾（Claude の判断）**: 盾は武器ではないので、武器と別の種類「盾」にする。`validate.py` の決まりは「武器の部品（`assets/part/equip/` のうち盾以外）は輪郭と武器の種類だけで塗る。盾の部品は輪郭と盾の種類だけで塗る。それ以外の部品・芯は武器の種類を使わない」とする。`weapon_check` は盾の画素を武器として読まないので、ロランの結果は変わらない。

服・目の白目など、ほかの種類と、tile・face の種類の分け方は作る人に任せる（下の「任せること」）。

`validate.py` が新しく確かめること:

- 絵の `map` の名前が、その型の `uses/<型>.json` か `uses/common.json` にある
- 用途の色の `swatch` が `swatches.json` にあり、`kind` が `kinds.json` にある。すべての項目・色見本・種類に `note` がある
- 武器の決まり（上の表）。依頼者の求めた「武器が武器の色で描かれていることを確かめる道具」はこれにあたる
- 使われていない用途の色・色見本は報告する（落とすかは任せる）

新しい判定は、作る前に既存のアセット全件に掛けて落ちる件数を数える（forge の CLAUDE.md「新しい機械チェックを思いついたら、まず偽陽性を数える」）。

## 目の確認（依頼者と合意）

- 目の部品（`assets/part/eye/`）を使うユニットでは、`eye_check` が**目の部品の画素から目を読む**。設定ファイルに目の位置を書かない
- ある向きの目の画素が、被り物・装飾品ですべて覆われているときは通す（knight のバイザー、メガネなど）。一部だけ覆われているときは落とす
- 目の高さを向きどうしで比べるときは、目がすべて隠れた向きを除く
- 目が芯に描かれているロラン・イネス・ガウは、今の設定の書き方のまま

## 色の割り当ての移し替え

- 1317 枚の `map` を、今の色の名前から用途の色の名前へ書き換える。同じ `stone_hi` でも、兜・刃・城の壁で行き先が変わるので、**ファイルの置き場（型と `assets/` の下のフォルダ）ごとに対応表を作り**、道具で機械的に書き換える
- 1つのファイルの中で、同じ色が別の用途に使われている所（芯に描いた髪と服など）は、対応表では分けられない。そうした所は一覧にして、1件ずつ決める。**決める基準（Claude の判断）**: その画素が描いている物（髪・服・ベルト・武器など）の種類にする。作る人が基準で決めて書き換え、決めた結果を、物ごとに色を付けて示すページ（Artifact）にまとめ、依頼者が一度に見て承認する。承認までは次へ進まない
- 敵のレシピの `recolor` は「用途の色 → 色見本」にする
- **完了の条件**: 書き換えの前と後で、`render.py` などで書き出したすべての PNG と、ゲームへの書き出し（`tools/export.py`）の結果が、1バイトも変わらない。あわせて `unit_rules.py` をロラン・イネス・ガウに掛け、結果が変わらない

## 文書

- README・forge の CLAUDE.md・`types/*/SPEC.md` の `master.json` の記述を、新しい構成に合わせる。とくに CLAUDE.md の「パレットに色を足すなら、描く前に `probe_colors.py` で測る」は、色見本を足すときの決まりになる
- `types/unit/SPEC.md` に、武器・装飾品・髪・被り物の色の決まりを書く
- イネスのピアスは芯に描かれている。種類を装飾品にするのはこの作業で行う。芯から部品に分けるのは、イネスを組み直すときに回す（ISSUES に書く）

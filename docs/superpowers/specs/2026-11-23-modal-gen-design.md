# Modal で生成する（設計）

2026-11-23 依頼者と相談して決めた。作業「顔グラを生成 AI で作る」（`2026-11-22-face-gen-ai-design.md`）に、新しい工程として入れる。

| 工程 | 中身 |
|---|---|
| 1. 取り込み方式にする | 完了 |
| 2. ボルグを新しい画風で作り直す | 完了（PR #63） |
| 3. **Modal で生成する** | この設計書 |
| 4. 表示の大きさと顔の構図を決める | 元の工程 3。下の「工程 4 で決まっていること」 |
| 5. 残りの顔グラ 26 枚を作る | 元の工程 4 |

## 意図

生成（GPU）は、依頼者が Colab で動かしてきた。2026-11-23、工程 4（元の工程 3）の試しをしようとしたところ、有料版でも Colab のランタイムに接続できなかった。依頼者は Colab を信用できないと判断し、より止まりにくく、Claude が自分で生成を実行できる流れを求めた。

候補を比べた結果（AWS の EC2・SageMaker・Modal）、個人がときどき画像生成のモデルを動かす用途で一般的な Modal を使う（依頼者）。Modal の稼働率の数字は公開されていないが、障害の履歴はあり、Colab のように接続できない状態が続くという報告は見当たらなかった。

## 目標・目標でないこと

目標:

- Claude がこのサーバーから、Modal の GPU で顔・全身の候補を作れる。候補は Drive を通さず、このサーバーに届く
- Claude が、決まりで外せる候補（下の「決まりで外すもの」）を道具で外し、残りを依頼者が選ぶページ（Artifact）を作れる。依頼者は番号で答える
- 選ばれた候補を、今の採用・取り込み・書き出しの流れ（`adopt`・`install_selection`・`artgen.export`）に載せられる
- Modal で作った絵と Colab で作った絵が、同じ条件（シード・タグ）なら同じになる

目標でないこと:

- 表情（inpaint）を Modal で作ること。表情を作る段階（工程 4 の後）で必要なら足す
- A・C の 2 通りの切り出しとゲームの直し（工程 4）
- 決まりで外すものの 3 つ目（顔が小さすぎる）の判定の数字。A の切り出しの規則が工程 4 で決まるまで決められない（下）
- forge 本体（`akabee0161/illust-asset-forge`）に入れること。このコピーで作り、`UPSTREAM.md` に「forge に戻す候補」として書く

失敗とみなすこと:

- T4 以外の GPU で作る。同じシードでも GPU の種類が違うと出る絵が変わり、「同じシードで同じ構図」を手がかりにした寄せ方が使えなくなる（依頼者）。T4 が空いていなければ、別の GPU に替えずに待つか、やり直す
- Colab のノートブックの道を壊す。Colab は残す（下）

## 2 つの道

- **メインは Modal**（依頼者）。顔グラ 26 枚のような量産では、Claude が Modal で候補を作り、依頼者は選ぶだけ
- **Colab のノートブックも残す**（依頼者）。依頼者が画風の調整でしたように、自分の手でタグを変えながら 1 枚ずつ試す作業に使う。量産には使わない
- 2 つの道で同じ絵が出るように、Modal でも Colab と同じ T4 と、同じライブラリの版を使う。版は、今の PNG の条件にある値（`torch` 2.14.1+cu130・`diffusers` 0.42.1・`transformers` 5.22.2）と `requirements-colab.txt` に合わせる。Colab 側は torch を固定していない（Colab に入っている版を使う）ので、Colab の版が変わると 2 つの道がずれうる。ずれたら、そのとき Modal 側の版を合わせ直す（Claude の判断。Colab の torch を固定すると、Colab の CUDA と合わなくなるおそれがある）

## 進め方の案（Approaches）

違いは、forge のどこまでを Modal の上で動かすか。

| 案 | 中身 | 採否 |
|---|---|---|
| A. エンジンを丸ごと Modal で動かす | Claude がこのサーバーでコマンドを実行すると、このサーバーの `illust-asset-forge/`（コードと設定）が Modal へ送られ、Modal で今の `Forge.generate` がそのまま動く。できた PNG（条件入り）はこのサーバーへ戻る | **採用**（依頼者） |
| B. 薄い関数だけを Modal に置く | プロンプトの組み立てはこのサーバーで行い、Modal には「プロンプト・シード → 画像」だけを置く | 不採用。条件の記録や生成の手順を 2 か所に持ち、Colab と結果がずれるおそれがある |
| C. Modal に Web の API を立てる | — | 不採用。鍵の管理と API の作りが要り、呼ぶのは Claude 1 人なので要らない手間 |

A の良い所: プロンプトの組み立てと条件の記録が Colab と同じコードになる。手元のコードを送るので、設定を直しても push せずにすぐ試せる（Colab は push が要る）。

## GPU とサービス

- Modal の T4 に固定する（依頼者）。Modal の「空いていなければ別の GPU」の設定は使わない
- T4 で 1 枚 20 秒ほど（Colab と同じ）。料金は T4 が約 $0.000164/秒に、CPU とメモリの料金が加わる（2026-11 の公表値）。12 枚の 1 回りは、モデルの読み込みを含めて数分で、10 円前後の見込み
- モデル（`cagliostrolab/animagine-xl-4.0`、約 7GB）は Modal の保存場所（Volume）に置き、毎回 Hugging Face から取らない。`lpw_stable_diffusion_xl` の custom pipeline も、今の `load_pipeline()` と同じ取り方でよい

## 設計

### 1. Modal の入口（`illust-asset-forge/` に足す）

- Modal で動かす入口のモジュールと、Claude が実行するコマンドを足す。コマンドは、今の `forge.generate` と同じ引数（キャラクター・テンプレート・`n`・`seeds`・`extra`・`remove`・`extra_negative`・`remove_negative`・`guidance`・`steps`）を受け取る
- Modal の上では、今の `load_pipeline()` と `attach()` を使い、`attach()` の `base_dir` は Modal のコンテナの中の作業場所にする。できた PNG（条件入り）をこのサーバーへ返し、このサーバーの置き場の `runs/<キャラクター>/<種類>/<日時>/` に、Colab と同じ名前と形で置く
- 送るのは `illust-asset-forge/` のコード（`src/`）と設定（`characters/`・`templates/`・`styles/`・`defaults.yaml`）。`characters/*/source/` の絵・`.venv/` は送らない
- 全身絵を作るとき、今のコードは採用済みの顔（`selected/<id>/face.png`）の画風を引き継ぐ。Modal の上でも同じになるよう、このサーバーの `local/selected/<id>/face.png` があれば一緒に送る（Claude の判断。今は全員がデフォルトの画風なので結果は同じ）
- コマンドに画風（`style`）の引数は付けない（Claude の判断）。量産はデフォルトの画風だけを使い、画風を試すのは Colab の道
- 条件の `commit`: Modal のコンテナには `.git` が無い。このサーバーで調べた commit を渡して記録する。作業ツリーに未コミットの変更があるときは、それと分かる印を付ける（印の形は builder の判断）。Colab の道の記録は変えない
- 条件の `gpu` が `Tesla T4` 以外なら、その絵を返さずに止める（念のため。Modal の設定で T4 に固定しても確かめる）
- diffusers・torch は今と同じく、関数の中でだけ import する（`illust-asset-forge/CLAUDE.md`）。Modal のライブラリも、入口のモジュールの中でだけ import し、ほかのモジュールとテストは Modal が無くても動くままにする
- このサーバーで Modal を使うためのライブラリは、`illust-asset-forge/` の venv に入れる（`pyproject.toml` の任意の依存に足す）

### 2. このサーバーの置き場

- 候補・採用した絵（`runs/`・`selected/`）は、リポジトリに入れない場所に置く（`illust-asset-forge/CLAUDE.md`「候補はリポジトリに入れない」）。場所は Claude の判断で `illust-asset-forge/local/`（`.gitignore` に足す）。Drive の置き場（Colab の道）とは別
- 採用は今の `Forge.adopt(path, flip=…)` と同じ動き（`selected/<id>/face.png` などに置く。右向きは左右反転して採用）。取り込みは今の `install_selection`、書き出しは `python -m artgen.export <id>`。Claude がこれらをコマンドで呼べるようにする（GPU は要らないので、このサーバーで動く）

### 3. 決まりで外すもの（道具）

候補のうち、決まりで外せるものは Claude が外す（依頼者）。Claude が 1 枚ずつ目で見て決めるのではなく、画素を数える道具で判定する（判断が絵によってぶれないように）。

| # | 外すもの | 理由 | 判定 |
|---|---|---|---|
| 1 | 頭が切れている（髪や頭の物が上の辺に触れている） | A の切り出し（頭の全体＋首元）ができない | 上の辺の近くに、背景でない画素がある |
| 2 | 外の背景が白やクリーム色でない | 背景を透明にする手順（README「顔グラの例外」）が使えない | 四辺の画素のうち、白（全チャンネル 240 以上）と飾りのクリーム色（最小値 214 以上で r−g ≤ 14 かつ g−b ≤ 16。工程 2 でボルグの顔の透明化に使った条件。HANDOVER.md 工程 2 の結果）でないものが多い |
| 3 | 顔が小さすぎる | A の切り出しが 256px を下回り、ぼやける | 工程 4 で A の切り出しの規則を決めるときに、測り方と数字を決めて足す |

- 1・2 の数字（上の辺から何 px・何割）は、builder が今ある絵（ボルグ・見本 4 人。ボルグ・騎士・魔法使いは 1 で外れ、男子生徒・女子生徒は外れないはず）で決める。女子生徒・男子生徒は背景がクリーム色寄りなので、2 で外れないことを確かめる
- 判定は顔のテンプレートにだけ使う。全身絵は外さない（全身絵は参考資料で、切り出さない）
- 道具は `illust-asset-forge/` の Python のモジュールにし、テストを付ける（GPU なしで動く）。顔の自動検出は入れない（`illust-asset-forge/CLAUDE.md`）

### 4. 候補のページ（Artifact）

- 1 回りの候補を、番号付きで 1 枚の HTML ページに並べ、Artifact で依頼者に見せる。選ぶ候補を上に、外した候補はページの下にたたんで、外した理由と一緒に並べる（依頼者が「外しすぎ」に気付けるように）
- 各候補に、シードと、その回りのタグの足し引き（案の名前）を添える
- 依頼者は「3 番を採用」「5 番を左右反転して採用」のように番号で答える。Claude がそれで採用する
- ページは、`illust-asset-forge/` の道具で作る（毎回同じ形にするため）。絵は縮小して埋め込む（ページの大きさの上限 16MB を超えないように）

### 5. 依頼者の作業（最初に一度）

1. Modal のアカウントを作る（Starter で始める）
2. Modal の管理画面で、使う金額の上限を決める（任意。Claude が案内する）
3. このサーバーで Modal につなぐ: Claude が `modal token new` を実行すると URL が出るので、依頼者がそれをブラウザで開いて承認する

鍵（トークン）は `~/.modal.toml` に入り、リポジトリには入らない。

### 6. 文書

- `illust-asset-forge/README.md`: Modal の道の使い方（Claude が実行するコマンド・置き場・候補のページ）。Colab の道は「手で試すとき」として残す
- `illust-asset-forge/CLAUDE.md`: 「GPU を使う処理は依頼者が Colab で動かす」を、「量産は Claude が Modal で動かす。手で試すときは依頼者が Colab」に直す。「受け取った画像の扱い」に Modal の道（このサーバーの `local/` から採用する）を足す
- `illust-asset-forge/UPSTREAM.md`: Modal の道と、決まりで外す道具を「forge に戻す候補」に 1 行ずつ
- README.md（ゲーム）「顔グラの例外」: 変えない（作り方の流れは forge の README に書く）
- HANDOVER.md の進捗の工程を 5 つに直す

## 工程 4 で決まっていること（この工程では作らない）

工程 4（表示の大きさと顔の構図）の相談で、2026-11-23 に決まったこと。工程 4 の設計で使う。

- 頭が切れない写し方にする（依頼者）。今のボルグの顔は頭が切れている
- 大きい枠（64px: 会話・セリフ欄・カード）は A「頭の全体＋首元」、小さい枠（40px の下のバー・32px の仲間一覧とリザルト）は C「顔のアップ」（依頼者。小さい画像では A だと見えにくい）。1 枚の元画像から 2 通りに切り出す。40px を小さい枠に入れたのは Claude の受け取り方で、依頼者は訂正しなかった
- `FACE_PX`（64・40・32）は変えない（Claude の案。依頼者が気にしているのは頭が切れることで、枠の大きさではない）
- 頭が切れない元画像は、テンプレートの写し方を「顔のアップ」（`portrait`）から「胸から上」（`upper body`）に変えて出す（案ア。依頼者が承認）。決める前に、ボルグで 2 通り（`portrait` を `upper body` に置き換える・`portrait` に `upper body` を足す）を 4 枚ずつ試す
- ゲームには顔の画像を 2 枚渡す（案カ。`<id>-face.png` が A、`<id>-face-small.png` が C）。ゲームは枠の大きさで使う画像を選び、小さい画像が無い顔は 1 枚を使う
- ボルグは新しい写し方で作り直す。マップの絵を少し直す必要が出るかもしれない

## builder に任せること

- `commit` の未コミットの印の形
- 外す道具の 1・2 の数字（今ある絵で決める）
- 候補のページの作り
- Modal のイメージの作り方（Python の版は Colab に近いもの、ライブラリは上の版）

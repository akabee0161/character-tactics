# 戦闘の演出 設計

2026-11-17 に依頼者と合意した内容。作業「テストプレイで出た直し」の工程 5。作成時点のログ。「（Claude の判断）」と書いたものは、依頼者が決めていない点を Claude が決めたもの。

## 目的と背景

依頼者がテストプレイで挙げた 20 件のうち、戦闘の演出にあたる 3 点を直す（工程の分け方は `2026-11-15-counter-allies-design.md`）。

- **村**: 村人との会話がほしい。会話の間は戦闘をいったん止める。今は加入の村だけが会話になり、ほかの 5 種類（`talk`・`heal`・`powerUp`・`xp`・`stat`）は下のセリフ欄に 1 行が数秒出るだけで、戦闘は止まらない
- **仲間が倒れたとき**: 「悲しい」「しまった」と感じたい。今はあっけなさすぎる。今は仲間がその場で消え、セリフ欄に一言（`retire:<id>`）が出るだけ。そのセリフは優先度が最も低く、ほかと重なると出ない。敵には白い輪（`defeat`）が出るが、仲間には何も出ない
- **必殺技**: 突き・火の雨は何が起きているのか分からない。ガウの駆け抜けるは瞬間移動にしか見えない。今の見た目は 11 個のうち 4 個だけ（踏ん張るの輪、狙い撃ちの十字、駆け抜ける・急降下の白い線 0.25 秒）。残りの 7 個は数字が出るだけ。駆け抜ける・急降下は、計算で一瞬で行き先へ移る

## 目標

1. 6 種類のすべての村で、着いたら戦闘を止めて、村人と訪れた仲間の会話を出す
2. 仲間が倒れたら、画面の時間を 1〜2 秒ゆっくりにし、倒れた仲間の顔と最期の言葉を大きく出してから自動で戻す。倒れた仲間は 2〜3 秒点滅してから消える
3. 11 個すべての技に、何が起きたか分かる見た目を付ける。駆け抜ける・急降下は、画面の上で行き先まで走る（飛ぶ）ように見せる

## 目標にしないこと

- **勝率を変えること**: 演出だけを変える。戦闘の計算（`src/core/`）の結果は変えない。`npm run balance -- --check` は終了コード 0 のままであること
- **村人の本番の絵**: 仮の顔で作る。村ごとに違う村人を描き分ける（依頼者の言う「C」）のは後の作業
- **技のドット絵のエフェクト**: 図形（線・輪・粒）で描く
- **シオンの「攻撃のかわりに回復」**: 工程 4 で見送ったまま
- **ガルムに当たる火花・矢の位置**（48px のボス）: 依頼者がゲームで動かしてから指摘する約束で、この作業に入れない
- **結果の画面の魔力の行が詰まる件**: 結果の画面は触らないので直さない

## 失敗とみなすもの

- 演出の間に操作が効かなくなる、または前のタップで構えた技が演出の後に勝手に出る
- 会話や演出が戦闘の計算の結果を変える（勝率が動く）
- 村人の顔を後で描き分けるときに、コードを直す必要がある

## 作り方の選択

| 決めたこと | 候補 | 選んだもの | 理由 |
|---|---|---|---|
| 技の見た目を何で描くか | ア. 図形（線・輪・粒）をプログラムで描く／イ. forge でドット絵のエフェクトを描く | ア（依頼者） | 不満は「何が起きているか分からない」で、図形の動きで解ける。イは 11 個 × 数コマの絵の作業になり、工程の大半が埋まる。後から技ごとにドット絵へ差し替えられる作りにする |
| 駆け抜ける・急降下の動き | ア. 計算は一瞬のまま、画面の上だけ滑らせる／イ. 計算でも時間をかけて走らせる | ア（依頼者） | イは技の強さが変わり、勝率の測り直しが要る。stage10・stage3 は帯の端にあり外れやすい |
| 倒れたときの止め方 | A. 止めて会話の画面（タップで戻る）／B. 1〜2 秒ゆっくりにして自動で戻る／C. 止めない | B（依頼者） | 「しまった」と気付く間ができ、操作で流れが切れない。後半のステージでは 1 回の戦闘で 2〜3 人倒れる |
| 村人の顔 | A. 顔なし／B. 共通の仮の顔／C. 村ごとに描き分け | B。ただし C に差し替えられる作り（依頼者） | 会話の画面の見た目がそろい、絵は後の本番の絵の作業にまとめられる |

村の会話は、今の加入の会話（戦闘を止めて会話の画面を出す仕組み）を広げる 1 通りしかない。ゆっくりにするのも、画面の時間を遅くする 1 通り（ボットは画面を通らないので勝率は変わらない）。

## 1. 村での会話

### 決まったこと

- 村に着いたら戦闘を止め、会話の画面（加入の会話・ステージ開始の会話と同じ `drawTalk`）を出す。会話が終わったら戦闘に戻る
- 会話は、村人と訪れた仲間の数行のやりとりで、最後に何が起きたかを書く（例「{訪れた仲間}の HPが 全部 回復した！」）
- 村人は村ごとに別の話し手にする。今は全員が同じ仮の顔を使う

### 村人の定義（差し替えられる作り）

- 村人は `assets/npcs/<id>.json` に 1 人 1 ファイルで置く。中身は `id`・`name`・`sprites.face`（Claude の判断: ユニットと同じ `sprites` の形にして、会話の顔の描き方を共有する）。ID は名前と関係ない `npcNN`（仲間の `allyNN` と同じ規則）
- 顔の画像は村人ごとに別のファイル（`npc01-face.png` など）にする。今は中身が同じ仮の顔。C にするときは PNG を上書きし、JSON の `name` を直すだけで済む（コードを直さない）
- 仮の顔は `tools/gen-placeholder-sprites.mjs` で作る（村人の ID を引数で受けられるよう直す）
- 会話の話し手の検証（`registry.ts` の `lookupDef`）が村人も見つけられるようにする。知らない ID は今どおり起動時エラー
- 今ある村は 6 つ（stage1・4・5・6・8・10 に 1 つずつ）なので、村人は 6 人

### 村の定義の書き方

- 村（`villages` の項目）に `npc`（話す村人の ID）と `talk`（会話の行の並び。`intro` と同じ書き方）を足す（Claude の判断）
- 会話の中で訪れた仲間に話させる行は、`speaker` に `"$visitor"` と書く。本文の `{visitor}` は訪れた仲間の名前に置き換わる（Claude の判断: 誰が訪れるかは遊ぶたびに違うため）。訪れた仲間の行は、どの仲間が言っても不自然でない文にする
- 最後の「何が起きたか」の 1 行は、今の `text` をそのまま使う（`{visitor}` を使えるようにする）。会話の文と効果が食い違わないよう、`text` は効果に合わせて書く
- `recruit` の村は、今の加入の会話（`effect.recruit.talk`）をそのまま使う。村人の行は、その前に足せる（`talk` を書けば前に付く。書かなければ今のまま）
- 会話の文は Claude が下書きし、依頼者が読んで決める

### 止めない場合（Claude の判断）

次のときは会話を出さず、今と同じくセリフ欄に 1 行だけ出して、戦闘は止めない。同じステージを遊び直したときに、受け取れないごほうびの会話を何度も読まされないため。

- 一度きりのごほうび（`xp`・`stat`）を受け取り済み（「村の 人が 手を ふっている」）
- `recruit` の村で、その仲間がすでに仲間にいる

### 動き

- 止めるのは画面の側（`main.ts`）。`villageVisited` の出来事を見て、加入の会話と同じように戦闘の更新を抜け、会話の画面に入る。効果（回復など）は今どおり着いた瞬間に出ている
- 戦闘の計算（`src/core/events.ts`）は変えない。ボット（`balance.ts`）は会話を通らないので、勝率は変わらない
- 会話に入るとき、構えた技（`pendingSkill`）・ドラッグ・セリフ欄を今の加入の会話と同じく片付ける
- 一度読んだ村の会話を飛ばす「とばす」は付けない（Claude の判断。止めない場合の決まりで、同じ会話を何度も読むのは遊び直しの 1 回ごとに 1 度だけになる）。依頼者が見本で欲しいと言えば足す

## 2. 仲間が倒れたとき

### 決まったこと

- 倒れた瞬間、画面の時間を約 1.5 秒ゆっくりにし、自動で元の速さに戻す（依頼者は「1〜2 秒」）
- ゆっくりの間、倒れた仲間の顔と最期の言葉（`retire:<id>`）を大きく出す
- 倒れた仲間は、その場で 2〜3 秒点滅してから消える

### 細部（Claude の判断。見本で合わせる）

- ゆっくりの速さは 0.3 倍から始める。戦闘の計算の 1 歩の長さは変えず、画面の時間に掛ける（`?debug` の `S` の 1/4 再生と同じ考え方）
- 顔と最期の言葉は、マップの上に重ねる帯で出す（位置・大きさは見本で決める）。最期の言葉はこの帯で必ず出すので、下のセリフ欄には出さない
- 点滅は 2.5 秒。戦闘の計算では今どおり倒れた瞬間に退場（`retired`）なので、点滅の間は狙われず、当たり判定も無い。点滅は画面の演出（`effects.ts` の新しい種類）で、倒れた位置と最後の向き・姿で描く
- 消えた後、マップに跡は残さない（依頼者の「点滅して退場」を優先）。下の段の顔の枠は今どおり「倒れた」
- 2 人が続けて倒れたら、ゆっくりの時間を延ばし、帯は 1 人ずつ順に出す
- 負けになる倒れ方（護衛対象が倒れた・全滅）では、今どおりすぐ負けの画面へ進むか、ゆっくりと点滅を見せてから進むかを見本で依頼者に決めてもらう。勝ちと同じ瞬間に倒れたときは、勝ちを優先する
- 敵が倒れたときは今のまま（白い輪）

## 3. 技の見た目

### 決まったこと

- 11 個すべてに見た目を付ける。図形（線・輪・粒）で描く
- 駆け抜ける・急降下は、計算では今どおり一瞬で着き、画面の上だけ元の場所から行き先へ滑らせ、残像を付ける
- 滑らせる長さは、ガウ（駆け抜ける）とピコ（急降下）とも 0.6 秒前後にする（依頼者の指示で、Claude が最初に出した 0.3 秒より長く。長さは見本で合わせる）。今この 2 つの技を使うのはガウとピコだけなので、長さは技ごとに持つ
- 見た目は文字で決めず、技ごとに動く見本を Artifact のページで依頼者に見せて決める

### 技ごとの案（Claude の判断。見本で直す）

| 技 | 使う仲間 | 今 | 案 |
|---|---|---|---|
| 踏ん張る | ロラン・ガンツ | 黄の輪 | 今の輪に、効いている 5 秒の間の薄い黄の縁取りを足す |
| 狙い撃ち | イネス・ユナ | 白い十字 | 今の十字に、次の矢が当たるときの大きな火花を足す |
| おまじない | ミスト | 回復の数字と輪 | 使った仲間から回復する仲間へ、光の粒が飛ぶ |
| 駆け抜ける | ガウ | 白い線 0.25 秒 | 0.6 秒前後で滑らせ、残像と斬撃の線。通り道の敵に火花（2026-09-04 の設計で予定して未対応だったもの） |
| 引きつける | ボルグ | なし | 使った仲間から範囲の敵へ赤い線が伸び、足元に赤い輪 |
| 火の雨 | セラ | なし | 指した所の範囲（半径 48）に火の粒が上から降り、着いた所が赤く光る |
| 突き | リュカ・ミラ | なし | 向いた先へ長さ 80 の槍の光が伸びて消える |
| はげます | ノエル | 橙の印 | 使った仲間から橙の輪が広がり、範囲の仲間が一瞬光る |
| たたき割り | バルド・オルト | 数字だけ | 相手の上に大きな割れ目の形の線と、強い揺れ |
| 結界 | シオン | 水色の印 | 使った仲間から水色の輪が広がり、範囲の仲間に一瞬の水色の膜 |
| 急降下 | ピコ | 白い線 0.25 秒 | 0.6 秒前後で弧を描いて飛び、着いた所に土煙の輪（範囲 32） |

### 滑らせ方の決まり

- 計算の位置は一瞬で行き先に移るので、画面の側で「見た目の位置」を持ち、元の場所から行き先へ補間して描く（`effects.ts` に移動の演出を足し、描画はそれを見る）
- 滑らせている間も、HP バー・旗・選択の輪などは見た目の位置に付ける（Claude の判断。本体と離れて見えないため）
- ダメージの数字は今どおり技を出した瞬間に出る。通り道の敵の数字・火花は、見た目の位置がその敵を通る時刻にずらして出す（Claude の判断。数字が先に出るずれを目立たなくするため。描く時刻だけをずらし、ダメージは変えない）
- 滑らせている間に、その仲間へ移動の指示を出したとき、見た目の位置をどう扱うか（行き先から補間を切って計算の位置に飛ぶ、など）は作る人に任せる
- 計算では先に着いているので、本体が滑っている 0.6 秒の間に、行き先で殴る・殴られる、技で倒れた敵の白い輪や HP バーの減りが先に出る、ということが起きうる。見本でこのずれを依頼者に見せ、気になるなら描く時刻をずらす範囲を広げる（計算は変えない）

### 差し替えられる作り

技の見た目は、技の ID ごとに描き方を 1 つずつ持つ形にする（今の `skillCast` の分岐を、技ごとの関数の表にする）。後でドット絵に替えるときは、その技の描き方だけを替える。

## 確かめ方

- 描画にはユニットテストを書かない（CLAUDE.md）。見た目は README の CDP 手順で撮り、Artifact で依頼者に見せて承認を得てから先へ進む
- 純ロジック（村の会話の行の組み立て・`$visitor` の置き換え・止めない場合の判定・ゆっくりの時間の延び方・補間の位置・数字を出す時刻）はユニットテストを書く
- 村人の定義の読み込みと話し手の検証はユニットテストを書く（知らない村人の ID は起動時エラー）
- 最後に `npm test`・`npm run build`・`npm run balance -- --check`（終了コード 0）を通す
- 技の見本は、ゲームを動かさずに技ごとの動きを再生する HTML のページで見せる（ユニットの動きのページと同じ考え方）。そのうえで、ゲームの画面でも撮って確かめる

## 重なったときの決まり（Claude の判断）

- 経験値の村（stage8）でレベルアップと村の会話が同じ瞬間に起きたら、村の会話を先に出し、レベルアップのカードはその後に出す（会話の最後の行が「経験値が入った」で、その結果がカードになる順）
- ゆっくりの最中に村の会話・レベルアップのカード・加入の会話が始まったら、ゆっくりを打ち切って会話・カードに入る。点滅と帯は会話・カードが終わった後、残りの時間だけ続ける
- 点滅（2.5 秒）と滑らせる時間（0.6 秒）は、ゆっくりにした画面の時間で数える（ゆっくりの間は点滅も滑りもゆっくりになる）。帯の表示とゆっくりの長さ（約 1.5 秒）は実際の時間で数える
- 技の見た目に要る値（火の雨で指した所・突きの向き・範囲の中の相手）が技の出来事に無いときは、出来事に項目を足してよい（計算の結果は変えない）。倒れた仲間の位置は、`state.units` に `retired` のまま残るユニットから取る

## 作る人に任せること

- 帯・会話の画面の文字の位置と大きさ、図形の色・太さ・粒の数（見本で依頼者と合わせる）
- 技の見本のページを作る道具の作り（作業が終わったら片付ける）
- 村の会話の文の下書き

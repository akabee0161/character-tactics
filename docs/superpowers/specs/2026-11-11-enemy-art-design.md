# 敵の絵 設計

2026-11-11 依頼者との相談（brainstorming）の結果。作業「仲間・村・難易度・絵の仕上げ」の工程 3。
パスは、断りが無ければリポジトリのルートからの相対。

## 目的と理由

ゲームの敵のうち、ならず者・盾持ち・弓兵・まじない師・説得の相手 2 体（`ally06-foe`・`ally08-foe`）は、マップ上の絵が仮の絵（色つきの人型）のまま。
一方、forge（`pixel-asset-forge/`）には、部品から組んで確認の道具を通した敵が 16 体ある（短剣 4・斧 7・槍 5。男性 8・女性 8。敵の組み直し D、2026-11-05 完了）。
この 16 体はゲームにまだ入っていない。D の設計書（`2026-10-27-enemy-rebuild-design.md`）が「ゲームへの組み込みは D の後に依頼者に聞く」としており、今回がその作業。

依頼者の方針（2026-11-11）:

- 今の敵の区分にこだわらず見直し、**今ある敵のグラフィックに全部置き換える**
- 盾を持つ敵はフルフェイス（兜で顔が全部隠れる見た目）にする
- 数の多いならず者は、斧・槍・短剣を持つ敵を取り混ぜて置き換える
- 弓兵・まじない師は forge に無いので、新しく組んでよい
- **同じ種類の敵でも、16 体の見た目を使って数体の見た目を混ぜる**

成功: ゲームの敵（ガルムを除く）が、すべて forge の部品から組んだ絵で動き、同じ種類の敵が複数の見た目で出る。依頼者がゲーム画面と再生ページで確かめて承認している。

## 範囲

やること:

- 敵のマップ上の絵（32px のシート）を置き換える
- 新しく組む敵（盾持ち・弓兵・まじない師。後述）
- 敵の定義（`assets/enemies/*.json`）とステージの敵の置き方を、見た目を混ぜられる形に直す

## 範囲外（やらない）

- 顔グラ（`*-face.png`）と役割アイコン（`role-teki*.png`）。仮の絵のまま。見た目が増えても、同じ種類は同じ顔グラ・役割アイコンを指す
- 味方（`ally05`〜`ally08` を含む）の絵。仮のままにする
- ガルムの絵（本番の絵が入っている）
- 敵の強さ（HP・攻撃力・守り・速さ・射程・攻撃の間隔）の変更。難易度の調整は済んでおり、残課題は工程 5 で依頼者が扱う
- ステージのタイル（工程 4）
- 敵の配置の位置・数・AI の変更（見た目の割り当て以外）

## 決めたこと（依頼者の判断）

1. 範囲はマップ上の絵だけ（顔グラ・役割アイコンは扱わない）
2. 区分を見直し、全部 forge の絵に置き換える。盾持ちはフルフェイス。ならず者は斧・槍・短剣を取り混ぜる
3. 弓兵・まじない師・盾持ちは新しく組んでよい
4. 味方は対象外。説得の相手 2 体は、戦場に立つ間は敵なので絵の置き換えの対象に含める
5. 同じ種類でも、16 体の見た目を使って数体の見た目を混ぜる

## 設計（Claude の判断を含む。「Claude の判断」と書いたものは依頼者が決めたことではない）

### 1. 敵の「種類」と「見た目」を分ける

- **種類**は強さと攻撃の型で決まる今の 4 区分（ならず者・盾持ち・弓兵・まじない師）のまま。ゲームの数値は変えない
- **見た目**は 1 つの種類に複数ある。ならず者は 14 通り、盾持ちは 2 通り、弓兵とまじない師は 3 通りずつ（Claude の判断。数は組み合わせを見て計画で増減してよい。各 2 以上）
- 割り当て:

| 種類 | 見た目の元 | 数 |
|---|---|---|
| ならず者 | forge の斧・槍・短剣の敵のうちフルフェイス以外（`dagger-bandit`・`dagger-horn`・`dagger-thug`、`axe-*` 7 体、`spear-thug` と `spear-thug-{a,b,c}-f`） | 14 |
| 盾持ち | フルフェイス（`dagger-knight`・`spear-knight`）に盾を持たせた新しい組み合わせ | 2 |
| 弓兵 | 敵の男性・女性の体に弓と矢を持たせた新しい組み合わせ（頭は既存の被り物・素の髪から選ぶ） | 3 |
| まじない師 | 敵の女性の体に杖を持たせた新しい組み合わせ（Claude の判断。頭は魔女の帽子系を色替えして味方のミストと見分ける） | 3 |

- 説得の相手は、戦場に敵として立つ間の絵だけを置き換える。説得に成功して仲間になったあとの絵（`ally06`・`ally08` の仮の絵）は変えないので、**説得の前後で見た目が食い違う**（依頼者の判断「味方は対象外」の結果。味方側の絵を作る作業で揃える）。今は `ally06-foe` と `ally06` が同じ `ally06-map.png` を指している。味方側の絵を残すため、敵側の新しいシートは別のファイル名（`ally06-foe-map.png`・`ally08-foe-map.png`）にする
- 説得の相手の `ally06-foe`（魔法）は、まじない師の見た目の 1 つ。`ally08-foe`（近接）は、ならず者の見た目の 1 つ（Claude の判断。同じステージに出る共通の敵と別の見た目を選ぶ）

### 2. ゲーム側の持たせ方（Claude の判断）

- **敵の定義を見た目ごとに別の ID で持つ。** 同じ種類の定義は、`id`・`name` 以外のうち `sprites.map`・`color` だけが違い、強さの数値・攻撃の型・`role`・`face` は同じ
  - **「種類」を表す任意の項目 `kind` を敵の定義に足す**（省略時は `id`）。初対面の会話の判定（`src/core/sim.ts` の `seenDefIds`）と、セリフの鍵（`src/core/dialogue.ts` の `first:<味方>:<敵>`・`rival:...`。`assets/lines/common.json` に `first:roran:narazumono` など）は、今は敵の `id` で見ている。見た目ごとに ID を分けると、見た目ごとに「初対面」になり、`-2` の敵と先に戦うと初対面のセリフが出ず、あとで ID が `narazumono` の敵と戦ったときに唐突に出る。そこで判定とセリフの鍵を `kind` で見る（ユニットを作るときに `kind` を持たせる）。見た目が違う敵は `kind` を同じにする。ガルムなど見た目を混ぜない敵は `kind` を書かない（`id` のまま）。セリフの JSON は変えない（`kind` が今の 4 つの ID と同じになるため）
  - これは小さなエンジンの変更で、テストを足す（`kind` 違いの 2 体と戦っても初対面は 1 回、`kind` 省略時は今までどおり）。エンジンは変えない案は、同じセリフを新しい ID の数だけ写すことになり、写しの食い違いを防ぐテストも要るので採らない（Claude の判断）
  - 今ある 4 つの ID（`narazumono`・`tatemochi`・`yumihei`・`majinaishi`）は、その種類の 1 つ目の見た目として残す（既存のテスト・ステージが ID を参照しているため）。2 つ目以降は `narazumono-2` のように番号で足す。名前（`name`）は種類の名前のまま（画面に出るのはこの名前）
  - 理由: 見た目の数が最大 14 でも、エンジンの変更（敵の配置への見た目の指定など）より、JSON を足す方が小さく安全。数値を複数の JSON に写すので、食い違いを防ぐテストを足す（同じ種類の定義は、`sprites.map` と `color` 以外が一致することを `npm test` で見る）
- ステージの敵の置き方は、見た目の ID を割り当て直すだけ（位置・AI・数は変えない）。割り当ては、同じステージ内で見た目が偏らないように混ぜる（近くにいる敵が同じ見た目にならないようにする。具体の割り当ては計画で決める）。時間湧き（`spawners`）は 1 つの ID しか指せないので、そのステージの湧く敵の見た目は 1 つ（Claude の判断。見た目を混ぜるには `spawners` を種類ごとに分ける必要があり、敵の総数上限の数え方に関わるため、今回は混ぜない）
- 絵は `sprites.json` に書き、`pixel-asset-forge/tools/export.py` で `assets/images/<id>-map.png` へ書き出してコミットする。ファイル名は敵の ID と同じ（`narazumono-map.png` ・`narazumono-2-map.png` など）
- コマ数・fps は今と同じ（待機 2 コマ 4fps・歩き 4 コマ 8fps・攻撃 3 コマ 6fps）。forge の敵のシートもこの形。攻撃の出るまでの時間が変わらないので、難易度の測定結果に影響しない

### 3. 新しく組む敵（盾持ち・弓兵・まじない師）

- forge の決まりどおり、部品から `compose/<id>.json` で組み、`tools/unit_rules.py checks/<id>.json` と `compose.py --check` を通す。道具で落ちたら道具に従って絵を直す（依頼者に途中で聞かない。`CLAUDE.md`）
- 使える部品: 盾（ロラン・ガルムの `equip/shield/`）、弓・矢（`equip/bow/`・`equip/arrow/`）、杖（`equip/staff/`）、敵の芯（`body/enemy_male/`・`body/enemy_female/`）、フルフェイスの頭、素の髪・被り物、服
- 既存の武器・拳の部品は特定の体（ロランの盾、イネスの弓、ミストの杖）に合わせて描いてある。敵の体に合わせるには部品や拳の描き足しが要る可能性がある（見込み。計画で確かめる）。描き足すときも「完全な単品」「物は先に向きごとに合意」など、記憶・forge の決まりに従う
- 弓兵の攻撃は今の `attack: "bow"`、まじない師は `"magic"`。攻撃のコマの意味（最後のコマで発射）は forge の弓・杖の絵で守る
- 盾持ちの盾は、盾を持つ側の手に持たせ、向きごとの重なり順は承認済みの順（ロランの盾）に合わせる

### 4. 確認の進め方

- 新しく組む敵は、状態×4方向の再生ページ（`tools/anim-page.py`）を Artifact で見せて依頼者の承認を得る（絵を直したら見せてから進む）。既存の 16 体は D で承認済みなので絵は見せ直さず、ゲームに入れた画面と、見た目を混ぜた並びのページで確かめる
- ゲームに入れたあとの確認: `npm test`・`npm run build`。`npm run balance` の勝率が、置き換える前と**ぴったり一致する**ことを期待する（強さの数値も配置も変えないため）。最初のタスクで、ID だけを差し替えて一致するかを確かめる。一致しなければ、乱数の使い方や敵の並びが ID に依存していないかなど原因を調べて報告する（許容幅は決めない。Claude の判断）。ヘッドレスブラウザ（README の CDP の手順）でステージを開き、敵の見た目が混ざって表示されることを撮る
- 依頼者が人手で確認する工程 5 では、ゲーム画面で見る

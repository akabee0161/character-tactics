# 足元の箱とタイルの大きさ 設計

作成: 2026-09-28

## 背景

pixel-asset-forge の issue #6（https://github.com/akabee0161/pixel-asset-forge/issues/6）の対応の3番目。

- **めり込み:** ユニットの当たり判定は足元の1点だけで、通れないマス（木・岩・村）の脇まで足元が入る。
  体（32px のコマで中心から左右に6〜7px）の半分がそのマスの絵に重なって見える
- **タイルの大きさ:** `drawTerrain` は画像の大きさに関係なく 16px として 1マスに 2×2 で敷く。
  アセットの大きさの規約（README）で、物は 16px の部品を組んだ 32px のセットで描くと決めたので、
  32px の画像を受け取れるようにする

## 目的と成功条件

- 通れないマスに横または上から近づいても、ユニットの体がそのマスの絵に重ならない
- 下から近づいたとき、頭が上のマスの絵に重なるのは残す（見下ろし型ではマスの手前に立っているように見える。依頼者の選択）
- 移動の操作感（マスの中の自由な位置へ動ける、壁の角で止まらない）は今のまま
- タイルは画像の元の大きさで描かれる（16px なら 2×2、32px なら1枚）

## 足元の箱

ユニットの位置（足元の点）を基準に、次の範囲を「足元の箱」とする。

| 向き | 幅 | 理由 |
|---|---|---|
| 左右 | 6px ずつ（幅12px） | 32px のコマの体は x=10〜23（中心16）。ロランは剣先が最大4px、ガルム（48px）は数px出るが、1つの値にする |
| 下 | 2px | 足先は足元の点の 2px 下まである（`FOOT_INSET`） |
| 上 | 0px | 下から近づいたときの頭の重なりは残す |

箱の四隅がすべて通れるマスの中にあるとき、その位置に立てる。

定数と四隅を求める関数は `src/engine/footprint.ts` に置く。ステージの JSON の検査（engine）と
シム（core）の両方が使うため。README の方針で engine は core を参照しないが、core は engine を参照してよい。
下の 2px が描画側の `FOOT_INSET` と同じ値であることはテストで確かめる。

## 判定の関数（`src/core/field.ts`）

- `fitsAt(grid, pos)`: 箱の四隅がすべて通れるマスの中にあるか
- `fitInCell(grid, pos)`: 箱が収まらない位置を、同じマスの中で箱が収まる位置へ寄せる。
  寄せても収まらなければマスの中心（通れるマスの中心には必ず収まる）、マス自体が通れなければ null
- `hasClearPath(grid, from, to)`: 箱の四隅から引いた4本の線が、どれも通れるマスだけを通るか（`hasLineOfSight` を4回）

敵に気づく判定と詰め寄る相手を選ぶ判定（`ai.ts`・`autoclose.ts`）は「見えるか」なので、
今の1本の線（`hasLineOfSight`）のままにする。

## 箱の判定を使う箇所

| 箇所 | 今 | 変更後 |
|---|---|---|
| 1歩ごとの移動 `stepTo`（`sim.ts`） | 行き先に補正が無ければ歩けるかを見ない | どの場合も `fitsAt` で確かめる。収まらなければ x だけ・y だけ動かす案を試して横すべりする。どちらもだめなら今と同じく blocked |
| 目的地への直進 `moveTowardGoal` | `hasLineOfSight` | `hasClearPath`。だめならフローフィールド（今と同じ） |
| 移動先の置き換え `resolveMoveDest` | 通れるマスならそのまま | `fitsAt` ならそのまま。通れるマスで収まらなければ `fitInCell`。通れないマスは今と同じ |
| 配置 `canPlaceAt`（`state.ts`） | `isWalkableAt` | `fitsAt`。ドラッグ中のプレビューの赤表示も同じ関数を通る |
| かけぬける（`skills.ts`） | 行き先と途中の点を `isWalkableAt` | 行き先を `fitInCell` で寄せ、途中の点を `fitsAt` で確かめる |
| ステージの JSON の検査（`schema.ts` の `checkWalkable`。開始位置・時間湧き・敵・見張りの持ち場の4か所） | 位置のマスが通れるか | 箱が収まるか。エラー文は「足元が 通れない マスに かかる」 |

味方・敵・詰め寄りの移動はすべて `stepTo` を通る。経路探索（フローフィールド）はマス単位のままにする。
今あるステージの位置（マスの中心でないもの14か所を含む）は、すべて箱が収まることを確かめた（2026-09-28）。JSON の検査は通る。

## タイルの描き方

- `drawTerrain`（`src/render/draw.ts`）は画像の元の大きさ（`naturalWidth`）で描く。1マスに (cell / 一辺)² 枚
- `TILE_PX`（`src/render/sprites.ts`）は消し、代わりに許すタイルの一辺の一覧 `TILE_SIDES = [16, 32]` を置く。
  一辺が1マス（32px）を割り切れることが条件で、`drawTerrain` は一覧に無い大きさの画像を単色で描く（読み込み前と同じ扱い）
- `src/engine/sheet-size.test.ts` の検査を「16×16」から「正方形で、一辺が `TILE_SIDES` のどれか」に広げる
- 複数マスを占める物（城の 2×2 マスなど）を置く仕組みは作らない（規約の spec のとおり、使うステージが出てから）

## テスト

- `fitsAt`・`fitInCell`・`hasClearPath` の単体テスト（`field.test.ts`）
- シムのテスト: 通れないマスの横を歩いても 6px より近づかない、角で止まらずに回り込める、
  脇を指定すると内側へ寄る、配置が拒否される、かけぬけるの行き先が寄る
- JSON の検査のテスト: 箱が収まらない位置の敵がエラーになる
- 見た目: README の CDP 手順で、木の脇を歩かせて撮る

## README に書くこと

- 「そうさ」の移動の説明に、通れないマスの脇を指したときは内側へ寄ることを足す
- 「コンテンツの足しかた」のステージの項: 敵などの位置は足元の箱が収まること、タイル画像は 16×16 か 32×32
- 「アセットの大きさの規約」の「まだ規約に追いついていないもの」のうち、ゲーム側の描き方の部分を直す

## 今回の作業に含めないもの

- 森で遅くなるタイル（issue #6 の対応の5番目）
- 村・岩・木を 32px のセットで描き直すこと（forge 側）
- 複数マスを占める物を置く仕組み

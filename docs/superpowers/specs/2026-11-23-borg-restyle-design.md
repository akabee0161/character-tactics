# ボルグを新しい画風で作り直す（設計）

2026-11-23 依頼者と相談して決めた。作業「顔グラを生成 AI で作る」（`2026-11-22-face-gen-ai-design.md`）の工程 2。

## 意図

ゲームに出ているボルグ（ally05）の顔は、古い画風（color-anime）で作った絵を切り出したもの。顔グラはすべてデフォルトの画風（thick-line-flat）の生成イラストにするので、ボルグを最初に作り直す。

ボルグは、あとでロラン・イネスなど（今は顔が無く、マップの絵だけがある）の顔を作るときの手本になる（依頼者）。ボルグで決めた手順（プロンプトの寄せ方・選び方・取り込み・差し替え・マップの絵の直し）を、工程 4 でそのまま使う。

工程 1 の残りだった「Colab でこのリポジトリのコピーから動くこと」は、2026-11-23 に依頼者が確かめた（HANDOVER.md）。

## 目標・目標でないこと

目標:

- ボルグの顔（ふつうの表情）と全身絵を、デフォルトの画風で、このリポジトリの `illust-asset-forge/` から作り、取り込んで書き出す
- ゲームの顔 `assets/images/ally05-face.png` を新しい顔に差し替える
- マップの絵 `assets/images/ally05-map.png` を、新しい顔と全身絵に合わせて直す

目標でないこと:

- 表情（`hurt`・`shout`）。ダメージの顔は今は出さない（前の作業での依頼者の判断）。構図を工程 3 で変えると作り直しになるので、工程 3 の後に作る（依頼者が Claude の案を承認）
- 表示の大きさ（`FACE_PX`）と顔の構図（工程 3）
- ほかの顔グラ（工程 4）
- 見本の騎士（`knight`）を変えること

失敗とみなすこと:

- 新しい顔が、今のマップの絵から大きく離れる（下の「顔と今のドット絵」）
- forge 本体の Drive（`MyDrive/illust-asset-forge/`）の古い絵を取り込む（`illust-asset-forge/CLAUDE.md`）

## 顔と今のドット絵

順序は「顔が先、マップの絵は顔に合わせて直す」（依頼者。普通は顔グラが先にあって、それに合わせてドット絵を描くから）。ただし、マップの絵の直しを小さくするために、次の 2 つを両方行う（依頼者）:

- Claude は、今のマップの絵からできるだけ離れない絵が出るように、プロンプト（タグ）を工夫する
- 依頼者は、候補から、今のマップの絵からできるだけ離れない絵を選ぶ

今のマップの絵（`pixel-asset-forge/types/unit/SPEC.md` のボルグの節、`assets/images/ally05-map.png`）:

| 所 | 今のマップの絵 | 今の設定で作った騎士の顔（2026-11-23、シード 3034254740） |
|---|---|---|
| 髪 | 赤茶（`auburn`）、後ろへ流した短髪 | 茶、後ろへ流した髪（近い） |
| 鎧 | 中くらいの灰色（`plate`）の胸当てと肩当て | 白に近い灰色（明るすぎる） |
| 金の縁 | 少し（`metal`） | 多い |
| 鎧の下の服 | 紺（`clothes_blue`） | 首元に紺（近い） |
| 持ち物 | 右手に剣、左手に暗い鋼に金の縁の丸い盾（ロランより一回り大きい） | 顔には写らない（顔のテンプレートは持ち物を使わない） |

## 進め方の案（Approaches）

違いは、プロンプトを試すたびに設定を Colab へどう届けるか。

| 案 | 中身 | 採否 |
|---|---|---|
| A. 試すたびに push | Claude が `character.yaml` を直して作業ブランチに push し、依頼者が `REPO_BRANCH` を作業ブランチにして準備のセルを実行し直す | 不採用。1 回試すごとに push と準備のセルの実行が要り、依頼者が Claude を待つ |
| B. ノートブックで足し引きし、決まったら設定に戻す | Claude がタグの足し引き（`extra=`・`remove=`）を書いたセルを、貼れる形で渡す。採用した絵の PNG の条件（`overrides`）を、取り込むときに `character.yaml` へ書き戻す | **採用**（依頼者） |
| C. マップの絵を元に絵を作らせる（image-to-image） | — | 外した。forge にその機能が無く、道具を作る作業が増える |

B の弱点: 試した途中の案はリポジトリに残らない。Claude が、渡したセル（タグの案）と結果を台帳に書いて残す。

## 設計

### 1. 参考のページ（Claude）

依頼者が Colab で選ぶときに見比べるため、今のマップの絵（立ち絵を拡大したもの、4 方向）と、今のゲームの顔を 1 枚の HTML ページにして Artifact で渡す。

### 2. 顔のプロンプトと候補（Claude がセルを渡し、依頼者が作って選ぶ）

- ボルグの設定はすでに develop の `illust-asset-forge/characters/ally05/character.yaml` にある。ブランチを切り替えずに、develop のまま始める
- Claude は、上の表の差（鎧が明るすぎる・金が多い）を縮めるタグの案を、2〜3 通り作る。1 つのセルに、案ごとの `forge.generate(["ally05"], "face", n=…, extra=…, remove=…, on_image=F.show_one)` を並べ、最後に `P.pick(forge, <全部の paths>)` を置く
- ボルグの設定は、工程 1 で騎士の見本の設定をボルグから写したため、名前以外が騎士と同じ（同じシードなら騎士と同じ絵が出る）。ボルグとして候補を作って選ぶが、見本の騎士と同じ（または近い）絵になってもよい（依頼者）。そのため、各案に騎士のシード 3034254740 を 1 枚入れ、残りはシードを固定しない（Claude の判断。タグを変えたときに騎士の絵がどう変わるかも見られる）
- 依頼者は結果を見て、選ぶか、もう一回り試すかを決める。もう一回り試すときは、依頼者が見たこと（スクリーンショットか言葉）を元に、Claude が次のセルを渡す
- 顔は左向きで採用する（右向きなら「左右反転して採用」。工程 1 と同じ）
- 1 回の生成は T4 で 1 枚 20 秒ほど。1 セルの枚数は合計 12 枚程度までにする（Claude の判断。選ぶ画面が長くなりすぎないように）

### 3. 全身絵（同じ流れ）

- 顔を採用した後に、顔で決めたタグの足し引きをそのまま使い、全身の候補を作る
- 持ち物は今のマップの絵と同じ「右手に剣、左手に盾」に寄せる（`items` は今 `large shield, holding shield` だけ。剣の足し方は Claude の判断）
- 見るのは、服の種類・色・持ち物と、髪の色・髪型が顔と合っているか（ノートブックの説明どおり）

### 4. 取り込みと書き出し（Claude）

- 採用した 2 枚（`face.png`・`fullbody.png`）を、Drive のコネクターで `MyDrive/character-tactics/illust-asset-forge/selected/ally05/` だけから取る（`illust-asset-forge/CLAUDE.md`「受け取った画像の扱い」）。zip でもよい
- `install_selection` で取り込み、書き戻しの一覧（`overrides` の `extra`・`remove` など）を `characters/ally05/character.yaml` の自然な欄（鎧の色は `outfit`、剣は `items` など）に戻す
- 書き戻した後のタグの並び順は、採用した絵の条件と変わる（Claude の判断）。エンジンは `extra` を表情のタグの後ろ・画風のタグの前に入れるが、`character.yaml` で書ける欄はそれより前に並ぶため。困る場面は無い: 採用した絵は条件ごと残り、表情は採用した顔に描き足して作るので、設定から同じ絵を作り直す流れは無い。エンジンは直さない
- `python -m artgen.export ally05`

### 5. ゲームの顔の差し替え（Claude）

- 前と同じやり方にする（README「顔グラの例外」）: 元画像（1024px）から顔を中心に正方形に切り出し、外につながる白い背景を透明にして 256px に縮め、`assets/images/ally05-face.png` を置き換える。切り出す範囲は新しい絵を見て決める
- README「顔グラの例外」の元画像の場所・切り出した範囲を、新しいもの（このリポジトリの `illust-asset-forge/characters/ally05/source/face.png`）に直す
- 縮めたときの見え方を、ゲームと同じ描き方（`FACE_PX` の 64・32・40px）で確かめ、ページにして依頼者に見せる

### 6. マップの絵の直し（Claude）

- `pixel-asset-forge/types/unit/SPEC.md` の「入力がイラストのときの設定シート」の流れで行う（標準。2026-11-22）。顔と全身絵が食い違う所は、見たままを一覧にして、設定シートの前に依頼者へ一度に聞く
- 新しい顔・全身絵と今のマップの絵の差を、部品（髪 `hair/borg/`・鎧 `cloth/borg/`・盾 `equip/shield/borg/` など）と色（色見本）ごとに一覧にし、変える部品だけを直す。差が無い部品は変えない
- 確認の道具で落ちたら、道具に従って絵を直す（CLAUDE.md）。動きと重なり順は今の承認済みのまま（`checks/borg.json`）
- 確認ポイント（設定シート・案・再生ページ）は、今のユニットの流れ（SPEC.md）と同じく依頼者に見せる

### 7. 文書

- README「顔グラの例外」（上の 5）
- `pixel-asset-forge/types/unit/SPEC.md` のボルグの節（変えた部品・色）
- HANDOVER.md の工程 2 の結果。プロンプトの寄せ方で分かったこと（工程 4 で使う）
- `illust-asset-forge/` のエンジン・道具を直したときだけ `UPSTREAM.md` に 1 行（`CLAUDE.md`）

## 確かめ方

- `illust-asset-forge/.venv/bin/pytest`（ボルグの設定がすべてのテンプレート・表情で組み立てられること）
- 取り込んだ 2 枚の条件の `character` が `ally05`、`style` が `thick-line-flat` であること（`python -m artgen.pnginfo`）。書き戻した後、`character.yaml` から組み立てたタグが、PNG の条件のタグと並び順を除いて同じであること
- `npm test`・`npm run build`
- マップの絵は pixel-asset-forge の確認の道具と、ゲームと同じ fps の再生ページ
- ゲームの顔とマップの絵は、ブラウザ（README の CDP 手順）でも見る

- 参考のページの作り
- 剣を全身絵に持たせるタグ
- 顔の切り出しの範囲（新しい絵を見て）

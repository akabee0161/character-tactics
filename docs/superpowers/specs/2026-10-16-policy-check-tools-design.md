# 方針を確かめる道具をそろえる 設計

作成: 2026-10-16

## 目的

pixel-asset-forge の方針（`types/*/SPEC.md`・`CLAUDE.md`・依頼者の指摘）のうち、機械で確かめられるのに道具が無いものを、D（敵16体を体＋拳で組み直す）の前に全部道具にする。

依頼者の判断（2026-10-16）: 道具がそろう前に絵を描くと、後から道具にかけて直す手戻りが出る。
「D と関係ない道具もある・既存の絵に掛けると判断が要る・規模が大きい」という弱点より、手戻りを防ぐ利点が大きい。
したがって、時間をかけてでも D の前に道具を整備する。

対象:

- `pixel-asset-forge/ISSUES.md` の節「方針を確かめる道具が無いもの」の12件（2026-10-16 に洗い出して立てた。この設計では番号 1〜12 で呼ぶ。下の表）
- ISSUES に既にあった道具の課題3件: 「拳以外の部品（武器・弓・矢・盾）が輪郭で閉じているかを確かめる道具が無い」（以下 33）、
  「`weapon_check.py` が部品の取り付けの大きさと位置を見ない」（以下 81）、「敵を 体 + 拳 の方針で組み直す」のうち `weapon_check.py` の `--arm` の見直し（以下 77）
- 「スマホで見せる画像の道具が作業フォルダにだけある」（スマホ用の画像の道具）

番号 1〜12:

| # | 方針 |
|---|---|
| 1 | 承認された重なり順を作業する側が変えない |
| 2 | 切っ先は頭頂（y=5）より上に出さない。待機の2コマ目は y=3 まで |
| 3 | 待機の2コマ目は頭・脚・盾が `base` のまま、歩きは脚だけを動かす |
| 4 | 盾はどのコマでも `base` の位置から動かさない |
| 5 | 背丈 24〜26px |
| 6 | 尖った先端を、輪郭に囲まれた1画素で表さない |
| 7 | item の長い持ち物は、軸 x+y=15 について形が左右対称 |
| 8 | `unit` に mirror を使わない |
| 9 | 持ち物の部品には専用の文字を割り当てる |
| 10 | 新しいタイルは全点をレイアウトに置く |
| 11 | 回帰テストに現役のアート（`assets/`）を参照させない |
| 12 | 目の左右の隣が髪・かぶり物・顔の輪郭でない、目の上端の行が4方向でそろう |

## 決めたこと（2026-10-16 依頼者）

- 道具の組み立て方は案A: **確認ごとの小さな道具＋ユニットごとの設定ファイル＋まとめて走らせる入口**
  （案B「小さな道具を足すだけ」は走らせ忘れと例外の写し間違いが残る、案C「1本の大きな道具」は1本1役の書き方から外れる、で採らなかった）
- 新しいユニットの確認は、色ではなく**部品のファイル**で測る（刃と同じ色の兜などを取り違えない）
- 3・81・12 の解釈（下の「ユニットの確認」）
- 既存の絵で落ちたものは、道具ごとに一覧で依頼者に見せて1件ずつ決める。**絵はこの作業では直さない**
- 設計書は1つ、計画と PR は2つ

## 全体の形

### ユニットごとの設定ファイル `checks/<ユニット>.json`

forge の直下に置く（`compose/` と同じく `assets/` の外。`validate.py` が `assets/` の下の `*.txt` を読むため、設定を `assets/` に置かない決まりに合わせる）。書くもの:

- `compose`: 組み立て方（`compose/<ユニット>.json`）。コマの置き場は `assets/unit/<ユニット>/`
- `colours`: 色の役割（色名）。`hand`（手の肌）、`face`（顔の肌。12 で使う）など
- `items`: 持ち物の文字（`unit_check.py --items`）
- `parts`: 部品の役割。部品のファイル名の前半（`dagger_hand`・`dagger`・`free_hand`・`shield` など）ごとに、
  `weapon`（刃のある武器。2・81）・`blade`（刃の文字。2）・`fist`（拳。81）・`grips`（その拳が握る部品。81）・`fist_sizes`（拳の大きさ。81）・
  `moves`（待機の2コマ目に動いてよい。3）・`fixed`（どのコマでも動かない。4）・`open_chars`（体の上で輪郭を付けない文字。33）
- `orders`: 承認された重なり順。向きごとに奥→手前の部品の並び（芯は `CORE`）。1 で使う
- `eyes`: 目の行（向きごとの y の範囲）。12 で使う
- `weapon_check`: `weapon_check.py` に渡す指定（今 SPEC の「自己チェック①」の本文に書いてあるものを移す）
- `exceptions`: 確認ごとの例外。1件ずつ `{"check": 確認の名前, "frames": [コマ], "what": 何が落ちるか, "why": 理由, "approved": "日付 依頼者"}`

例（ガウ。値は形を示すためのもので、計画で実際の値を数える）:

```json
{
  "unit": "gau",
  "compose": "compose/gau.json",
  "colours": {"hand": ["skin_rose_hi", "skin_rose_base", "skin_rose_shadow"], "face": ["skin_rose_hi", "skin_rose_base", "skin_rose_shadow"]},
  "items": "stlmn",
  "parts": {
    "dagger": {"weapon": true, "blade": "st", "moves": true},
    "dagger_hand": {"fist": true, "grips": "dagger", "fist_sizes": ["3x2", "2x2"], "moves": true},
    "free_hand": {"fist": true, "fist_sizes": ["2x2"]}
  },
  "orders": {"down": ["CORE", "dagger", "dagger_hand", "free_hand"], "up": ["dagger", "dagger_hand", "free_hand", "CORE"],
             "left": ["dagger", "dagger_hand", "CORE", "free_hand"], "right": ["free_hand", "CORE", "dagger", "dagger_hand"]},
  "eyes": {"down": [11, 12], "up": null, "left": [11, 12], "right": [11, 12]},
  "weapon_check": {"blade": "stone_hi,stone_base", "weapon": "wood_hi,wood_base,wood_shadow", "hidden": "left_atk_wind,up_atk_wind,up_atk_hit", "depth": "down"},
  "exceptions": [
    {"check": "weapon_check", "frames": ["left_base", "left_idle2", "left_walk_a", "left_walk_b"], "what": "手が細い（1x2px）",
     "why": "短剣の拳は体の奥で、縁から1列だけ見える", "approved": "2026-10-15 依頼者"}
  ]
}
```

設定ファイルを読む道具は、知らないキー・無い部品の名前・無いコマの名前・パレットに無い色名を見つけたら止める（終了コード 2）。
ISSUES の「`weapon_check.py` が色名とコマ名を検査しない」と同じ穴を作らないため。

### まとめて走らせる入口 `tools/unit_rules.py checks/<ユニット>.json`

次の順に走らせ、確認ごとに1行ずつ「ok／落ちた件数／例外で通した件数」を出す。例外に書いていない失敗が1つでもあれば終了コード 1、設定の誤りは 2。

1. 構造の検査 `validate.py`（コマと部品）
2. 部品から再現できるか `compose.py --check`
3. 今ある確認: `body_check.py`（芯）・`hand_mirror.py`・`unit_check.py`・`weapon_check.py`
4. 新しい確認（下の表の順）

今ある道具は書き換えない（77 の `weapon_check.py` を除く）。入口が設定ファイルから引数を組み立て、各道具の `main(argv)` を呼ぶ。
今ある道具の失敗を例外で通すときは、その道具が出すコマの名前と文言で例外と突き合わせる。

### 新しい確認の置き場

- ユニットの確認（1〜6・9・12・33・81）: 1つずつ `tools/` の小さな道具にする。どれも設定ファイルを受け取り、単独でも走らせられる。3 と 4 は1つの道具
- 77: `weapon_check.py` を直す
- 8: `validate.py` に足す
- 7: `tools/item_check.py`
- 10: `tools/tilemap.py` に、どのレイアウトにも置かれていないタイルを出す指定を足す
- 11: `tests/` に、テストのコードを調べるテストを足す
- スマホ用の画像: `tools/phone_sheet.py`

対象のユニットは、部品で組むロラン・イネス・ガウの3体。敵は D で部品から組むようにした後に設定ファイルを足す。

## ユニットの確認が何を落とすか

| # | 道具 | 落とすもの |
|---|---|---|
| 1 | 重なり順 | `compose/<ユニット>.json` の各コマの重なり順（`compose.py` の `stack_order` で奥→手前に並べた部品の名前の前半）が、`orders` と違うコマ |
| 2 | 切っ先の高さ | 攻撃（`atk_*`）以外のコマで、`weapon` の部品の `blade` の文字の画素の一番上が y=5 より上にあるもの（`idle2` は y=3 より上） |
| 3 | 動かない所 | `idle2`: 芯が同じ向きの `base` の芯と違う画素のうち、`base` の拳の部品の手の肌の位置に無いもの（拳がどいた胴を埋めた所は通す。SPEC「アニメの規約」）。`moves` でない部品が `base` と違うもの。`walk_a`・`walk_b`: 芯の y≤27 が `base` と違うもの |
| 4 | 盾 | `fixed` の部品が、攻撃を含むどれかのコマで、同じ向きの `base` と違うもの（3 と同じ道具） |
| 5 | 背丈 | 芯の一番上の画素から足元 y=30 までの行数が 24〜26 でないコマ |
| 6 | 1画素の先端 | 組んだコマで、上下左右がすべて輪郭の、輪郭以外の画素 |
| 9 | 部品の文字 | 芯以外の部品が、同じコマの芯と同じ文字を使っているもの（輪郭 `o` と、`fist` の部品の手の肌の文字は除く） |
| 12 | 目 | `eyes` の行で、左右のどちらかが顔の肌（`colours.face`）である輪郭の画素を目とみなし、もう片方の隣が顔の肌でないもの。目の上端の行が、目のある向きの間でそろわないもの |
| 33 | 部品が閉じている | `fist` でない芯以外の部品を単品で見て、`open_chars` 以外の色の付いた画素が、透明かコマの外と上下左右で直に接しているもの |
| 81 | 拳の大きさと握り | `fist` の部品の手の肌の外接矩形（縦横）が `fist_sizes` のどれでもないもの。`grips` のある拳が、握る部品の画素と上下左右・斜めのどれでも接していないもの（どちらかが空の部品のコマは除く） |
| 77 | 腕が残っていないか | `weapon_check.py` の `--arm` の意味を逆にする。今は「握る手が腕の色とつながっていない」を落とすが、体＋拳の方針に合わせて「握る手に、腕の色が直にか輪郭1画素を挟んでつながる」を落とす。D で敵の袖の消し忘れを拾うため |

依頼者に確かめた解釈:

- 3: ロランの待機の2コマ目で、拳がどいて見えるようになった胴を埋めた所は、SPEC に埋めると書いてあるので「動いてよい」として通す
- 81: ISSUES の行は「部品の取り付けの大きさと位置を見ない」だけなので、SPEC の決まり（握る手は他の手と同じ大きさ、拳は柄を握る）を確かめることと解釈した
- 12: 目と輪郭は同じ色なので、目の行を設定で教える。それでも誤検出が多ければ、ISSUES に「道具にしない」と理由を書いて閉じる

## スマホ用の画像の道具 `tools/phone_sheet.py`

依頼者はスマホで見るので、HTML のページの代わりに PNG を作る。作業フォルダの3本（`phone_png.py`・`phone_diff.py`・`phone_cmp.py`）を1本にまとめ、最初の引数で種類を選ぶ。

- `order CONFIG OUTDIR`: 向きごとに1枚。各行が1コマで、部品を奥→手前に並べ、最後に組んだ絵
- `diff NOW_DIR CAND_DIR DIR OUT.png`: コマごとに「今の絵／案／案に今と違う画素の赤枠」（印なしと印ありを並べる決まりのとおり）
- `cmp NOW_DIR DIR OUT.png LABEL=CAND_DIR[@向き] ...`: コマごとに今の絵と案をいくつも並べる

今の3本は比べる絵の置き場が `assets/unit/gau` に固定なので、引数で渡す。状態は `--states` で絞れる（省くとその向きのコマすべて）。`--dirs` で向きを絞れる（`order`）。
`px.py`・`shift_cfg.py`・`drop_keep.py`・`count_boxes.py` はガウの作業の使い捨てなので移さない。

## 進め方

道具ごとに:

1. テストを先に書く。テストの絵は一時フォルダか `tests/fixtures/` に置き、`assets/` の絵を読ませない
2. 道具を作る
3. 既存の絵の全件に掛けて、落ちたものを数える（ユニットはロラン・イネス・ガウ、item とタイルは全点、11 は `tests/` 全部）
4. 落ちたものを一覧（スマホ用の画像つき）で依頼者に見せる。依頼者が1件ずつ、例外にする（設定ファイルに理由と日付）・絵を直す（ISSUES に1行立てる）・道具の判定を直す・道具にしない、を決める

**絵はこの作業では直さない。** 依頼者が「直す」と決めた絵は ISSUES に立て、合意済みの順の E（全ユニット再検証）で直す。
絵を直すと、そのたびに見せて承認をもらう流れが入り、道具の整備と混ざるため。

## 文書

- `types/unit/SPEC.md`: 「自己チェック①」を「`tools/unit_rules.py checks/<ユニット>.json` を通す」に書き換え、長い `weapon_check.py` の指定は設定ファイルへ移す（敵の指定は D まで SPEC に残す）。
  77 に合わせて、武器の節の「振りかぶりで手を上げたら、体と手の間に腕（袖）を描く」と `--arm` の説明を体＋拳の方針に合わせて直す
- forge の `CLAUDE.md`: コマンドの一覧に新しい道具と入口を足す
- forge の `ISSUES.md`: 直した行は消す。依頼者が「直す」と決めた絵、「道具にしない」と決めた確認は行を立てる

## テスト

- 道具ごとに `tests/test_<道具>.py`。小さな絵で、落とすべきものを落とし、通すべきものを通すことを確かめる
- 設定ファイルの誤り（知らないキー・無い部品・無いコマ・無い色名）で終了コード 2 になること
- 入口は、例外で通した失敗を数え、例外に無い失敗で終了コード 1 になること
- 全体の `.venv/bin/python -m unittest discover -s tests` を通す

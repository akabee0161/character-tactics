# 表示の大きさと顔の構図を決める（工程 4 の設計）

2026-11-23 に依頼者と相談して決めた。作業「顔グラを生成 AI で作る」の工程 4。前の工程の設計は `2026-11-22-face-gen-ai-design.md`（全体）と `2026-11-23-modal-gen-design.md`（工程 3。最後に「工程 4 で決まっていること」がある）。

## 意図

今のボルグ（ally05）の顔グラは頭が切れている（依頼者）。顔のテンプレートが「顔のアップ」（`portrait`）で写すため、生成した絵の上の辺で頭が切れる。

そこで、頭が切れない写し方の元画像を作り、1 枚の元画像から 2 通りに切り出してゲームに渡す。大きい枠には頭の全体が入った絵、小さい枠には顔のアップを使う。小さい枠に頭の全体を入れると顔が小さくなって見えにくいため（依頼者）。

工程 5 では残りの顔グラ 26 枚を作る。そのため、切り出しと透明化は手作業でなく道具で行い、何度書き出しても同じ画像になるようにする。

## 目標・目標でないこと・失敗とみなすこと

目標:

- 顔のテンプレートを「胸から上」の写し方に変える
- forge の書き出しの道具（`artgen.export`）で、範囲どおりの切り出し・背景の透明化・2 通りの画像の書き出しを行えるようにする
- ゲームが、枠の大きさに応じて大きい顔と小さい顔を使い分けるようにする
- ボルグの顔を新しい写し方の絵（依頼者が選んだ 4 番）で作り直し、ゲームに入れる

目標でないこと:

- `FACE_PX`（64・40・32）を変えること（頭が切れることが問題で、枠の大きさは問題でない）
- ボルグ以外の顔を作ること（工程 5）
- ボルグのマップの絵を直すこと。新しい顔をゲームに入れたあと、依頼者が見比べて、直すかどうかを決める（依頼者）
- 表情（`face_<表情>.png`）を作ること
- 見本 4 人（`knight` など）を新しいテンプレートで作り直すこと
- 顔の位置を自動で見つけて範囲を決める仕組み（範囲は Claude が決めて依頼者が承認する）

失敗とみなすこと:

- 大きい顔で頭が切れている
- 顔や服の内側が透明になって穴があく（白い服・白目・明るい鎧など）
- 小さい画像が無い顔（ドット絵の顔 26 枚）の表示が、今と変わる
- 同じ元画像と設定から書き出し直したときに、違う画像になる

## 決まっていること（依頼者）

- 大きい枠（64px：会話・セリフ欄・カード）は A「頭の全体＋首元」、小さい枠（40px の下のバー、32px の仲間一覧・リザルトなど）は C「顔のアップ」にする。1 枚の元画像から 2 通りに切り出す
- 元画像は、テンプレートの写し方を `portrait` から `upper body` に変えて作る（工程 3 の試しでは、`portrait` を外して `upper body` だけにすると、ボルグの頭が収まった絵が 12 枚中 7〜10 枚。`portrait` を残して `upper body` を足すだけだと 8 枚中 3 枚）
- ゲームには顔の画像を 2 枚渡す。ゲームは枠の大きさで使う画像を選び、小さい画像が無い顔は 1 枚を使う
- ボルグは新しい写し方で作り直す。絵は 12 枚の回り（`illust-asset-forge/local/rounds/20261123_110238.json`）の 4 番（シード 2635050234、反転なし）。依頼者が選び、`illust-asset-forge/local/selected/ally05/face.png` にある
- 4 番は、とがった髪の先の 2 画素（x=308〜309）が元画像の上の辺に触れている。64px では見えないので、このままでよい（依頼者）。範囲は元画像の中に限る（はみ出しを透明で埋める仕組みは作らない）
- A・C の切り出す範囲はキャラクターごとに Claude が決め、依頼者がページで承認する（Claude の案を依頼者が承認）
- 頭の切れていない候補は、依頼者が候補のページで全部を目で見て選ぶ（工程 3 で決まった。画素を数えて候補を外す道具は使わない）

## 進め方の案（Approaches）

| 案 | 中身 | 採否 |
|---|---|---|
| 1. forge の書き出しの道具に、切り出しと透明化を入れる | 範囲と透明化の条件を `character.yaml` に書き、`artgen.export` が 2 枚と確認図を作る。ゲームはユニットの JSON に小さい顔の欄を足す | **採用**（依頼者） |
| 2. 道具を直さず、工程 2 と同じく Claude が手作業で 2 枚を作る | すぐできて変更が少ない | 不採用。範囲と条件が README の文章にしか残らず、工程 5 の 26 人 × 2 枚で同じ手作業を繰り返し、間違えやすい |

ゲームの側で、名前の決まり（`<id>-face-small.png` があれば使う）で小さい画像を探す形も考えたが、外した。小さい画像が無い顔では毎回読み込みが失敗し、起動時に画像の有無を確かめる今の検査（`src/engine/registry.ts`）にも合わないため（Claude の判断）。

案 1 の弱点: forge の道具を直すので、`illust-asset-forge/UPSTREAM.md` に記録が要り、テストも増える。

## 設計

### 1. 顔のテンプレートを「胸から上」にする（`illust-asset-forge/templates/face.yaml`）

- `prompt` の `portrait` を `upper body` に置き換える。ほかのタグ（`looking to the side, simple background, white background`）は変えない
- `negative` から `upper body` を外す（今は `negative` にも `upper body` が入っている。工程 3 の試しではジョブの `remove_negative` で外していた）。ほかのネガティブ（`full body, cowboy shot, from behind, profile, head out of frame, cropped head`）は残す
- この変更は依頼者が承認済み（デフォルトのテンプレートを変えるときは依頼者に確かめる決まり）。`UPSTREAM.md` に 1 行足す
- `inpaint.box`（表情の範囲の既定値 `[320, 260, 720, 660]`）は顔のアップに合わせた値で、胸から上の絵では顔の位置と合わない。今回は表情を作らないので変えない。表情を作るときは、依頼者がキャラクターごとに範囲を決める（今の決まりのまま）。README にそのことを 1 行書く
- 見本 4 人の採用済みの絵は、古いテンプレートで作ったまま残す。書き出しの検査は条件のプロンプトとテンプレートの一致を見ないので、書き出しは止まらない（builder が確かめる）

### 2. 切り出しの範囲と透明化の条件を `character.yaml` に書く

顔のキャラクターごとに、次の欄を任意で書けるようにする（キーの名前は Claude の案。builder が変えてよい）:

```yaml
face_crop:
  large: [x0, y0, x1, y1]   # A「頭の全体＋首元」。元画像（1024px）の画素の座標
  small: [x0, y0, x1, y1]   # C「顔のアップ」
  clear_colors:             # 任意。外につながる白のほかに透明にする色
    - {min: 214, max_rg: 14, max_gb: 16}
```

- 範囲は正方形にする（`x1 − x0 == y1 − y0`）。正方形でない、元画像からはみ出す、`x0 >= x1` などは `ConfigError`（`<相対パス>: face_crop.large: <理由>` の形）で止める
- `small` は `large` が無いと書けない。`large` だけ書いたときは小さい画像を作らない
- `face_crop` が無いキャラクター（見本 4 人など）の書き出しは今と同じ（元画像を丸ごと縮める。透明化しない）
- `clear_colors` の各項目は、工程 2 のクリーム色の条件と同じ形（全チャンネルの最小値が `min` 以上、かつ `r − g ≤ max_rg`、かつ `g − b ≤ max_gb`）。形の細部は builder に任せる。ボルグの 4 番に飾りのクリーム色が無ければ書かない
- 表情の範囲（`inpaint_box`）と同じく、範囲は元画像の画素の座標で持つ。元画像を選び直したら、範囲も決め直す

### 3. 書き出しの道具で 2 枚と確認図を作る（`illust-asset-forge/src/artgen/export.py`）

`face_crop` があるキャラクターでは、`python -m artgen.export <id>` が `face.png`（と、あれば `face_<表情>.png`）から次を作る:

| 出力 | 中身 |
|---|---|
| `characters/<id>/face.png` | `large` の範囲を切り出し、透明化し、256px に縮めた RGBA の PNG |
| `characters/<id>/face-small.png` | `small` の範囲を切り出し、透明化し、128px に縮めた RGBA の PNG（`small` があるときだけ） |
| `characters/<id>/face_<表情>.png` と `face_<表情>-small.png` | 表情があるときは、同じ範囲・同じ条件で作る |
| `local/check/<id>/face-large.png`・`face-small.png` など | 確認図。透明にした画素を赤で塗った、切り出した範囲の絵（リポジトリに入れない） |

- 大きさ（256・128）は Claude の判断。64px の枠は高精細の画面で 3 倍の 192px ほどになり、40px の枠は 120px ほどになるため。`templates/face.yaml` の `export_size` を大きい方に使い、小さい方の大きさをテンプレートに足すか定数にするかは builder に任せる
- 透明化: 切り出した範囲の四辺の画素から塗りつぶしを始め、つながっている「白（全チャンネル 240 以上）」と `clear_colors` に当たる画素を透明にする。範囲の内側にあって外につながっていない白（白目・服の白など）は残す。透明化は縮める前の大きさで行い、縮めるときは透明の縁が黒ずまないよう、アルファを考慮して縮める（builder の判断で方法を選ぶ）
- 範囲の辺で服が切れているときは、服の白が辺から塗りつぶされて透明になるおそれがある（工程 2 で分かった注意。HANDOVER.md の「工程 2 の結果」にあり、README にはまだ無い。README「顔グラの例外」に書き足す）。それを見つけるのが確認図。確認図は毎回作る
- `params.json` には今と同じく元画像の条件を書く。あわせて、書き出しに使った `face_crop` も記録する（どの範囲で作った画像かを後から分かるように。形は builder に任せる）
- 今の決まり（すべてを検査してから書き始める、今回の `source/` に無い古い出力は消す）を小さい画像にも当てはめる。`face_crop.small` を消したら、古い `face-small.png` も消す
- `UPSTREAM.md` に 1 行足す。README の「Claude 側の流れ」と「10. Modal で作る」の取り込みの後の手順に、範囲を決めて承認を受けることを書き足す

### 4. 範囲を決めて承認を受ける流れ

1. 依頼者が候補のページで顔を選び、Claude が `cloud adopt`・`cloud install <id>` で `source/face.png` に取り込む（今の流れ）
2. Claude が元画像を見て、A・C の範囲と、必要なら `clear_colors` を決め、`character.yaml` に書く
3. Claude が `artgen.export <id>` を実行し、承認用のページ（HTML を Artifact で公開する）を作る。ページには次を並べる
   - 元画像に A・C の範囲を枠で描いた絵と、枠を描いていない元画像（枠が画素を覆うため、印なしと対で見せる）
   - 確認図（透明にした画素を赤で塗った絵）
   - 書き出した 2 枚を、ゲームの枠の大きさ（64px・40px・32px）とゲームの背景の色で表示した見え方。64px は大きい画像、40px・32px は小さい画像
4. 依頼者が承認したら、書き出した画像をゲームの `assets/images/` に写してコミットする。直す点があれば 2 に戻る

承認用のページを作る道具を forge に入れるか、その都度 Claude が作るかは builder に任せる（工程 5 で 26 回使うので、道具にする方が手間は少ない）。

### 5. ゲームが大きい顔と小さい顔を使い分ける

- ユニット・敵・村人の JSON の `sprites` に、任意の欄 `faceSmall`（小さい顔の画像のファイル名）を足す。例: `"face": "ally05-face.png", "faceSmall": "ally05-face-small.png"`
  - `src/engine/schema.ts` の `Sprites`・`NpcDef` の読み込みに足す。無ければ `null`
  - `src/engine/registry.ts` の画像の有無の検査に足す（`faceSmall` のファイルが `assets/images/` に無ければ止める）
  - `faceSmall` だけがあって `face` が無いときはエラーにする（Claude の判断。小さい枠だけに顔が出るのはおかしいため）
- 描くときの使い分け: `src/render/sprites.ts` の `drawFace` で、描く大きさ（`radius × 2`）が `FACE_PX.panel`（40px）以下なら `faceSmall` を、それより大きければ `face` を使う。`faceSmall` が無ければ `face` を使う。呼び出し側（`src/ui/screens.ts`・`src/ui/card-view.ts`）は変えない（Claude の判断。呼び出し側に分岐を置くと付け忘れが起きるため。`drawSquareOrCircle` の注記と同じ考え）
- 敵は同じ `kind` で `face` をそろえる決まりがある（`src/engine/enemy-looks.test.ts`）。このテストは定義の全体（id・`sprites.map.sheet`・color を除く）を比べるので、`faceSmall` を schema に足せば、そのままそろいを見る対象に入る。テストの直しは要らない
- 村人の顔は `src/engine/registry.ts` で `sprites: { role: null, face, map: null }` に作り直してから `drawFace` に渡している（358 行あたり）。ここにも `faceSmall` を通す
- 今の顔（`*-face.png`）のファイル名は変えない

### 6. ボルグを作り直す

1. `cloud install ally05` で 4 番を `characters/ally05/source/` に取り込む。全身絵（`source/fullbody.png`）は持ち越される。今ある表情は無い
2. 取り込みの出力の書き戻しの一覧を `character.yaml` に戻す。4 番は試しのジョブ（`remove: portrait`・`extra: upper body`・`remove_negative: upper body`）で作ったので、取り込みの道具は、画像に記録された上書きをそのまま一覧に出すので、一覧は空にならない。テンプレートの変更でこの上書きは反映済みとみなし、`character.yaml` には何も足さない（Claude の判断）。テンプレートでは `upper body` の位置が先頭になるので、プロンプトの文字列は 4 番のものと順番が違う（タグの集まりは同じ）。同じシードで作り直しても画素まで同じ絵にはならないが、Modal と Colab でも画素は一致しないので、同じ絵を作り直す使い方はもともとしていない
3. 上の 4 の流れで範囲を決め、依頼者の承認を受ける
4. `assets/images/ally05-face.png` を新しい大きい顔に差し替え、`assets/images/ally05-face-small.png` を足し、`assets/units/ally05.json` に `faceSmall` を書く
5. ブラウザで、会話・セリフ欄・カード（64px）、下のバー（40px）、仲間一覧・リザルト（32px）にボルグの顔が出ることを確かめ、撮った絵を依頼者に見せる。マップの絵を直すかは、ここで依頼者が決める
6. `illust-asset-forge/local/runs/ally05/face/20261123_105626/`（4 番がある候補のフォルダ。回りの記録の名前 `20261123_110238` とは違う）と `local/selected/ally05/` は、`source/` に入ったあとは消してよくなる（消すのは依頼者。週次のタスクが削除候補として報告する）

- README（ゲーム）のユニットの JSON の説明に `faceSmall` を足す
- `illust-asset-forge/README.md`・`illust-asset-forge/CLAUDE.md`: テンプレートの写し方、`face_crop`、書き出しの出力、承認の流れ

- `params.json` に範囲を記録する形
- 承認用のページを道具にするか、その都度作るか
- 確認図の置き場の名前

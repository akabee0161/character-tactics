# 敵ユニットのバリエーション自動生成 設計

作成: 2026-10-06

## 目的

敵の種類を増やすとき、1体ずつ描く手間と依頼者の確認の回数を減らす。
ロラン（剣と盾）・イネス（弓）・ガウ（短剣）のコマを流用し、**色・かぶり物・素体（男女）を変えて**、敵の見た目のバリエーションを機械的に作る。
品質はロラン・イネス・ガウと同じ程度を保つ。

## 依頼者と合意したこと（2026-10-06）

- 今回は**新しい敵の種類を追加する**。既存の5種（弓兵・盾持ち・ならず者・まじない師・ガルム）には触らない。
  最終的には既存の敵を新しい絵に置き換える想定だが、それは別の作業とする
- 敵の種類ごとに男女のパターンを作る
- 実現方法は**段階導入**（短剣 → 剣盾 → 弓の順）。各段階の終わりで止まって依頼者に見せる
- ミスト（ローブ型）は別の型なので対象外

## 前提（2026-10-06 に調べたこと）

- 味方3体は素体と部品を `pixel-asset-forge/tools/compose.py` で重ねて作る。設定は `compose/<unit>.json`、書き出しは `sheet.py` → `export.py`
- グリッドファイルは `# map: p=cloth_hi` のように、文字から色名への対応で色を決める。**色替えはこの対応の色名の置き換えだけで済み、画素は触らない**
- 素体は `types/unit/base/male_<dir>.txt` と `female_<dir>.txt`（立ちの4方向のみ）
- 武器が単品の部品になっているのは短剣（`assets/part/dagger/`）だけ。剣・盾・弓はロラン・イネスのコマに素体と一体で描かれている
- 待機の2コマ目・歩き・攻撃用の素体コマ（`parts/body_idle2_*`、歩きの脚、`body_noarm_*`）は男性素体の分しかない。**女性素体の分は新しく描く必要がある**
- 既存の敵は `assets/enemies/<id>.json` と `assets/images/<id>-map.png`（12行のシート）で、味方と同じ形式

## 設計

### 1. 仕組み全体

- 敵1種類ごとに「レシピ」を1ファイル書く。置き場は `pixel-asset-forge/enemy/<id>.json`。
  `assets/` の下に置くと `validate.py` と `render.py` が `rglob` で読んで落ちる（既存の決まり。シート定義・compose 設定と同じ理由）
- レシピの内容:
  - `archetype`: 武器の型（`dagger` / `swordshield` / `bow`）。動きの手本（コマ構成・fps・攻撃のコマ数）を決める
  - `body`: `male` / `female`
  - `head`: かぶり物・髪の部品（既存の部品の指定）
  - `recolor`: 役割（服・かぶり物・金属・革など）ごとの、置き換え後のパレット名
  - `id`・`name`: 出力名と、敵の JSON の雛形に使う名前
- 新しい道具 `tools/enemy_build.py` が、レシピから compose の設定をメモリ上に組み、既存の `compose.py` → `sheet.py` を呼んで `build/sheets/<id>.png` まで作る。
  既存の道具の中身は変えない（レシピを読む部分だけを足す）
- 同じレシピからは**常に同じ PNG** ができる（乱数を使わない）

### 2. 色替え

- 色替えは `# map:` の色名の置き換えだけ。**画素は変えない**
- 使う色は `palette/master.json` の既存色だけ。足すときは既存の規約どおり、描く前に `probe_colors.py` で草・道・床に対して測る
- 役割の分け方は、手本のコマの `# map:` の文字を基準にする（例: ガウの `p q r` は服）。役割ごとの文字は段階ごとに手本から読み取って決める
- 敵の見分けのため、味方（ロラン・イネス・ガウ）と区別できる色の組み合わせにする。色の組み合わせの一覧を作って依頼者に見せる

### 3. 男女

- **男性**: 味方の手本のコマ（待機・歩き・攻撃）をそのまま流用する。ほぼ自動
- **女性**: `female_*` の素体に、待機の2コマ目・歩きの脚・攻撃の腕のコマを新しく描く。
  描いた素体コマは武器の型をまたいで使い回す（1回描けば足りる）。ここは自動化せず、確認ポイントで依頼者に見せる
- 男女で同じレシピを使い回せるように、レシピの `body` だけを変えれば女性版ができる形にする

### 4. 段階

| 段階 | 内容 | 終わりの確認 |
|---|---|---|
| 1 | 短剣（ガウ流用）で、男・女、色、かぶり物を通しで作る。`enemy_build.py` とレシピの検査を作る。女性素体の動きのコマを描く | 女性素体の品質、一覧と動きのページ |
| 2 | ロランの剣と盾を部品に分解し、剣盾の敵を作る | 部品の形、一覧と動きのページ |
| 3 | イネスの弓を部品に分解し、弓の敵を作る | 部品の形、一覧と動きのページ |

- 段階1で一番大きな不確定要素（女性素体の品質）を、武器が部品化済みの短剣だけで確かめる。うまくいかなければ段階2に進む前に方針を変える
- 剣・弓を部品に分解するときは、味方のコマが1画素も変わらないことを `compose.py --check` で確かめる

### 5. 範囲外

- ステージへの配置、HP・攻撃力などのバランス（敵の JSON の雛形までは作るが、数値の調整はしない）
- 既存の5種の置き換え
- ミスト型（ローブ・スカート）
- 顔の絵（`assets/images/*-face.png`）。今回は既存の顔の流用か、色替えの範囲で扱う（段階1で扱いを決める）

### 6. 検査

- 自動テスト（pytest。`pixel-asset-forge/tests/`）:
  - レシピの検査: 知らないキー、存在しない色名・部品、不正な `archetype`・`body` を、メッセージつきのエラーにする
  - 色替えが画素を変えないこと
  - 同じレシピから同じ PNG ができること
  - 組み立てたシートが、ゲーム側の規約（12行・コマの正方形・足元 y=30）を満たすこと
- 絵の検査: 既存の `unit_check.py` を全バリエーションに通す（持ち物の文字は型ごとに測る）
- 見た目の確認: 全バリエーションを並べた一覧のページと、状態×4方向の動きのページを Artifact で見せる。確認は1種類につき1回にまとめる
- ゲーム側: 敵の JSON を足したら `npm test`（`sheet-size.test.ts` が実寸と JSON の食い違いを検出する）を通す

## 判断の回数を減らす工夫

- ガウの結果（判断13回）から、確認が必要だったのは「組み合わせた後の顔と動き」だった。バリエーションでは、顔と動きは手本と同じなので確認の対象にしない
- 依頼者が見るのは、一覧のページ1枚（色・かぶり物・男女の組み合わせ）と、女性素体の動きだけ

## 未決（計画の中で決める）

- 敵の顔の絵の扱い

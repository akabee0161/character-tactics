# ユニットのドット絵を描く標準のワークフロー 設計（ガウで試す）

作成: 2026-10-04

## 目的

ロラン・イネスと同じ品質のユニットのドット絵を、依頼者の判断を減らして描けるようにする。
そのために、入力・確認ポイント・Claude が自律で行う範囲を決めたワークフローを作り、ガウを1体描いて試す。
うまくいけば、次の一体から確認ポイントを減らしていく。

issue #23 の1番目（顔グラを forge で作る）はしばらく置いておく。入力の顔は今のフリー素材（`assets/images/*-face.png`）を使う。

## 背景: ロラン・イネスの記録から分かったこと（2026-10-04）

### 判断の回数と種類

依頼者が選んだ・差し戻した回数（進捗台帳の `Ruling:` 行）はイネスで約12回、ロランで約6回。中身は3種類に分かれる。

| 種類 | 例 |
|---|---|
| A. 何を描くかの決定 | 頭の桃紫はバンダナ、弓の構え W1、攻撃は6コマ、ズボンの色 |
| B. 見た目の品質の指摘 | 横向きが太い、結び目の差し戻し、背面の鏃、左右の非対称 |
| C. Claude の進め方の問題 | 見せる前にコミットした、計画の不備 |

### 候補を描いた枚数（部品ごと）

| 部品 | ロラン | イネス |
|---|---|---|
| かぶり物・髪 | 約29枚（前髪5、横向きの頭21、背面3） | 約25枚（結び目18、結び端4、バンダナ3） |
| 武器（持ち方と攻撃） | 約31枚（ほぼ攻撃の振り方） | 約53枚（構え5、待機の手の引き8、攻撃40） |
| 目・服・ズボン・体形 | 約10枚 | 約19枚 |

枚数は描いた候補の数で、差し戻しの回数そのものではない。

- かぶり物・髪は、顔の絵に写っていない側（ロランの横向き、イネスの後頭部）で枚数が増えた。
  イネスの結び目は K→L→M→N→S1 と5回やり直し、原因は「結び目がどこにあり、端がどう垂れるか」という物の形を Claude が知らなかったこと。
  依頼者が言葉で構造を教えるたびに案を描き直していた。逆にロランの横向きの髪は、依頼者が参考画像を出して早く決まった
- 武器は、形ではなく**持ち方と動き**（剣の振り方、弓の構えと腕の位置）で枚数が増えた。待機の2コマ目の中身（上下でなく手を引く）や攻撃のコマ数（6コマ）は作業の途中で決まった
- 依頼者の指摘には「部品の形」と「体に重ねたときの隠れ方」が混ざっていた

### 使い捨てのスクリプト

2体の作業フォルダ（`.superpowers/sdd/2026-10-01-roran-unit-from-face/`・`2026-10-02-roran-sword-from-icon/`・`2026-10-03-ines-unit-bow/`、git 管理外）に約120本ある。

| 分類 | 例 |
|---|---|
| ① 確認の道具 | `open_edges.py`・`body_center.py`・`colors.py`・`zoom.py`・`present.py`・`review_page.py` |
| ② 組み立ての道具 | `compose.py`・`side.py`・`up.py`（部品をずらして組む）、`propagate.py`（`base` の差をコマに写す）、`walk.py`、`face_down.py` |
| ③ その一体だけのもの | `knot*.py`・`bow.py`・`attack_up*.py`・`add_stage_t10b〜k.py`（11本） |

`zoom.py`・`open_edges.py`・`present.py`・`colors.py` はロランとイネスで中身が分かれている。
イネスの `compose.py` は弓の画素の座標を Python に直接書いていて、使い回せない。

## 決めたこと（依頼者の判断、2026-10-04）

### 1. ワークフロー

| 段階 | Claude が自律で行うこと | 確認ポイント（依頼者） |
|---|---|---|
| 0. 設定シート | 顔の絵とゲームの JSON から、部品の分解、色と解釈（髪かかぶり物か、無視する色など）、使う素体を一覧にする | **CP0: 設定シートと動きの方針を承認** |
| 　動きの方針 | 状態ごとに言葉で案を出す: 待機の2コマ目で何が動くか、歩き、攻撃のコマ数と fps、方向ごとの攻撃の決めの姿勢（「正面は真っすぐ振り下ろす」など）。手本としてロラン・イネスの動きのページを添える | （CP0 に含む） |
| 1. 部品の単体スケッチ | 髪・かぶり物・武器を**素体抜きの単体で4方向**描く。素体の頭の輪郭は下敷きにだけ使い、絵には入れない | **CP1: 部品の形を確認** |
| 2. 正面の `base` | 部品と素体を、前後の順番の規則で組み合わせる。自己チェックを通してから見せる | **CP2: 正面を確認** |
| 3. 4方向の `base` | 残り3方向を組み合わせ、既存のユニットと並べて自分で比べる | **CP3: 4方向を確認** |
| 4. アニメ | CP0 の方針どおりに待機・歩き・攻撃を作る | **CP4: 動きのページで確認** |
| 5. 仕上げ | 書き出し、SPEC への追記、PR の準備 | （PR は依頼者の指示で作る） |

- 確認ポイントは CP0〜CP4 のすべてで止まる（案 A）。1体目の試行は、どの段階でまだ差し戻しが出るかを確かめるのが目的
- 部品の単体スケッチの狙いは、依頼者が確かめるものを**部品そのものの形だけ**にすること。体に重ねたときの隠れ方は Claude が前後の順番の規則で処理する
- 武器の単体スケッチは**4方向の向きだけ**。弓の引き絞りや剣の傾きのような、形や傾きが変わる状態は描かない
- 武器の持ち方と動きは単体スケッチでは決まらない。最初に合わせるのは絵ではなく**動きの方針**（CP0）
- CP0・CP1 で決めたことは、2. 以降の Claude の作業の前提になる。前提が変わるときだけ確認し直す

### 2. 0. の設定シートで決めること

1. 部品に分ける: 頭（髪・かぶり物）、顔（目・眉・耳）、上着、下、持ち物、その他。部品ごとに顔の絵から切り抜いて見せる
2. 解釈を確かめる: 「桃紫はバンダナ」「左下の青は無視」のような読み方の一覧
3. 見えない側の形: 顔の絵から読めない部分（後頭部・背中・持ち物の向き）を部品ごとに挙げる。形そのものは 1. の単体スケッチで合わせる
4. 案を振る軸: 部品ごとに、形・位置・大きさのどれを振るかを先に合意してから案を描く
5. 聞かないこと: `types/unit/SPEC.md` の規約で決まっていること（目は縦2px など）は聞かない

### 3. Claude が自律で行う範囲

| Claude が確認なしで行う | 止めて確認する |
|---|---|
| 自己チェック①②に落ちた案を、見せずに直すか捨てる | CP0・CP1 で決めた前提から外れるとき |
| 組み合わせでの隠れ方の処理（前後の順番の規則の範囲） | 規約にないことを決めるとき |
| 規約の範囲での色の置き方 | 計画の不備が見つかったとき |
| 確認ポイントのあいだの作業スクリプト | — |

- 確認ポイントで見せた絵を、自己チェック①②のために**1〜2画素だけ直すときは事後の報告でよい**
- **絵を変えたら、見せる前にコミットや次の段階へ進まない**（イネスで止められた件。手順として明記する）

### 4. 自己チェック

過去の指摘を3つに分ける。

**① 道具で機械的に測る（見せる前に毎回流す）**

- 輪郭の切れ目
- 方向ごとの脚の中心が全コマでそろっているか（輪郭と持ち物を除いた y≥24 の画素の中心）
- 孤立した1画素（ロランで肩の明るい点の残りが欠けた点に見えた）
- 色の文字の取り違え（イネスの最終レビューで弓の1画素が脚の色だった）
- 色どうしが見分けられるか（`probe_colors.py`）

**② Claude が見て確かめる（チェックリスト）**

- 奇数幅・偶数幅で左右対称が崩れていないか（コマの中心は x=15.5）
- 尖った先端を、輪郭に囲まれた1画素で表していないか
- 動くとき部品の長さが変わっていないか（矢が伸びて見えた件）
- 奥の手・持ち物が体に重なる画素を描いていないか
- 武器の長さをコマの空きでなく武器そのもので決めているか
- 横向きの胴の厚みが、既存のユニットと並べてそろっているか

**③ 見え方（依頼者にしか判断できない）**

「ハートに見える」「刈り上げに見える」「もみあげに見える」など。Claude はチェックできないので、指摘された形を「似た形を避ける例」として記録する。

### 5. 道具の標準化

道具はテストを書いて（TDD）forge の `pixel-asset-forge/tools/` に入れ、`UPSTREAM.md` の「forge に戻す候補」に記録する。

**試行の前に作るもの**

- **部品の重ね合わせ道具**（新規）
  - 部品は絵のファイル。アセットと同じ書式（`# type: unit`、`# size: 32x32`、透明は `.`）で、32×32 のコマの上のユニットに載る位置に描く。CP1 で確かめたものがそのまま入力になる
  - 組み立て方は設定ファイルに書く: 方向ごとに、素体、部品、部品のずらし量、前後（体の手前か奥か）
  - 奥の部品は体が透明な画素にだけ描く。手前の部品の縁は、体に接するところも輪郭で閉じる（イネスの `compose.py` の `layer(..., "front")` と同じ考え）
  - 置き場: ユニットだけの部品は `assets/unit/<ユニット>/parts/`、ユニットをまたいで使い回す武器は `assets/part/`（敵の弓兵がイネスの弓を使えるように）
- **自己チェック①**: `open_edges`・`body_center`・`colors` を1本にまとめ（ロラン版とイネス版の差を吸収）、`validate.py` から呼べるようにする

**試行中に必要になった時点で移すもの**

`zoom`・`present`（案を拡大して並べる）、`review_page`（段の追加を設定ファイルへの追記で済ませ、`add_stage_*` をなくす）、`face_down`（拡大された顔を元の画素に戻す）、`propagate`（`base` の差をアニメの各コマに写す）。
2回以上使ったものだけを共通にし、作り込みすぎない。

**標準にしないもの**: その一体だけの作業スクリプトは今までどおり作業フォルダに置く。

### 6. 試行するユニット: ガウ

- ガウ（物見・近接、`assets/units/gau.json`）。顔（`assets/images/gau-face.png`）には緑の頭巾のようなかぶり物と首のスカーフがあり、髪は赤茶
- 選んだ理由: かぶり物がイネスのバンダナと似ていて、判断の回数と品質をイネスと比べやすい。今までの部品を流用しやすい
- ミストは描かない。ローブ・スカートの服になると思われ、女性形の素体が使えない新しい型なので、別の作業として扱う
- 同時に2体は進めない

### 7. 評価のしかた

**判断の回数**

- 確認ポイントごとの依頼者の返答を台帳に記録する（承認・選択・差し戻し）。差し戻しには種類 A・B・C を付ける
- イネスと比べる（判断約12回、かぶり物の候補25枚、武器の候補53枚）
- 自己チェックのあとの1〜2画素の直し（事後の報告）は別に数える

**品質**

- ロラン・イネス・ガウを同じ倍率で4方向に並べた絵と動きのページで、依頼者が「同じくらいか」を判断する（最後の判断は依頼者）
- 自己チェック①はすべて通っていることを前提にする

**振り返り**

- どの確認ポイントで差し戻しが出たかを見て、次の一体で確認ポイントを減らせるかを決める
- 新しく出た見え方の指摘は、自己チェック②の項目か「似た形を避ける例」に足す

### 8. 標準の手順の置き場

決まったワークフローは forge の `pixel-asset-forge/types/unit/SPEC.md` に「描く手順」の節として書く（ユニットの規約の正典）。
自己チェック②・③の項目もそこに置く。この spec は作成時点のログとして残す。

## 範囲外

- issue #23 の1番目（顔グラを forge で作る）
- ミスト、敵のユニット
- ゲームのコードの変更（ガウの `gau.json` のコマ数・fps は CP0 の動きの方針で変えることがある）
- 色の命名の整理（`feat/roran-face` のマージ後に独立した作業として行う）

## 進め方

- この spec の承認 → 実装計画（writing-plans）→ 実行方法の選択、の順に承認を取る
- 計画に不備が見つかったら、直す前に止めて報告する
- 絵は確認ポイントごとに、案を並べたページ（Artifact）と、アニメは動きのページで見せる

# アセットの大きさの規約 設計

作成: 2026-09-28

## 背景

pixel-asset-forge の issue #6（https://github.com/akabee0161/pixel-asset-forge/issues/6）で、
ステージ1の村・岩・木が1マスに4つ並び、人より小さく見えることが分かった。
原因は、ゲームの1マス（32px）と forge のタイル（16px）の関係を決めないまま、
両方のリポジトリで別々にアセットを作ったこと。`drawTerrain` は16pxのタイルを1マスに2×2で敷き詰める。

画面のアセットにも同じ種類の食い違いがあった。

| アセット | 元の絵 | ゲームで描く大きさ |
|---|---|---|
| 顔グラ | 128px（forge の `face` は32px） | 直径 26/28/32/48/60px の5通り |
| 役割アイコン | 32px（README では64px と書かれている） | 26px |

この設計では、全アセットの大きさの規約を character-tactics として決め、README（正典）に書く。

## 目的と成功条件

- forge で新しいアセットを作るとき、この規約を見れば大きさで迷わない
- 顔グラと役割アイコンの枠が、規約の大きさで描かれている

## 規約

**基本:** 絵の1画素を論理座標の1pxで描く（等倍）。等倍にしない例外は表の「表示」欄に書いたものだけ。

| アセット | 絵の大きさ | 表示 | 占める範囲 |
|---|---|---|---|
| 1マス | ― | 32px | ― |
| 地面タイル | 16px | 等倍。1マスに2×2で敷く | 1マス |
| 物（村・岩・木・城など） | 16pxの部品を組んだセット。1マスぶんは2×2（32px） | 等倍 | 1マス以上の整数マス（城は2×2マス＝64pxなど） |
| ユニット | コマ32px（大型は48px） | 等倍 | 足元 y=30・左右中央・背丈24〜26px |
| 顔グラ | 64px | 大きい枠は64px（等倍）、小さい枠は32px（半分） | ― |
| 役割アイコン | 16px | 32px（2倍） | ― |

- 物の絵は、今の forge のタイルと同じく地面（草）を背景に含めて描く
- 顔の小さい枠（32px）だけは、描くときにぼかしを有効にする。ちょうど半分なので2×2画素の平均になり、
  最近傍で1画素おきに間引くより形が残る（依頼者は「1pxの線が抜けるかぼやける」ことを了承済み）
- 画面全体の表示倍率が整数でないのは変えない（issue #17 で依頼者が判断）。規約で揃えるのは
  「絵の1画素＝論理座標の何px」まで
- 複数マスを占める物をマップに置く仕組みは、使うステージが出てきたときに作る

### 決めた理由

- **1マス32pxのまま。** ユニットのコマ（32px、背丈24〜26px）が1マスに収まっている。16pxにすると
  全ステージのデータと移動・射程の数値に影響が広がる
- **物は16pxの部品のセット。** forge の `tile` は16px固定で、城と山で2×2セットの前例がある。
  新しい大きさを規約に足さずに済む
- **物は整数マスを占めてよい。** 城を家と同じ1マスにすると縮尺が崩れる（依頼者の選択）
- **顔グラは64px。** 大きい枠を等倍できれいに出すため（依頼者の選択）。forge の `face` の規約（32px）を変える
- **役割アイコンは16pxの2倍。** forge の `item` と同じ大きさで、描く手間が小さい

## 枠の変更

| 画面 | 関数（`src/ui/screens.ts`） | 今の直径 | 変更後 |
|---|---|---|---|
| 会話の画面 | `drawTalk` | 60px | 64px |
| 戦闘中のセリフ欄 | `drawSpeechBar` | 48px | 64px |
| ステージ選択の仲間一覧 | `drawRoster` | 32px | 32px |
| リザルト | `drawResult` | 28px | 32px |
| 戦闘中の下のバー | `drawBottomBar` | 26px | 32px |

役割アイコンの枠（`src/ui/layout.ts` の `roleBadgeIn`）は高さ26pxから32pxにする。

枠が広がったぶん、周りの要素と重ならないかを README の CDP 手順（ヘッドレスブラウザ）で撮って確かめる。
描画コードにはユニットテストを書かない（CLAUDE.md のテスト方針）。`roleBadgeIn` のようなレイアウト計算を
変えた場合は、既存のテストがあればそれを直す。

今の顔（128px）は、新しい枠では64px（半分）と32px（4分の1）で表示される。

## 今回の作業に含めないもの

合意した順番（HANDOVER.md）で後に回す。

- タイルを元の大きさで描く・通れないマスへのめり込み → 次の作業
- 村・岩・木の描き直し、64pxの顔、16pxの役割アイコンを描くこと → forge 側
- forge の `face` の規約を64pxに変えることと、役割アイコンの型を作ること → forge 側
- 画像の大きさを検査するテスト → 規約どおりの絵に差し替えるときに足す。今の顔（128px）と
  アイコン（32px）は規約と違う大きさなので、今足すと落ちる
- 仮アセット生成スクリプト `tools/gen-placeholder-sprites.mjs`（顔128px・アイコン64pxで出力する）の修正
  → アセットのテキストとビルドをこのリポジトリへ移設するときに合わせて直す

## README に書くこと

「コンテンツの足しかた」節に、上の「規約」の表と補足を書く。
あわせて `assets/images/README.txt` の「face は 128×128、role は 64×64」を規約に合わせて直す。

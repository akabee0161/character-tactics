# 修正事項-20260926（issue #17）対応 設計

作成日: 2026-09-26

## 1. 目的

issue #17 に挙がった9項目（依頼者の6項目と、作業中に見つかった3項目）に対応する。
PR #16（ロランの新しいシート）を CDP で確かめたときに見えた問題が元になっている。
攻撃では敵が重なって絵が見えず、近接のロランはステージ1で攻撃する機会がほとんど無かった。

内容は3系統に分かれ、この順で実装する。

1. **描画の土台** — 足元アンカー、dpr の変化への追従、ステージ1のタイル
2. **攻撃モーション** — モーションを遅くする、ダメージのタイミング、確認用のスロー再生
3. **移動と戦闘** — 敵味方の最小距離、近接の自動の詰め寄り、歩けない場所のタップ

描画の土台を先にするのは、足元の位置が決まらないと、最小距離（§5.1）が見た目どおりかを判断できないからである。

### 対象外

- **③ ドット絵を縮尺しない。** 論理解像度 540×945 より小さい画面では縮小が避けられない。
  依頼者の判断（2026-09-26）で「縮小が避けられないなら仕様を変更しない」とし、今の表示倍率の決め方を残す。
  倍率を整数に切り下げる案も検討したが、PC の画面で表示が今より小さくなるため採らない
- **村のイベント。** 村のマスは今回は歩けないマスとして置くだけにする。イベントは依頼者が後で別件として扱う
- **味方どうし・敵どうしの重なり。** 最小距離は敵味方の間にだけかける
- **pixel-asset-forge 側の記述。** forge の CLAUDE.md に「ゲーム側で倍率が掛からないよう修正する予定」とあるが、
  ③を見送るので実態と合わなくなる。forge リポジトリの変更になるため、本件とは別に依頼者に確認して直す

## 3. 描画の土台

### 3.1 足元アンカー

pixel-asset-forge の `unit` 型は「足元 y=30（32px のコマで）・左右中央」を規約にしている。
今の `drawMapUnit`（`src/render/sprites.ts`）はコマの中心を論理位置に合わせるので、論理位置が腰に来る。

**変更:** コマの足元の行を論理位置に合わせて描く。

- 足元の行は `frame - 2` とする（32px のコマで y=30、ガルムの 48px のコマで y=46）。シートごとの設定は足さない
- `sprites.ts` に「絵の中心」を返す関数を足す。今の論理位置を絵の中心として使っている描画は、すべてこの値に置き換える。
  対象は HPバー・旗・選択リング・護衛の印・被弾や回復などのエフェクト・ドラッグ中の残像である。
  32px の絵では、絵の中心 = 論理位置から 14px 上になる。これで HPバーなどと絵の位置関係は今のまま保たれる
- 丸のフォールバック（シートが無い、または画像を読み込む前）は、丸の下端を足元に合わせる
- **タップの判定:** `pickUnit`（`src/ui/hit.ts`）は論理位置からの距離で選んでいる。これを絵の中心からの距離に変える。
  そのままだと、足元より下の何も無いところをタップしても選べてしまう。
  `pickUnit` は `src/ui` にあり描画の定義を知らないので、呼び出し側（`main.ts`）が絵の中心を求めて渡す形にする

core の座標（移動・射程・交戦の判定）は何も変えない。変わるのは、論理位置に対して絵をどこに描くかだけである。

### 3.2 dpr の変化への追従

`src/main.ts` の `resize` は `ResizeObserver` で要素のサイズ変化だけを見ている。
要素のサイズが変わらずに `devicePixelRatio` だけが変わると、canvas の backing store が作り直されない。

**変更:** `matchMedia(\`(resolution: ${devicePixelRatio}dppx)\`)` の `change` で `resize` を呼ぶ。
このクエリは今の dpr に対してしか一致しないので、発火するたびに新しい dpr でクエリを作り直して登録し直す。
`ResizeObserver` は残す（両方で拾う）。

描画コードなのでユニットテストは書かない。CDP でエミュレーションの dpr だけを変えて、canvas の `width` が追従することを確かめる。

### 3.3 ステージ1のタイル

**タイル画像:** pixel-asset-forge の `build/tile/` から等倍の PNG（16×16）を4枚持ってくる。

| forge のタイル | ゲーム側のファイル名 | 使い方 |
|---|---|---|
| `plain` | `assets/images/tile-plain.png` | 歩けるマス（草原） |
| `tree` | `assets/images/tile-tree.png` | 歩けないマス（林） |
| `rock` | `assets/images/tile-rock.png` | 歩けないマス（岩場） |
| `village` | `assets/images/tile-village.png` | 歩けないマス（村） |

画像の読み込み（`src/engine/loader.ts`）は `assets/images/*.png` の直下しか見ず、`images.ts` はファイル名だけで引く。
そのためサブディレクトリは作らず、`tile-` の接頭辞で区別する。
forge の `build/` は gitignore されている生成物なので、`tools/render.py` で出力したものをコピーしてコミットする。

**敷き方:** 1マス（32px）に 16px のタイルを 2×2 で敷く。拡大しないので、キャラの絵（32px を等倍で描く）と画素の細かさがそろう。
木・岩・村のマスも同じタイルを 2×2 で並べるので、小さな林・岩場・村に見える。

**ステージデータ:** 今の `mapRows` は `.`（歩ける）と `#`（歩けない）の2文字しか使えない。
これに、ステージごとの任意の凡例 `legend` を足す。

```json
"legend": {
  ".": { "tile": "tile-plain.png", "walkable": true },
  "T": { "tile": "tile-tree.png", "walkable": false },
  "R": { "tile": "tile-rock.png", "walkable": false },
  "V": { "tile": "tile-village.png", "walkable": false }
}
```

- `legend` が無いステージ（2 以降）は、今の既定（`.` 歩ける / `#` 歩けない、単色で描く）のままにする
- `legend` があるステージでは、`mapRows` に使える文字は `legend` のキーだけ。キーは1文字に限る
- `tile` の画像が読み込み前なら、今の単色（歩ける／歩けない）で描く
- 歩けるかどうかの判定を、`#` との比較から凡例の `walkable` を見る形に変える。
  対象は `makeGrid`（`src/core/field.ts`）とスキーマ側の配置検証（`src/engine/schema.ts` の `isWalkableCell`）

**ステージ1のマップ:** 外周の `#` をなくして全面を草原にし、木2・岩1・村1の合計4マスを置く。
初期配置・敵の初期位置・ゴールとは重ねない。

| 物 | 列, 行（0始まり） | マスの中心（論理座標） |
|---|---|---|
| 村 | 3, 4 | (112, 144) |
| 岩 | 11, 9 | (368, 304) |
| 木 | 2, 11 | (80, 368) |
| 木 | 13, 18 | (432, 592) |

外周をなくしても、ユニットがマップの外へ出ることはない。移動先の判定（`isWalkableAt`）と
経路探索（`canStep`）の両方が、すでに範囲外を歩けないマスとして扱っている。

## 4. 攻撃モーション

### 4.1 モーションを遅くする

今の攻撃は、全キャラとも 3コマ × 12fps = 0.25秒である。
これを 0.5秒にする。絵を持っている全キャラ（味方4体・敵5体）の JSON で、`attack.fps` を 12 から 6 に変える。
数値の変更だけで、コードは変えない。

### 4.2 ダメージのタイミング

今は攻撃を出した瞬間（`resolveAttacks` の `attack` イベントと同じ tick）にダメージが入るか、飛翔体が出る。
モーションを遅くすると、振り下ろす前にダメージの数字が出るずれが大きくなる。

**変更:** ダメージと飛翔体の発射を、攻撃モーションの最後のコマ（振り下ろし）が出る時刻まで遅らせる。

- **振りかぶりの時間** = `(attack.frames - 1) / attack.fps`。3コマ × 6fps なら 0.333秒。
  ユニットを作るとき（`src/core/state.ts`）に定義のシートから求めて `Unit` に持たせる。シートが無いユニットは 0（今と同じく即時）
- `resolveAttacks` はクールダウンが明けたら、今までどおり `attack` イベントを出し、攻撃側の値（`HitSource`）を固定する。
  ねらいうちの消費・絆の支援・クールダウンの再設定も、この時点で行う（今と同じ）。
  そのうえで、ダメージの代わりに「保留中の攻撃」（相手の uid・`HitSource`・発動時刻）を `Unit` に積む
- 毎 tick、発動時刻に達した保留中の攻撃を処理する。攻撃した側と相手がどちらも生きていれば（`retired` でなく `hp > 0`）、
  近接はダメージを与え、弓と魔法は飛翔体を出す。どちらかが倒れていれば、その攻撃は捨てる
- 相手が離れても、射程は判定し直さない。空振りは作らない。交戦が解けた場合や、攻撃した側が移動を指示された場合も同じである
- 振りかぶりの時間が 0 のユニットは、今と同じ tick で処理する。今のテストはシートを持たない定義で書かれているので、そのまま通る

振りかぶり（0.333秒）は攻撃の間隔（1.4〜2.4秒）より十分短い。なので、1体が同時に抱える保留中の攻撃は1つで足りる。

### 4.3 確認用のスロー再生（開発用）

攻撃のコマは短く、時間を止めたりコマ番号を出したりする手段が無いので、連写しても捉えにくい。

**変更:** URL に `?debug` が付いているときだけ、次の操作を有効にする。付いていなければ何も変わらない。

| キー | 動作 |
|---|---|
| `P` | 一時停止と再開を切り替える |
| `.` | 一時停止中に、シムを1ステップ（1/60秒）進める |
| `S` | 1/4 の速さと通常の速さを切り替える |

- あわせて、各ユニットの上に今のモーション名とコマ番号（例: `attack 2`）を出す
- アニメの時計はシム時刻（`battle.time`）なので、シムを止めればアニメも止まる。スロー再生は、1フレームあたりのシムの進め方を減らして実現する
- 時間の進め方の計算（通常・1/4・一時停止・1ステップ送り）は純粋関数に切り出してテストする。キー入力と表示は描画側に置き、CDP で確かめる

## 5. 移動と戦闘

### 5.1 敵と味方の最小距離

今は、敵が相手の位置そのものを目的地にして追う。交戦が成立すると止まるが、1体の相手と交戦できるのは1体までなので、
2体目の敵は交戦できないまま相手の位置まで歩いてきて重なる。味方も、移動の指示を受けると敵をすり抜ける。

**変更:** 敵と味方のあいだに最小距離 `MIN_SEPARATION = 24` を設ける（`src/core/constants.ts`）。
近接の射程（24）と同じ値にして、最小距離まで近づけば近接攻撃が届くようにする。

`moveTowardGoal` で求めた1ステップぶんの移動を、次のように補正する。

1. 移動後の位置で、最小距離より内側に入る敵対ユニットを集める
2. それぞれについて、移動のうち相手へ近づく向きの成分を取り除く（相手の横をすべるように回り込む）
3. 補正した結果がまだ最小距離より内側に入る、または歩けないマスに入るなら、その tick は動かない

- すでに最小距離より内側にいる場合（必殺技「かけぬける」の着地点など）は、相手から離れる向きの移動だけを許す
- 「かけぬける」の移動（`skills.ts` の `self.pos = dest`）は最小距離の対象外にする。敵を突き抜ける技なので
- 判定の相手は、敵対していて、`retired` でなく `hp > 0` のユニット（`hostilesOf` と同じ）
- 補正は純粋関数に切り出してテストする

**既知の挙動:** 1体の相手と交戦できるのは1体までというルールは変えない。
なので2体目の敵は、24px 手前で止まって攻撃せずに待つ。今も2体目は攻撃しないので、重なって待っていたのが手前で待つようになるだけである。

### 5.2 近接の自動の詰め寄り

**変更:** 次の条件をすべて満たす味方は、2マス（`AUTO_CLOSE_RANGE = 64`）以内にいる最寄りの敵へ自動で近づく。

- プレイヤーが操作するユニットで、攻撃種別が近接（`melee`）で、攻撃できる（`combat`）
- 移動の指示を受けていない（`goalPos === null`）
- 誰とも交戦していない
- 相手が見通せる（`hasLineOfSight`）。壁や障害物の向こうの敵には反応しない
- 相手が、ほかのユニットの交戦相手になっていない（交戦を始められない相手へ近づいても攻撃できないため）

仕組み:

- `Unit` に、詰め寄っている相手の uid（`closingOn`）を足す。`goalPos` は使わない。
  `goalPos` を使うと、プレイヤーが出した移動指示（`hasOrderedMove`）と区別できなくなる
- 詰め寄り中は相手の位置へ直進する。最小距離（§5.1）で止まり、そこで交戦が成立する
- 交戦が成立したら、移動の指示を受けたら、相手が倒れたら、相手が 64px より遠くへ離れたら、`closingOn` を消す
- 敵を倒したあとは、元の位置へ戻らない。その場に留まる
- 詰め寄る相手を決める処理は純粋関数に切り出してテストする

### 5.3 歩けない場所のタップ

今は `applyCommands` が、歩けない場所への移動指示を黙って捨てる。

**変更:** 移動先が歩けない場所なら、そのユニットがたどり着けるマスのうち、タップした点に最も近いマスの中心へ置き換える。

- たどり着けるマスは、ユニットの位置を起点にしたフローフィールド（`computeFlowField`）で距離が -1 でないマスとする。
  障害物に囲まれた閉じた区画は選ばない
- 近さはタップした点からマスの中心までの直線距離で比べる。同じ距離なら、フローフィールドの距離が短いマスを選ぶ
- マップの外（左右の余白など）をタップした場合も同じ扱いにする
- 対象は戦闘中の移動指示だけ。配置フェーズの配置先や、必殺技の目標地点は変えない
- 置き換えの計算は `src/core/field.ts` に純粋関数として置き、テストする

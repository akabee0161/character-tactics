# Modal で生成する Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude がこのサーバーから Modal の T4 で顔・全身の候補を作り、決まりで外せる候補を道具で外して候補のページを作り、選ばれた絵を今の採用・取り込み・書き出しの流れに載せられるようにする。

**Architecture:** `illust-asset-forge/` に、GPU も Modal も要らない純粋な部品（置き場・ジョブ・外す道具・候補のページ）と、Modal の入口 1 つ（`modal_app.py`）と、Claude が叩く CLI（`cloud.py`）を足す。Modal の上では今の `load_pipeline()`・`attach()`・`Forge.generate` をそのまま動かし、できた PNG（条件入り）をバイトで返してこのサーバーの `local/runs/` に置く。

**Tech Stack:** Python（このサーバーの venv は 3.14、Modal のイメージは 3.12）、Modal、diffusers、Pillow、pytest。

**Spec:** `docs/superpowers/specs/2026-11-23-modal-gen-design.md`

## Global Constraints

- 作業はすべて `illust-asset-forge/`（このリポジトリの forge のコピー）の中。コマンドは `cd illust-asset-forge` してから
- GPU は Modal の `"T4"` だけ。別の GPU への切り替え（GPU の一覧・fallback）は書かない。条件の `gpu` が `Tesla T4` でなければ生成せずに止める
- Modal のイメージの版: torch `2.14.1`（cu130 の wheel）・diffusers `0.42.1`・transformers `5.22.2`・accelerate `1.15.0`・safetensors `0.8.0`（`requirements-colab.txt` と PNG の条件の値）
- `modal`・`torch`・`diffusers` は `modal_app.py` の中（`torch`・`diffusers` は関数の中）でだけ import する。ほかのモジュールとテストは、それらが無くても動く（`illust-asset-forge/CLAUDE.md`）
- 候補・採用した絵は `illust-asset-forge/local/` に置き、リポジトリに入れない（`.gitignore`）
- Colab の道（`notebooks/run.ipynb`・`attach()`・`DEFAULT_BASE_DIR`・`tests/test_notebook.py`）は変えない
- 設定の誤りは `ConfigError` で、`<相対パス>: <キーの位置>: <何がおかしいか>` の形で止める（CLAUDE.md）
- 画風の引数（`style`）はジョブに付けない
- コミットは Conventional Commits + 日本語の要約
- テスト: `.venv/bin/pytest`（GPU・Modal なし）

## Review Focus

1. ジョブのファイルの誤り（無いキャラクター・`n` と `seeds` の両方が無い・知らないキー）は、Modal を起動する前（料金がかかる前）に、どのジョブのどのキーかを言って止まる → Task 2 のテスト
2. `local/selected/` には前に採用した別のキャラクターも残る。取り込みで、頼んだキャラクター以外の `source/` を古い採用で上書きしない → Task 4 のテスト
3. 依頼者が、道具が外した候補の番号をわざと選ぶ（「外しすぎ」に気付いたとき）。採用はでき、外した理由を警告として出す → Task 4 のテスト
4. 全身絵や無い番号に「左右反転して採用」を頼む。トレースバックでなく、理由の 1 行で止まる → Task 4 のテスト
5. 未コミットの変更がある状態で生成した絵は、条件の `commit` で見分けられる（あとで同じ設定から作り直せるかの手がかり） → Task 1 のテスト

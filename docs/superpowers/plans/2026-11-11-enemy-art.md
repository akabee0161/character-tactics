# 敵の絵 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ゲームの敵（ならず者・盾持ち・弓兵・まじない師）の仮の絵を、forge の部品から組んだ絵に置き換え、同じ種類の敵が複数の見た目で出るようにする。

**Architecture:** 敵の定義を見た目ごとに別の ID で持ち（強さの数値は同じ）、任意の `kind` 項目で「種類」を束ねる。初対面の会話の判定とセリフの鍵だけ `kind` で見る（エンジンの変更はここだけ）。絵は forge の `compose` → `enemy_build` → `export.py` の既存の流れで作る。新しい組み合わせ（盾持ち・弓兵・まじない師の 8 体）だけ新しく組む。

**Tech Stack:** TypeScript（Vitest）、Python 3.14（forge の `.venv`。`pixel-asset-forge/.venv/bin/python`）、JSON。

**Spec:** `docs/superpowers/specs/2026-11-11-enemy-art-design.md`

## Global Constraints

- 範囲外（触らない）: 顔グラ（`*-face.png`）・役割アイコン（`role-teki*.png`）、味方（`assets/units/*`）、ガルム（`assets/enemies/garum.json`・`garum-map.png`）、説得で仲間になる相手（`assets/enemies/ally06-foe.json`・`ally08-foe.json`・`ally06-map.png`・`ally08-map.png`）、敵の強さ（`maxHp`・`power`・`guard`・`attack`・`range`・`attackInterval`・`speed`・`xpReward`・`bowDamageCap`・`fleeAtHpRatio`）、敵の配置の位置・数・AI、ステージのタイル
- 敵のシートは 32px のコマ・4 列 × 12 行（128×384）。待機 2 コマ 4fps・歩き 4 コマ 8fps・攻撃 3 コマ 6fps（`frames`/`fps` は今の JSON と同じ）。攻撃の 3 コマは `[atk_wind, atk_hit, base]`
- 時間湧き（`spawners`）の `defId` は変えない（見た目は 1 つ）
- 道具（`unit_rules.py`・`compose.py --check` など）で落ちたら、道具に従って絵を直す。直してよいか、判定を変えてよいかを依頼者に途中で聞かない（`CLAUDE.md`「ドット絵の確認の道具」）。ISSUES.md に記録済みの原因で落ちたときは、絵を変えず ISSUES.md に記録する
- ユニットの部品は完全な単品で描く。欠けは部品に描き足す（重ねた後の後処理で補わない）。承認済みの重なり順（ロランの盾・イネスの弓・ミストの杖）を変えない
- コミットは Conventional Commits + 日本語の要約。push・PR は依頼者に頼まれるまでしない
- Python は `pixel-asset-forge/.venv/bin/python`。スクリプトはリテラルのパスで呼ぶ。変数展開（`S=...; bash $S/...`）と標準入力を使う heredoc（`python3 - <<'EOF'`）は安全フックに止められるので使わない（スクリプトは Write ツールでファイルに書く）
- `node tools/gen-placeholder-sprites.mjs` を引数なしで動かさない
- 作業用の一時ファイルは、`.superpowers/sdd/2026-11-11-enemy-art/`（git 管理外）に置く

## Review Focus

- `kind` を書かない敵（ガルム・説得の相手・味方）は、今までどおり `id` で初対面を判定する（Task 1 のテストで固定）
- `kind` が同じで `id` が違う敵 2 体と順に戦っても、初対面の会話は 1 回しか出ない（Task 1）
- 同じ種類の定義が、`id`・`sprites.map.sheet` 以外で食い違わない（強さの数値の写し間違い。Task 7 のテスト）
- 見た目を混ぜたステージで、同じ種類の敵が 1 つの見た目に偏らない（Task 8 のテスト）
- `npm run balance` の結果が置き換えの前後でぴったり一致する（Task 9）

## 順序

変形を先にやる。`tilemap.py` の実験で使うフィクスチャを作るときに、
変形が入っていると生成が楽になるため。

### 第1段: グリッドの決定的変形

| # | 内容 |
|---|---|
| 1 | `gridfile.py` に変形関数5種（`mirror_x` / `mirror_y` / `rotate_180` / `rotate_cw` / `rotate_ccw`）を足す |
| 2 | `parse()` が `# from:` と `# transform:` を解決する。由来元のヘッダを継承し、循環と深さ超過を `GridError` にする |
| 3 | 移行前の `river_{nw,se,sw}` の PNG を退避する |
| 4 | 3ファイルを派生ファイルに置き換える |
| 5 | **PNG がピクセル単位で一致することを確認する**。一致しなければ変形が誤り |
| 6 | テスト |

### 第2段: `tools/tilemap.py`

| # | 内容 |
|---|---|
| 7 | `--repeat NAME [--grid RxC]` / `--layout FILE` / 引数なしで `tile` 型全件を 3x3 |

| 9 | 継ぎ目チェックを実装し、**真陽性（壊れた川）と偽陽性（現行12枚）を測る** |
| 10 | 分離できるしきい値があれば採用、無ければ**機能ごと削除**して経緯を仕様に残す |
| 11 | テスト |

## テストで固定すること

**変形**

1. 5種それぞれが既知の小さなグリッドを正しく変形する
2. `rotate_cw` / `rotate_ccw` で寸法が入れ替わる
3. 由来元のヘッダを継承する。明示すれば上書きされる
4. 自己参照と循環が `GridError` になる
5. 存在しない `from` が `GridError` になる
6. **`river_nw` を解決した結果が、`river_ne` を左右反転したものと一致する**

**tilemap**

7. `--repeat` の出力サイズが `タイル寸法 × グリッド × 拡大率` になる
8. レイアウトの `.` が空セルになる
9. 継ぎ目チェックを採用した場合、壊れた川で発火し現行タイルで発火しない

## 想定される失敗

- **継ぎ目チェックが `plain` で誤爆する。** 草の房がランダムに散っているため、
  継ぎ目付近の行差分がたまたま中央値を超える可能性がある。その場合はしきい値では
  救わず、機能を落とす
- **PNG が一致しない。** 私の生成スクリプトのミラーと `gridfile` のミラーで
  軸の取り方がずれている場合。仕様どおりなら `river_sw` は `rotate_180`

## やらないこと

- `offset` とパレットサイクル（アニメーション機能が無い）
- 光源整合性の検査
- `knight` の瞳孔の修正（未確定項目のまま）

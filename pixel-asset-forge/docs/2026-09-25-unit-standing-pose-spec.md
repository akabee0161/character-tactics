# `unit` 立ち絵4方向 — 体の向きと持ち物の規約（仕様）

作成: 2026-09-25。**このファイルは作成時点のログ**。運用の最新は `README.md` と `CLAUDE.md` を見ること。

## 背景

`unit` 型の最初の1体（ロラン、2026-09-21 にマージ済み）の立ち絵に、依頼者から違和感の指摘があった。
点検したところ、指摘と同じ原因から来るものが他にもあった。

依頼者の指摘:

1. 横顔の鼻が不自然に長く、マリオのような顔に見える
2. 後ろを向いたとき、剣と盾が体に隠れていない
3. 横を向いたときも剣と盾が左右に並んでいる。体の横にあるのだから、横を向いたら手前と奥に見えるはず

点検で見つかったもの:

4. `right_base` が `left_base` の `mirror_x` 派生なので、**光源が反転している**。ヘッダは
   `# light: upper-left` を継承するが、実物のハイライトは右上にある。CLAUDE.md が
   「変形は光源を一緒に動かす。川は使えるが、顔グラや城には使えない」としているケースに該当する。
   ただしこれは見落としではない。`types/unit/SPEC.md` に「光源と盾の腕も一緒に反転するが、
   依頼者の判断で採用している」と記録された**既知の判断**であり、本仕様はこの判断を撤回する（5節）
5. 同じ絵の中で奥行きの扱いが矛盾している。`left_base` の足は手前を `cloth_base`、
   奥を `cloth_shadow` で描き分けているのに、腕と装備は左右に並べている
6. 盾が4方向とも同じ幅4pxの縦長長方形で、横向きでも形が変わらない
7. `down` と `up` のシルエットがほぼ同一で、方向の判別を顔の有無だけに頼っている

**2・3・5・6・7の共通原因は「装備と腕に奥行きが無いこと」である。** 足だけが既に正しく前後を
描き分けており、同じ考え方が上半身に適用されていない。

残る2件は原因が別である。1（鼻）は顔の造作の問題で、6節で扱う。4（光源の反転）は mirror の
使い方の問題だが、奥行きを直すと `left` と `right` が別の絵になって mirror が使えなくなるため、
結果として一緒に解消する（5節）。

## この作業のゴール

**ロラン1体を直すことではない。立ち絵4方向の規約を決めて、他の8体に適用できる形で残すこと。**

依頼者の指定は次の3点。

1. 絵柄（パレット・頭身・服装）は変えない。直すのは体の向きと物の持ち方
2. 動き（`walk` / `attack`）より先に、**立ち絵の上下左右を確定させる**
3. 将来、ユニット作成の指示をパラメータ化したい。性別、右手／左手に何を持つか、
   持ち物のイメージ（`item` として事前に作っておく）を指定すれば、一定の品質で作れる状態にする

したがって成果物は「ロランの絵4枚」ではなく「**規約と、それに従った実例1体**」である。

## 1. 持ち物の割り当て

**右手に剣、左手に盾。** 現状は逆（右手に盾・左手に剣）で、剣士としては左利きの構成だった。
今回4方向とも描き直すので追加コストはほぼ無く、他の unit の手本としても標準的な構成にする。

## 2. 4方向の幾何

| 方向 | 体 | 右手（剣） | 左手（盾） |
|---|---|---|---|
| `down` | 正面 | 画面**左**・手前・全体が見える | 画面**右**・手前・全体が見える |
| `up` | 背面 | 画面**右**・奥 | 画面**左**・奥 |
| `left` | 左向き | **奥**（体の向こう） | **手前**（カメラ側） |
| `right` | 右向き | **手前**（カメラ側） | **奥**（体の向こう） |

`down` と `up` で画面上の左右が入れ替わるのは、キャラクター視点では同じ手だからである
（背面では観測者とキャラクターが同じ方向を向く）。この原理は現行の絵でも守られており、変えない。
ただし1節で持ち手を入れ替えるので、画面上の剣と盾の位置は現行と左右逆になる。

## 3. 奥にあるものの描き方

**体に重なる部分は描かない。輪郭からはみ出す部分だけを `*_shadow` 系の暗い色で描く。**

これは `left_base` の足で既に使われている描き分けを、腕と装備にも適用するということである。
「全体を見せて暗くするだけ」は採らない。体を貫通して見えることになるため。

奥を暗く描くと、現行のロランには無い色の隣接が生じる（例: 今は使っていない `stone_shadow` が
`cloth_shadow` や `outline` と接する）。CLAUDE.md の規約どおり、**描く前に
`tools/probe_colors.py` で隣り合う予定のペアを測る**。暗い色どうしが潰れて、はみ出しが
輪郭の一部に見えるのを避けるためである。

## 4. 横向きでの装備の形

盾は腕に装着して正面を守るものなので、**横から見ると薄い板の側面になる**。
剣も下げた状態では刃の側面しか見えない。したがって `left` / `right` では盾・剣とも幅を大きく削る。
4方向とも同じ幅の縦長長方形で描く現状は誤りである。

この結果、`left` と `right` は別の絵になる。

- `left` = 薄い盾が手前に見え、剣はほぼ体に隠れて一部が暗く覗く
- `right` = 剣が手前に見え、盾はほぼ体に隠れて縁が暗く覗く

## 5. `unit` に mirror を使わない

4節のとおり `left` と `right` は手前と奥が入れ替わるため、**`mirror_x` では原理的に作れない**。
4方向すべてを本体グリッドとして持つ。これは背景4（光源の反転）の解消も兼ねる。

`# from:` / `# transform:` の仕組み自体は `tile` で有効に使われているので残す。
使わないのは `unit` 型に限った規約である。

`types/unit/SPEC.md` の「右向きは左向きからの `mirror_x` 派生にしてよい。光源と盾の腕も一緒に
反転するが、依頼者の判断で採用している」の段落は削除し、本規約に置き換える。

**経過措置:** 今回描き直すのは `base` の4枚だけなので（9節）、`right_breathe` / `right_walk_a` /
`right_walk_b` / `right_atk_wind` / `right_atk_hit` の5枚は `mirror_x` 派生のまま残る。
この5枚は規約の例外として `ISSUES.md` に記録し、`breathe` / `walk` / `attack` を本仕様で
描き直すときに本体グリッドへ置き換える。

## 6. 顔の造作

現状の横顔が破綻している原因は2つある。

- **顔の内部に `outline` 色の線が入っている。** 32px では「顔を横切る線」として目立つ。
  正面向きでは `outline` は目にしか使われていないのに、横顔では鼻筋の線に使われていた
- **顔の突出が縦2行に渡っている。** 「鼻の出っ張り」ではなく「顔面全体の前方への張り出し」になる

規約:

- **顔の内部に `outline` 色を使わない。** 造作は `skin_hi` / `skin_base` / `skin_shadow` の
  階調だけで示す。例外は目のみ（正面向きは1px の点2つ、横顔は1px の点1つ）
- **横顔の鼻は1行だけ、1px。** その行だけ顔の前端を髪の輪郭より1px出し、上下の行は輪郭と揃える
- **横顔の目は `outline` 色の1px の点1つ。** 両目を描かない
- **口は描かない。** 32px では顎の階調に潰れる
- 顔の縦位置は4方向で揃える

正面向き（`down`）は現状でもこの規約を満たしている。変更は横顔のみ。

## 7. 素体の分離

装備を持たない**素体**を4方向ぶん持ち、複製して使う土台にする。

```
types/unit/base/male_{down,up,left,right}.txt   素体（複製して使う土台）
assets/unit/roran/{down,up,left,right}_base.txt 完成品
```

| | |
|---|---|
| 素体に含める | プロポーション（背丈26px＝5〜30行目・輪郭込み、足元 y=30）、4方向の体の向きとシルエット、腕と手の位置、光源 upper-left に沿った基本の陰影、足と腕の手前／奥の描き分け。色は `outline`、肌の3階調（`skin_hi` / `skin_base` / `skin_shadow`）、服の3階調（`cloth_hi` / `cloth_base` / `cloth_shadow`）まで |
| 素体に含めない | 髪型、顔の造作、服のデザインと配色、装備 |

**作る順序を逆にする。** 素体を先に設計しても、それが使えるかは2体目を作るまで分からない。
先にロランの4方向を本仕様で描き、**完成した絵から装備・髪・顔を取り除いて素体として抽出する**。
実際に成立した絵から取るので、机上で設計した素体より確実である。

**`types/unit/base/` は、現状ではツールの既定の対象に入らない。** `validate.py` の
`default_targets()` は `assets/` と `types/*/reference` しか見ておらず、`render.py` /
`check_colors.py` / `contact_sheet.py` も同じ関数を import して使っている。このままでは
素体が検査も描画もされない。**`default_targets()` に `types/*/base` を加える**。`tools/` の
変更なので、テストを足して unittest を通す。

## 8. `types/unit/reference/` を廃止する

現在の `reference/` は `assets/unit/roran/` のコピーで（`down` / `up` / `left` は行が完全に同じ。
`right` は mirror 派生を展開したもの）、片方を直すともう片方とずれる（`ISSUES.md` の既知課題）。
素体を分離するなら二重管理の必要は無い。

**手本は `assets/unit/roran/` を直接見る**に変更し、`CLAUDE.md`・`README.md`・`types/unit/SPEC.md`
の文言を合わせる。`contact_sheet.py` が `reference/` を拾って unit を28点（24＋4）と
重複表示している問題も、これで解消する。

## 9. 対象範囲

**今回やること:**

- ロランの `{down,up,left,right}_base.txt` の4枚を本仕様で描き直す（`right_base` は本体グリッドにする）
- 完成した4枚から素体を抽出して `types/unit/base/` に置く
- `validate.py` の `default_targets()` に `types/*/base` を加え、テストを足す（7節）
- `types/unit/SPEC.md` に本仕様の規約を反映する（mirror を許していた段落は削除する。5節）
- `types/unit/reference/` を廃止し、`CLAUDE.md` と `README.md` の文言を更新する
- `ISSUES.md` を更新する。解消した項目（reference のコピー）を消し、次を足す
  - `right_*` の5枚が `mirror_x` 派生のまま残っている（5節の経過措置）
  - `breathe` / `walk` / `attack` が新しい `base` と不整合（11節）

**今回やらないこと:**

- `base` 以外の20コマ（4方向 × `breathe` / `walk_a` / `walk_b` / `atk_wind` / `atk_hit`）。
  立ち絵の確定が先（依頼者の指定2）
- 女性素体。今回は `male` のみ
- `item` のカタログ作成とパラメータ化の実装
- 剣が `stone_*` / 盾が `metal_*` というパレット命名と見た目の不一致。`ISSUES.md` に残す（依頼者の指定）

## 10. 将来のパラメータ化（今回は定義のみ）

依頼者の目標は「パラメータを指定すれば一定の品質で unit を作れる」状態である。
最終形は **持ち物を `item` として先に作っておき、それをパラメータとして指定する**形。

| パラメータ | 内容 | 今回 |
|---|---|---|
| `gender` | 素体の選択 | `male` のみ作成 |
| `right_hand` / `left_hand` | 持ち物。`item` 型のアセットを手本に unit へ描き込む | ロランは剣／盾 |

`item` は現在1点しか無いため、カタログの整備が別途必要になる。

## 11. 既知のリスク

- **`base` だけ直すと、他の20コマと不整合になる。** `idle` は `[base, breathe]`、`walk` と
  `attack` も `base` を挟むので、シート上では新旧の絵が交互に出る。立ち絵を確定させてから
  20コマに同じ規約を適用するまで、この状態は続く
- **素体の汎用性は2体目を作るまで検証されない。** 今回は抽出するだけで、使えるかは次のunitで分かる。
  足りなければ直す前提で置く
- **縮小表示での見え方は考慮しない（依頼者の指定）。** character-tactics が canvas を 0.796倍で
  描いて 1〜2px の線が消えた件は、ゲーム側で倍率が掛からないよう修正する予定の**経過的な課題**で、
  いずれ縮小されなくなる。横向きの薄い盾・剣も、ドット絵単体としての品質で幅を決める

## 12. 検証

| 段階 | 方法 |
|---|---|
| 描く前 | 新しく隣り合う色のペアを `tools/probe_colors.py` で測る（3節） |
| 構造 | `tools/validate.py`（素体も対象に入っていること。7節） |
| 色 | `tools/check_colors.py`（`knight` の既知 failure 以外が出ないこと） |
| 1枚ずつ | `tools/render.py` の `_x8.png` |
| 4方向の整合 | `tools/sheet.py` のプレビューで4方向を並べ、奥行きの扱いが揃っているかを見る |

背景1〜7の欠陥は、いずれも `validate.py` と `check_colors.py` を通過していた。
**4方向を並べて初めて見える**という点で、`tile` の「並べないと見えない」欠陥と同じ構造である。
機械チェックは追加しない（`docs/2026-09-23-findings.md` の「深いチェックを試して2回落としている」）。

CLAUDE.md は `unit` に「ゲームに入れて動かす」確認を求めているが、今回は行わない（依頼者の指定）。
ゲーム内確認の主目的だった 0.796倍の縮小は、経過的な課題である（11節）。

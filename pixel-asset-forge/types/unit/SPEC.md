# unit 型

タイル上を動くキャラクターのスプライトシート。
[character-tactics](https://github.com/akabee0161/character-tactics) のマップスプライトに
差し込む前提。絵柄は本文ではなく手本（`assets/unit/roran/`）で揃えること。以下は機械的な規約のみを書く。

設計の経緯は `docs/2026-09-20-unit-sprite-sheet-spec.md`、
ロラン1体で測った実測は `docs/2026-09-23-findings.md`、
立ち絵4方向の規約の経緯は `docs/2026-09-25-unit-standing-pose-spec.md`。

## 確定している規約

| 項目 | 値 |
|---|---|
| 解像度 | 32x32（ゲーム側 `frame = 32` に合わせる） |
| 背景 | `bg: transparent` |
| 光源 | `# light: upper-left`（タイルと同じ） |
| 構図 | **足元 y=30、左右中央、背丈 24〜26px** |
| 絵柄 | `face` の流儀（全周1pxの輪郭・髪4階調）は**持ち込まない**。全身32pxでは顔が3〜4pxしか取れない |
| 並び | 12行 = 3状態 × 4方向。行 0-3 `idle` / 4-7 `walk` / 8-11 `attack`、各ブロック内は down, up, left, right。ゲーム側が `row = state_index * 4 + direction_index` で読むので、順番は変えられない |
| コマ | `idle` 2 / `walk` 4 / `attack` 3（弓のユニットは `attack` 6）。列数は最大コマ数に揃え、余りは透明 |
| 構成 | `walk` は `[base, walk_a, base, walk_b]`、`attack` は `[atk_wind, atk_hit, base]`。中間と戻りは `base` の流用。弓のユニットの `attack` は `[atk_wind, atk_draw, atk_hit, atk_hit, atk_hit, atk_release]`（下の「弓の持ち方」） |
| 色 | `palette/master.json` を使う。色を足すときは描く前に `probe_colors.py` で草・道・床の色に対して測る |

## ファイル配置

```
assets/unit/<unit>/<frame>.txt    コマの本体
sheets/<unit>.txt                 シート定義（どのコマをどこに置くか）
build/sheets/<unit>.png           ゲームに渡すシート
build/sheets/<unit>_preview.png   目視用のプレビュー
types/unit/base/<body>_<dir>.txt  素体（装備・髪・顔の造作なし）。新しい unit を複製して作る土台
```

**シート定義を `assets/` の下に置いてはいけない。** `validate.py` と `render.py` は
`assets/` 以下の `*.txt` を全部 `rglob` するので、定義をグリッドとして解釈して落ちる。
`layouts/` がトップレベルにあるのと同じ理由である（この穴は実際に踏んだ）。

## 立ち絵4方向の規約

決めた経緯は `docs/2026-09-25-unit-standing-pose-spec.md`。ただし下の3点は、実装中に依頼者の判断で
仕様書から変わった（仕様書は作成時点のログなので直していない。こちらが正）。

- 奥の物をはみ出し部分だけ `*_shadow` 系で暗く描く → **色は手前と同じ**（向きで装備の色が変わると別の装備に見える）
- 横顔の鼻を1行だけ1px出す → **顔の前面は平ら**（鼻を出すと不自然に見えた）
- 剣を下げて持つ → **剣は立てて構える**（下げると戦う姿勢に見えない）

規約:

- **持ち物の標準は右手に剣、左手に盾。** 剣は刃を上に向けて立てて構える。切っ先は頭頂（y=5）より上に出さず、背丈26pxの範囲に収める
- 4方向で手の前後を次のとおりにする

  | 方向 | 右手 | 左手 |
  |---|---|---|
  | `down` | 画面左・手前 | 画面右・手前 |
  | `up` | 画面右・奥 | 画面左・奥 |
  | `left` | 奥 | 手前 |
  | `right` | 手前 | 奥 |

- **奥にあるものは、体に重なる部分を描かない。** 輪郭からはみ出す部分だけを描く。
  **色は手前と同じ階調を光源の向きに従って付ける**（奥だからといって暗くしない）
- **横向きでは盾の幅を大きく削る。** 盾は薄い板の側面（金属1px）になる。
  立てて構えた剣の刃は、横向きでも正面と同じ幅（ロランは2px）で読めた
- **持ち物を持つ手を描く。** 背面で盾の縁だけが見えるときも、盾を握る拳を重ねる（無いと盾が浮いて見えた）
- **`unit` に mirror を使わない。** `left` と `right` は手前と奥が入れ替わるので、反転では作れない。
  光源も反転してしまう
- **顔:** 顔の内部に `outline` を使わない（例外は目）。目は `outline` で縦長に描く。正面は2つ、横顔は1つ。
  ロランは縦2px・幅1px（issue #23、2026-10-01 依頼者の判断。元は1pxの点）。
  横顔の前面は平らにし、鼻を出さない。口は描かない。目の上端の行は4方向で揃える（ロランは y = 11）
- 奥の装備や手に新しい色を当てるときは、描く前に `probe_colors.py` で体の色と測る
- **剣は item の剣（`assets/item/sword.txt`）に色を揃える。** 画素は写さず、素材の色を合わせる（issue #23 の4番目、2026-10-02 依頼者の判断）。
  刃は `stone_hi`/`stone_base` の2px幅、鍔は木（`wood_hi`/`wood_base`/`wood_shadow`。横に4px。左向きの立ち・歩き・待機は端から見た2px、横向きの `atk_hit` は45°の刃に直角な斜めの2〜3画素）、
  柄頭は赤い宝石（`roof_base` の1画素）。盾は金（`metal_*`）のままなので、剣と盾の色は分かれる
- **切っ先は平らな蓋のまま。** 刃の上を輪郭2画素で閉じる。白い刃は長方形でも、上の輪郭で先がある程度尖って見える。
  2px幅では左右対称に尖らせられず、片側の列を1段下げる案も試したが採らなかった（issue #23 の4番目、2026-10-03 依頼者の判断）
- **持ち物の部品には専用の文字を割り当てる。** 同じ色の別の部品（例: 金の鍔と金の盾）と同じ文字にすると、`# map:` 行で片方だけ色を変えられない。
  専用の文字の割り当ては1行の `# map:` にまとめる。ロランは鍔 `G`・`H`・`J`、柄頭 `R`（2026-10-03 依頼者の判断）

### 弓の持ち方（イネス、issue #23 の5番目）

弓のユニットの標準。手本は `assets/unit/ines/`。決めた経緯は character-tactics の `docs/superpowers/specs/2026-10-03-ines-unit-bow-design.md`。

- **左手で弓、右手で矢。** 待機では、右手で弦にかけた矢を弓と交差させ、今にも引ける構えで待つ（引き絞らない）。剣と盾のように別々に持たない
- 手の前後は上の表のとおり（左手の弓は `down` で画面右・手前）
- **弓は縦に立て、弧を矢の向く側へ膨らませる。** 弦は弓の両端を結ぶ縦の1px。矢は水平にして、弓の握りのすぐ上を通す。弓の長さは15行（イネスは y=14〜28）
  - `down`: 弓は体の右側（画面右）。弦 x=17、弧の頂点 x=21（y=20〜22）。左手の拳（x=20〜21、y=20〜21）が握りを覆う。
    右手は体の前へ回して弦の上で矢の尾をつまむ（拳 x=15〜16、y=19〜20。前腕が胴の前を y=19 で横切る）。矢は y=19 の x=17〜22、鏃 x=23〜24
  - `left`: 弓は顔の前（画面左）。弦 x=10、弧の頂点 x=6。手前の左腕を前へ伸ばして握りを持つ（腕 y=19 の x=8〜12、拳 x=6〜7・y=19〜20）。
    奥の右手が弦をつまむ（x=10〜11、y=17〜18）。矢は y=18 の x=4〜9、鏃 x=2〜3
  - `right`: `left` と左右を入れ替えた位置（弦 x=21、弧の頂点 x=25、矢 y=18 の x=22〜27、鏃 x=28〜29）。手前は矢を持つ右手（x=20〜21、y=17〜18）、
    奥は弓を握る左手（腕 y=19 の x=19〜23、拳 x=24〜25・y=19〜20）。色は光源に合わせて付け直す（mirror は使わない）
  - `up`: 弓・矢・両手は体の向こう側。体からはみ出す部分だけを描く（画面左に弓の外側の弧・左手の拳・矢の先と鏃、画面右に矢を引く右腕の肘）
- **弦は体の上を通るところに輪郭を付けない。** 1px の線のまま体の上に描く（輪郭を付けると3px の暗い線になる）。透明な背景の上では輪郭で囲む
- 色はアイコンの弓（`assets/item/bow.txt`）に揃える: 弓の本体は `wood_*`、弦は `stone_hi`、鏃は `stone_base`、矢の軸は `wood_shadow`、矢羽根は `water_base`。画素は写さない。
  イネスの待機では矢羽根は右手の拳に隠れる
- 専用の文字: 弓 `k` `l` `m`（イネスは `l` だけを使う）、弦 `s`、鏃 `t`、矢の軸 `w`、矢羽根 `u`。
  矢の軸と弓の暗い面とズボンは同じ `wood_shadow` だが、攻撃のコマで矢だけを扱うために別の文字にする
- **待機の2コマ目（`breathe`）は、矢を持つ手を引く。** 上下には動かさない（弓は引いて打つので）。弓・左手・頭・胴・脚は `base` のまま。
  イネスは右手と矢を体の側へ2px 引き（矢は長さを変えずに一緒に動く）、弦は矢の尾の行で折れる。
  `down` は肩と肘も1px 外へ出す（腕を広げるのではなく、肩・肘・手が一緒に動く）。`up` は見えている矢の先を2px 動かし、右腕の肘を1px 外へ出す
- **攻撃は 構える → 引き始め → 引き絞る ×3 → 放った後 の6コマ（イネスは 6fps）。** 描く絵は方向ごとに4枚（`atk_wind`・`atk_draw`・`atk_hit`・`atk_release`）。
  シート定義で `atk_hit` を3回並べて、引き絞るコマだけを他の3倍止める（タメ）。character-tactics は攻撃の最後のコマが出た瞬間に矢を出す
  （`windupOf` = (コマ数−1)/fps）ので、最後のコマに放った後の絵を置く。ロランのように `base` を流用すると、矢が飛ぶ瞬間に次の矢をつがえた絵になる。
  攻撃のコマ数はユニットの JSON（`attack.frames`）で決まり、シートの横幅は 32px × 一番多いコマ数になる（イネスは 192×384）
  - 放った後は矢（`w` `t` `u`）を描かず、弦は真っすぐに戻す
  - `down`: 弓を縦に持って、見る人の方（下）へ放つ。弓は真横から見た縦の線（体の右側の前、上端 y=13・下端 y=28）で、左手が真ん中の握りを持つ。
    右手が弦を引くと、弦は弓の上下の端から右手へ向かう「く」の字になる。矢は見る人の方へ向いて短く見えるので、右手（尾）から握りの左下の鏃への線で表す。
    右手は 構える (16,20) → 引き始め (14,18) → 引き絞る (12,16)（顔の横の下）と引き、放った後は (11,15) へ抜ける
  - `left`・`right`: 弓は縦のまま前へ向け、右手と矢を 構える1px → 引き始め3px → 引き絞る5px と体の側へ引き、放った後は6px。
    **奥の手・矢・弦は、体（輪郭を含む）に重なる画素を描かない**（`left` は矢を持つ右手が奥）
  - `up`: 矢は体の向こう側なので、鏃の2画素と軸の1画素だけを弓の前に見せる（放った後は描かない）。弓と弓を持つ左手は `base` から上へ4px・左へ1px（前へ構える。体との間は袖でつなぐ）。
    矢を引く右腕は形と左右の位置を変えず、引き絞る・放った後で1px 下げる（肘の位置は変わらず、肩が少し後ろへ下がる動き）。拳は見せない

## アニメの規約

決めた経緯は `docs/2026-09-26-unit-animation-frames-spec.md`（`breathe` は `docs/2026-09-28-issue6-forge-assets-spec.md`）。

- 立ち絵の規約をすべてのコマに適用する。`right_*` も本体グリッドにする
- **盾はどのコマでも `base` の位置から動かさない。** 動かすのは剣を持つ腕と脚だけ。
  手前の腕が奥の盾の前を通るときは、覆われる部分を隠してよい（ロランの `right_atk_hit`）
- `breathe`（待機の2コマ目）: 頭・胴・脚・盾は `base` のまま、剣を持つ拳を剣ごと（刃・鍔・柄頭）2px上げる（1pxではゲームで動きが見えにくかった。依頼者の判断）。
  拳が上がって空いたところは袖と腕を描き足してつなげる。刃の長さは変えない。
  `up` と `left` の剣は奥にあるので、体に重なる部分は描かない（立ち絵の規約）。
  頭を動かさないのは、依頼者の指摘「顔が動いているだけ。顔よりも手足を動かしたい」（GitHub #6）による
- **待機の2コマ目に限り、切っ先は頭頂（y=5）より2px上（y=3）に出てよい**
- `walk`: 上半身と剣は `base` のまま、脚（y=28〜30）だけを動かす
- **攻撃は振り下ろし。** `atk_wind` の刃は `base` と同じ長さ（ロランは11px）
  - `atk_wind`: 剣を持つ拳をあごの高さ（ロランは y=13〜14）まで上げ、刃を真上に立てる。
    拳を頭の高さまで上げると、刃を `base` と同じ長さに保ったまま y=0 に収まらない
  - `atk_hit`（issue #23、2026-10-01 依頼者の判断で書き直した。元は「刃を前下がりの斜めに、正面・背面は45°」）:
    - **剣は 柄頭→拳（柄）→鍔→刃 を1本の軸に並べ、鍔は刃に直角にする。** 傾けた刃に鍔と拳が合っていないと違和感が出た
    - **刃の長さは剣で決め、コマの空きで決めない。** 左右の向きで同じ長さにする（コマの端までの空きに刃を詰めて、左右で1px違えた）
    - 正面: 真っすぐ前へ振り下ろす。拳は `base` の位置から体の中心へ寄せ（ロランは3px、高さは `base` と同じ y=18〜19）、
      刃を真下に向ける（ロランは6行と切っ先）
    - 背面: 剣は体に隠れて見えない。前へ下ろした右腕の肘が脇から少しのぞく（ロランは x=20〜22・y=17〜19）
    - 横向き: 刃を前上がり45°にする（ロランは7行）。拳は体に寄せる。剣を持つ手が奥（`left`）のときは、
      拳・柄・鍔のうち盾や体に重なる部分を描かない。切っ先はコマの端の輪郭の手前まで（32px のコマでは
      水平の剣は収まらない。水平に近いほど違和感は少ないが、拳を前に出すと腕が伸び切って見える）
- **攻撃コマに限り、切っ先は頭頂（y=5）より上に出てよい**（y=0 まで）。構えの「頭頂より上に出さない」は立ち絵の規約

## 目視の手順

1コマの `_x8.png` だけでは終わらない。

1. 4方向の `base` を `contact_sheet.py` に渡して横に並べる（`--columns 4`）。
   奥行きの扱いのずれは、4方向を並べないと見えない。並びはファイル名順（down, left, right, up）になる
2. `tools/sheet.py sheets/<unit>.txt` のプレビュー。コマ境界線・**赤い足元ライン(y=30)**・
   青い中心線が重ねてある。アニメで一番出る欠陥は「コマ間で足元や体の中心が1pxずれて
   絵がガタつく」で、1コマの拡大画像を見ても分からない
3. **ゲームに入れて動かす。** character-tactics は canvas を 0.796倍で描いた実績があり、
   1〜2px の線は丸ごと消える（振りかぶりの剣が消えた）。整数倍で表示される保証は無い。
   **ただし 0.796倍は経過的な課題。** ゲーム側で倍率が掛からないよう修正する予定で、いずれ
   縮小されなくなる。縮小で消えることを理由に絵を変えず、ドット絵単体の品質で描く

`sheet.py` が出す足元・中心の実測表は助言のみ。横向きの `atk_hit` は剣を前へ出すので、
横向きの `atk_wind` は剣を頭の後ろに上げるので、外接矩形が広がって中心がずれ、`off` と出るのが仕様どおりである
（体は `base` と同じ位置にある）。正面・背面の `atk_hit` は剣が体の外へ出ないので `ok` になる（2026-10-02 実測）。
正面・背面で `off` が出たら、中心がずれている。

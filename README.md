# とりでの なかまたち (character-tactics)

仲間（記録は最大 15 人、場に出るのは 8 人まで）を率いて、敵の本拠地へ攻め込むリアルタイム侵攻シミュレーション。
[ankardo](https://ankardo.com) のサブリソースとして `ankardo.com/play/character-tactics/` で公開する。

- 設計: `docs/superpowers/specs/2026-09-06-map-sprite-animation-design.md`
- 実装計画: `docs/superpowers/plans/2026-09-07-map-sprite-animation.md`

## そうさ

| 操作 | 結果 |
|---|---|
| なかまをタップ | 選択する。もう一度タップで選択を外す |
| 下のポートレートをタップ | 戦闘中はそのなかまを選び、必殺技を出す。配置フェーズでは強さのカードを開く |
| なかまをドラッグして離す | 戦闘中はその地点へ移動 |
| 選択中に地面をタップ | 戦闘中はその地点へ移動 |

必殺技は下のポートレートをタップして出す。タップすると同時にそのなかまが選択される。クールダウン中・必殺技を持たない場合は選択だけになる。倒れているなかまはタップしても何も起きない（選択も変わらない）。いま出せるなかまのポートレートには太い縁がゆっくり明滅して付き、残り時間はポートレートのゲージで読める。配置フェーズでは同じ下パネルの上段に「始める」が出る。

ステージ選択の一覧は縦にドラッグしてスクロールする。指をほとんど動かさずに離すとそのステージを選ぶ。右端の細いバーで今どのあたりを見ているかが分かる。

### クリアの時間と評価

勝つと、クリアにかかった時間と、金・銀・銅の評価が出る。速くクリアすると記録が良くなる（経験値などの実利は無い）。

- 時間は戦闘の時計（`battle.time`）で測る。会話・カード・倒れたときの帯で止まっている間と、配置の場面は数えない。記録するのは勝ったときだけ（負けた回の時間は残さない）
- 画面には秒の端数を切り捨てて「48秒」「2分14秒」（秒は 0 埋めしない）と出す（`formatClearTime`、`src/ui/clear-time.ts`）
- 評価は、画面に出す秒（切り捨て）がステージの `parTimes`（金・銀・銅の目安の秒）以下かで決める（`rankFor`）。目安ちょうどを含む。銅より遅いときは評価を出さず、時間だけ出す。評価はセーブに書かず、時間と目安からその場で出すので、`parTimes` を直すと前の記録の評価も変わる
- 結果の画面: 見出しの下に「クリア 14秒 金」と「最高 14秒　記録更新！」（一番速い記録を縮めたとき、または初めてのクリアのとき）。ステージ選択: クリア済みで記録のある枠の左上に「金 8秒」
- セーブの `bestTimes`（ステージ ID → 一番速い秒、小数のまま）に、より速く勝ったときだけ書く。旧セーブ（この欄が無いもの）は記録なしで読み、壊れた項目だけ捨てる（`SAVE_VERSION` は上げない）
- 敵を残してゴールへ着いても勝ちなので、1 人でゴールへ走るのが一番速い。それを止めるため、ゴールの手前に敵の壁を置き、駆け抜ける・急降下の届く距離と再使用の時間を制限している（「難易度を測る」の突っ込み）

### 強さを見せる（カード）

仲間と敵の能力は「カード」で見る。カードは顔・名前・レベル（仲間も敵も。敵はそのステージの `enemyLevel`）・敵は出る数（レベルの下）・役割・攻撃の種類と届く距離・HP・攻撃力・守備・魔法防御・速さ（棒は全ユニット共通の上限 `BAR_MAX` に対する割合。レベル 30 の仲間と各ステージの敵が収まる値で、`stat-card.test.ts` が守る）・技の一言・特徴（飛行・斧・盾持ちの矢の上限）を出す。魔法で攻撃するユニット（`attack` が `magic`。仲間も敵も）は、攻撃力を「魔力」と書く（中身は同じ `power`。レベルアップのカードと結果の画面の「魔力+1」も同じ）。技の一言の `{damage}`・`{heal}` は、そのユニットの今の攻撃力（魔力）を足した値で出す（実際の量と同じ）。カードや一覧を重ねている間は、下の画面に入力が届かない（カードの外か「閉じる」で閉じる）。

- ステージ選択: 下の仲間一覧（15 人）の枠を押すと、その仲間のカード（セーブのレベルと能力の加算から出す）。各ステージの「敵を 見る」を押すとそのステージに出る敵の一覧（配置・時間湧き・説得の相手を名前ごとに数える）。行を押すと、そのステージの `enemyLevel` の能力で敵のカード、カードを閉じると一覧に戻る。まだ行けないステージには出ない
- 配置フェーズ: 下の段の顔の枠を押すと、その仲間のカード（今の値）。マップ上の敵を押すと、その敵のカード。マップ上の仲間を押したときは今どおり選ぶ・動かす。戦闘中はカードを開かない（顔の枠は必殺技）
- レベルアップ: 戦闘の途中で上がると戦闘を止め、「上がる前 → 上がった後」のカードを出す（上がった能力は金色。顔と名前の近くに、その仲間のレベルアップのセリフも出る。セリフが無い仲間は出ない。戦闘中のセリフ欄には出さない）。どこを押しても閉じ、同時に複数の仲間が上がったときは 1 人ずつ出す。同じ瞬間に村の会話・加入の会話が起きたときは、会話が先でカードがあと。勝利の会話はカードを出し終えてから。結果の画面の行には、そのステージで上がった能力を「HP+1」のように書き、行を押すとカードが開く
- バフの印: はげます（橙）・結界（水色）が効いている間、マップ上のユニットの HP バーの上と、下の段の顔の枠の下に、色分けした上三角を出す。何が上がっているかは色で見分ける（戦闘中はカードを開けないので詳細は出ない）

ステージを選ぶと、まず会話から始まる。タップで送り、文字送りの途中でタップすると全文が出る。一度読み終えたステージでは「とばす」が出る。会話はステージ開始時と、敵の本拠地に到達したときの2回ある。

### 村と説得

マップの村へ仲間を歩かせる（村のマスの 18px 外まで近づけば着いたことになる）と、村の種類に応じて次の6種類のどれかが起きる。村は一度訪れると暗くなり、そのステージの間はもう何も起きない。同じ村に複数の仲間が同時に着いたときは、並びで先の1人だけが訪れた扱いになる。

| 種類 | 起きること |
|---|---|
| `talk` | 村人との会話が出るだけ（効果は無い） |
| `heal` | 仲間全員のHPが全回復する |
| `powerUp` | 訪れた1人の攻撃力が、そのステージの間だけ上がる |
| `xp` | 訪れた1人に経験値が入る（一度きり） |
| `stat` | 訪れた1人の HP・攻撃・守り・速さのどれかが上がる。レベルアップしても残る（一度きり） |
| `recruit` | 加入の会話が始まり、新しい仲間が村に加わる |

村に着くと、種類によらず戦闘が止まり、村人と訪れた仲間の会話（`drawTalk`）が出る。最後の行は何が起きたかの説明。会話が終わると戦闘に戻る（`recruit` の村は村人との会話のあとに加入の会話が続く）。効果（回復など）は着いた瞬間に出ている。同じ瞬間にレベルアップが重なったときは、会話が先でカードがあと。村と加入（説得）が重なったときは村の会話 → 加入の会話 → カードの順（`src/ui/interrupts.ts` の `nextInterrupt`）。同じ瞬間に 2 つの村へ着いたときは最初の村の会話だけ出る（今は 1 ステージ 1 村）。負けが決まった瞬間は、止めずにそのまま負けの画面。会話に入るとき、構えていた必殺技・ドラッグ・セリフ欄は片付く。

一度きりのごほうび（`xp`・`stat`）を受け取ったあとの村、すでに仲間にいる人の `recruit` の村は、会話を出さず、「村の 人が 手を ふっている」とセリフ欄に出るだけで、戦闘は止まらない（遊び直しのたびに同じ会話を読まされないため。出来事の `fresh` が `false`）。村人は `assets/npcs/` に置く（顔は今は 6 人とも同じ仮の絵）。

説得の相手は敵として出てくる。普通の敵と同じに扱うので、仲間は攻撃し、相手も攻撃する。決められた仲間（`persuader`）が相手から 2マス（64px）以内に入ると、加入の会話が始まり戦闘が止まる。会話が終わると相手は消え、同じ場所に新しい仲間が加わる。説得の相手の頭上には黄色い吹き出しの目印が出る。倒してしまった相手は説得できない。

加入・経験値・能力値の上昇は、クリアしたときだけセーブに残る。負けたら残らない。仲間は最大 15 人まで記録でき、場に出るのは 8 人まで。場がすでに 8 人のとき、説得も村の加入も会話は流れ、仲間は記録される（そのステージでは場に出ず、クリアすると加わったときのレベルで次から出撃の候補になる）。場に出る 8 人は、配置の場面で選べる（次の「出撃を選ぶ」）。選ばなかった仲間は、そのステージでは出撃しない。下パネルの下の段は 8 人まで並び、ステージ選択の仲間一覧は 3 列で 15 人まで並ぶ。

### 出撃を選ぶ

そのステージで場に出られる仲間（出撃の候補）が 8 人を超えるときだけ、配置の場面の上段が左「出撃を 選ぶ」・右「始める」に分かれる。8 人以下のステージは今までどおり上段全体が「始める」。

- 「出撃を 選ぶ」を押すと、候補の一覧（3 列、15 人まで）が重なる。枠を押すと入れる・外すが切り替わり、出撃している枠は金色の縁と「出撃」が出る。右上に「n / 8」。枠の右下の「強さ」を押すとその仲間のカードが開き、閉じると選んだ内容のまま一覧に戻る。一覧の外を押しても閉じない（閉じるのは「決める」だけ。選び直しが消えるため）
- 外せないのは、負けの条件（`defeat` の `unitLost`）の仲間だけ。押すと「（名前）は 倒れたら 負けなので 外せない」と出る。8 人のときに入れようとすると「8 人まで。先に 誰かを 外す」と出る。説得する役の仲間（`persuader`）は外せる（印も出さない）。外して始めた回は、その説得ができず、相手は敵のまま
- 「決める」で、選んだ内容で戦いの状態を作り直す。残した仲間は置いた場所のまま、外した仲間はマップから消え、入れた仲間は空いた開始位置に出る。加入の記録・レベル・村のごほうびの記録は変わらない（開始時に加わる仲間を外しても、加入の記録は残る）
- 「始める」を押したときの出撃を、前回の出撃としてセーブ（`sortie`）に残す。次にステージの配置の場面に入ったときの最初の出撃は、外せない仲間 → そのステージの開始時に加わる仲間 → 前回の出撃 → 自動の順（開始時の加入 → `roster` → 加わった順）で 8 人まで。セーブに前回の出撃が無いとき（最初・ボット）は自動の 8 人
- 負けて「もう一度」を押すと、同じ出撃・同じ置き場所で始まる（置き場所はセーブに書かず、画面の側で覚える）
- すでに加入している仲間を出撃から外しても、村での加入はやり直しにならない（セーブの `members` も見る）

仲間が倒れると、画面の時間が 0.3 倍のゆっくりになり、マップの中ほどに帯（顔・名前・最期の言葉）が 1.5 秒出る。倒れた仲間は 2.5 秒点滅してから消える（点滅は画面の時間、帯とゆっくりは実時間。計算は倒れた瞬間に退場済みで、点滅の間も狙われない）。2 人が続けて倒れると帯は 1 人ずつ順に出て、ゆっくりが延びる。最期の言葉は帯で出すので、セリフ欄には出さない。村の会話・レベルアップのカード・加入の会話が始まると、会話・カードの間はゆっくりも帯も止まり、終わった後に残りの時間だけ続く。護衛対象が倒れて負けになる場合は、帯もゆっくりも無く、今までどおりすぐ負けの画面へ進む。仕組みは `src/ui/fallen.ts`（順番とゆっくりの長さ）と `src/render/effects.ts`（点滅）。

必殺技には 11 個すべてに見た目がある（`src/render/skill-fx.ts`。図形で描く）。駆け抜ける・急降下は、計算では一瞬で行き先に着くが、画面の上だけ 0.6 秒かけて滑る（急降下は弧を描いて飛ぶ）。通り道の敵の数字・火花・倒れる白い輪と、行き先で殴られる数字は、見た目がそこを通る・着く時刻まで遅れて出る（描く時刻だけをずらし、計算は変えない）。滑っている仲間へ移動の指示を出すと、滑りを打ち切って計算の位置から続ける。

戦闘中のセリフは下パネルの上段に数秒だけ出る。時間は止まらない。同じ瞬間に複数のなかまが喋ったときは、優先度の高い1件だけを出す。盤面にはかぶらない。

移動先は出撃している仲間の全員ぶんが常に表示される。選択中のなかまだけ、現在地から目的地への線が引かれる。指示した移動は交戦しても最後まで進む（歩きながら攻撃する）。戦闘中に歩けない場所やマップの外を指すと、そのなかまがたどり着けるマスのうち最も近いマスへ移動する（ドラッグ中のプレビューも置き換え後の行き先に出る）。配置は黄色い線より下の、足元の箱（「アセットの大きさの規約」）が歩けるマスに収まる位置にできる。通れないマスの脇やマップの端から 6px 以内は、箱がはみ出すので置けない。配置中にドラッグ先が線より上か、箱が歩けないマスやマップの外にかかる位置だと、プレビューの線と丸が赤く変わり、そのまま離しても失敗することが事前にわかる（配置では内側に寄せない）。通れないマス（木・岩など）のすぐ脇を指したときは、足元が通れないマスにかからない位置まで内側に寄せて移動する。森のマスは通れるが、中では移動の速さが半分になる。指示した目的地までまっすぐ行くと森を通るときは、森を回った方が早ければ回り道する（森の中を目的地にすれば森に入る）。敵も同じ。

敵となかまは 24px（近接の間合い）より近づかない。指示した移動の途中に敵がいると横へすべって回り込み、真正面をふさがれたときはその手前で止まる。近接のなかまは、移動の指示がなく誰とも戦っていないとき、2マス（64px）以内の見えている敵へ自分から詰め寄って攻撃する。ただし、ほかのなかまがすでに戦っている敵には詰め寄らない（詰め寄っても交戦できないため）。倒したあとは元の位置へ戻らない。

敵の索敵範囲は表示しない。気づかれた瞬間、その敵の頭上に赤い「！」が2秒だけ出る。追われているあいだずっと出しっぱなしにはしない。

## 開発

必要なもの: Node.js 22 以上

```bash
npm install
npm run dev     # 開発サーバ
npm test        # ユニットテスト (Vitest)
npm run build   # 型チェック + 本番ビルド (out/play/character-tactics/)
npm run balance # ステージの難易度を測る（下の「難易度を測る」）
```

### 難易度を測る

`npm run balance [-- <シード数（既定 40）>] [--check]` は、ボットに全ステージを通しで遊ばせ、ステージごとの勝率などを表で出す。

- ボットは「敵を全部倒してからゴールへ」向かう。味方は最寄りの敵へ詰め、説得の相手・加入の村・必殺技も扱う。敵（時間湧きの残りを含む）が残る間は、ゴールの半径 + 20 の円の中へ入らない（目的地を円の外へ押し出し、最短の道が円を横切るときは円を避ける道の途中の点へ向かい、円の縁に入りかけたらすぐ指示を出し直す。技の目的地も同じ。ゲームの決まり「ゴールに着けば勝ち」は変えない）。シードごとに開始位置の割り当てと反応の遅れ（0〜1.5 秒）を揺らす。動きの細部は `src/core/balance.ts` の冒頭コメントを参照
- 1 ステージで負けたら、同じ編成のまま最大 5 回まで挑み直す。表の「1回目の勝率」（通し）は、1 回目で勝った通しの割合（そのステージに到達した通しに対する %）。「育てた」は、通しでそのステージに着いたときのセーブの全員のレベルを +3（`GROWN_LEVEL_BOOST`、上限 30、経験値は 0）して遊んだ 1 回目の勝率で、通しの結果には反映しない。ほかに出撃人数の平均・生き残りの平均・平均Lv（勝った通しで、出撃した仲間のクリア後の平均レベル）・敵が残った勝ち（%。1 回目の勝ちのうち、終わったとき敵が残っていた割合。ボットの直しの後は全ステージ 0 になるはず）が出る
- 目標の帯は `src/core/balance.ts` の `TARGET_BANDS`（通し。ステージごと）と `GROWN_BAND`（育てた。全ステージ 80〜100）。外には「帯の外(通し)」「帯の外(育てた)」「帯の外(突っ込み)」と出る。`--check` を付けると、どれかが 1 つでもあれば終了コード 1（引数の不正やアセットの読み込み失敗は 2）。`--check` は既定の 40 シードで使う（少ないシード数だと勝率がぶれて帯の外に見える）
- **突っ込み・急ぎ**: 通しのシード 1〜`RUSH_SEEDS`（10）では、各ステージに着いたときのセーブで、1 人だけをゴール（`victory.pos`）へ走らせる戦いも測る（`runRush`）。走らせる仲間は歩き（飛行でない仲間で一番足が速い 1 人）・飛行（飛行の仲間 1 人）・ガウの 3 通り（出撃していなければ測らない）。走る仲間は交戦中でも止まらず、技も使い、行き先はゴールの向き（「駆け抜ける」「急降下」は届く距離 `maxCells` で止めた点）。残りの仲間は開始位置で待つ。表の「突っ込み(%)」は勝った割合で、**3 通りのどれかが `RUSH_MAX`（10）を超えたら帯の外**。全員がゴールへ向かう「急ぎ」も測り、「急ぎ(秒)」は金・銀・銅の目安の時間を決める材料にする（帯には使わない）。「クリア(秒)」は通しの 1 回目の勝ちの時間の中央値
- 突っ込みを止める仕組み: ゲームの決まりで、1 人を同時に攻撃できる敵は 1 体だけなので、敵が増えても突っ込む仲間は早くは倒れない。そこで各ステージのゴールの手前に、持ち場を離れない見張り（`ai.kind: "guard"`、`leash` 2・`sightRange` 140 前後）を、すき間が 48px 以下（敵どうしは押し合わず、これを超えると通れる）になるように並べて道をふさぎ、倒すまで足止めする。壁の端は壁の縁から 11px に置く。ふさぐ数は通路の幅で決まる（ステージ 8 は飛ぶ仲間が家や柵を越えるので、ゴールを囲む半円）。最初に相手を攻撃した敵が相手を握るので、壁には射程の長いまじない師より近接の敵・弓兵を使うと早く倒せる。「駆け抜ける」「急降下」は 14 秒で再使用でき、足止めの間に再使用が来ると跳び越えてしまうため、再使用の時間は足止めの時間より長くしてある。壁の置き方と測定の結果は `docs/superpowers/specs/2026-11-18-clear-score-results.md`
- ボットは人より下手（状況を見て退いたり必殺技を温存したりしない）なので、数字は人が遊ぶより厳しめに出る
- 帯の表と、調整ごとの測定結果・最終の判定は `docs/superpowers/specs/2026-11-16-growth-classes-results.md`（工程 4。直前までの調整は `2026-11-11-difficulty-tuning-results.md`）にある。帯に入れるために動かしてよいのは、仲間と敵の初めの値・伸び方、`enemyLevel`、加わったときのレベル、技の基本量、経験値の数字、`bowDamageCap`、ゴールの手前の敵の配置、「駆け抜ける」「急降下」の再使用の時間と届く距離。地形は動かさない。敵の配置は、ゴールの手前の壁だけ（敵の数は 16 体まで）
- 所要時間は 40 シードで約 5 分（通しに加えて、育てた場合を各ステージで 1 回ずつ、突っ込み・急ぎをシード 1〜10 で遊ぶため）

### 描画と入力をブラウザで確認する

描画コードにはユニットテストを書かない方針なので、`drawTalk` / `drawSpeechBar` の見た目や
ポインタ操作は実ブラウザで確かめる。**Playwright パッケージは要らない。** Chromium の
バイナリさえあれば（`~/.cache/ms-playwright/` に落ちているものでよい）、追加の依存なしで
CDP から駆動できる。

```bash
npm run build                       # out/ を任意の静的サーバで配信する
chrome --headless=new --no-sandbox --disable-gpu \
       --remote-debugging-port=9222 --window-size=540,945 <URL>
```

`http://127.0.0.1:9222/json/list` から WebSocket に繋ぎ、`Runtime.evaluate` で
`document.getElementById('game')` に対して `PointerEvent` を直接 dispatch してタップと
ドラッグを送り、`Page.captureScreenshot` で画面を撮る。`Input.dispatchMouseEvent` は
headless Chromium で `pointerdown` / `pointerup` として正しく届かないことがあるため使わない。
論理座標 540×945 からクライアント座標への変換は `computeViewport` と `fitCanvas`
（どちらも `src/render/viewport.ts`）と同じ式を使う。

判定はスクリーンショットを見るほか、`getImageData` で色の塊を数えると機械的に取れる。
セリフ欄のパネルは `#f7f3e6`、ユニットの丸は各 def の `color`。下部バーのポートレートも
同じ色なので、マップ領域（論理 y が 50〜786）に絞ること。

**確認しにくいもの:** 飛翔体（弓・魔法）は着弾までの数フレームしか画面に映らないため、
`Page.captureScreenshot` を短い間隔で連写しないと捉えられない。

URL に `?debug` を付けると、戦闘中だけ次の操作ができる（攻撃のコマを確かめる用。付けなければ何も変わらない）。各ユニットの足元の下に今のモーション名とコマ番号（例: `attack 2`）が、画面左上に今の速さが出る。

| キー | 動作 |
|---|---|
| `P` | 一時停止と再開を切り替える |
| `.` | 一時停止中に、シムを1ステップ（1/60秒）進める |
| `S` | 1/4 の速さと通常の速さを切り替える |

## アセットの大きさの規約

絵の1画素を論理座標（540×945）の1pxで描く（等倍）。等倍にしないのは表の「表示」に書いたものだけ。
画面全体は端末に合わせて整数でない倍率で拡大・縮小するので、規約で揃えるのは「絵の1画素＝論理座標の何px」まで。

| アセット | 絵の大きさ | 表示 | 占める範囲 |
|---|---|---|---|
| 1マス | ― | 32px | ― |
| 地面タイル | 16px | 等倍。1マスに2×2で敷く | 1マス |
| 物（村・岩・木・城など） | 16pxの部品を組んだセット。1マスぶんは2×2（32px） | 等倍 | 1マス以上の整数マス（城は2×2マス＝64pxなど） |
| ユニット | コマ32px（大型は48px） | 等倍 | 足元 y=30・左右中央・背丈24〜26px |
| 顔グラ | 64px | 会話・セリフ欄は64px（等倍）、仲間一覧・リザルト・下のバーは32px（半分） | ― |
| 役割アイコン | 16px | 32px（2倍） | ― |

- 物の絵は地面（草）を背景に含めて描く
- 顔を縮小して描くときだけぼかす（`smoothFor`、`src/render/sprites.ts`）。ほかはドット絵のまま
- 顔の枠の大きさは `FACE_PX`、役割アイコンの枠は `roleBadgeIn`（どちらも `src/ui/layout.ts`）
- ユニットの当たり判定は足元の箱（足元の点から左右6px・下2px・上0px。`src/engine/footprint.ts`）。通れないマスに横と上からはめり込まない。下から近づいたときに頭が上のマスに重なるのは、マスの手前に立っている見え方として残す

**まだ規約に追いついていないもの:** 複数マスを占める物をマップに置く仕組みはまだ無い。
顔（128px）と役割アイコン（32px）の画像は規約より大きく、縮小して描いている。

## ドット絵の作りかた

ドット絵は `pixel-asset-forge/` で作る。pixel-asset-forge（forge）をこのリポジトリへ丸ごとコピーしたもので、このゲームに合わせて自由に直してよい。コピー元の commit と、forge に戻す候補は `pixel-asset-forge/UPSTREAM.md` にある。絵の描き方と規約は `pixel-asset-forge/README.md` と `pixel-asset-forge/types/*/SPEC.md`。

確認の道具（`pixel-asset-forge/tools/unit_rules.py` など）で落ちたら、道具に従って絵を直して通す。直してよいか、道具の判定を変えてよいかを、途中で依頼者に聞かない。依頼者には、直し終えた完成品を見せる。`pixel-asset-forge/ISSUES.md` に記録済みの原因で落ちたときは、絵を変えずに ISSUES.md に記録する。詳しくは `pixel-asset-forge/CLAUDE.md` の「確認の道具で落ちたら、道具に従って絵を直す」。

forge の生成物のうちゲームで使うものは、ルートの `sprites.json`（forge の `build/` からの相対パス → `assets/images/` のファイル名）に書き、次のコマンドで `assets/images/` へ書き出す。書き出した PNG はコミットする（デプロイでは Python を使わない）。

Python は 3.14 を使う（3.10 では forge のテストが落ちる）。venv は [uv](https://docs.astral.sh/uv/) で作る。

```sh
uv python install 3.14   # 初回だけ
uv venv --python 3.14 pixel-asset-forge/.venv   # 初回だけ
uv pip install --python pixel-asset-forge/.venv/bin/python -r pixel-asset-forge/requirements.txt   # 初回だけ
cd pixel-asset-forge
# 1 段目: build/ を空にして、タイル・セット・味方のシートを作る
# 2 段目: 敵のシートを build/sheets/ に足す（build/ を空にした後に流す）
# 3 段目: assets/images/ へ書き出す
# 前の段が失敗したら次の段へ進まないよう、&& でつなぐ
.venv/bin/python -c "import sys; sys.path.insert(0,'tools'); import export; raise SystemExit(export.build())" &&
.venv/bin/python tools/enemy_build.py --all &&
.venv/bin/python -c "import sys; sys.path.insert(0,'tools'); import export; from pathlib import Path; export.export(Path('../sprites.json'), Path('../assets/images'))"
```

`sprites.json` に敵のシートを含むので、書き出しは上の 3 段で行う（`export.build()` で `build/` を作り直し、`enemy_build.py --all` で敵のシートを足し、`export.export()` で書き出す）。順序を入れ替えない: `enemy_build.py` を先に流すと `export.build()` が敵のシートを消し、`export.build()` を省くと `build/` が空のときにタイル・セット・味方のシートが無い。`export.py sprites.json assets/images` をそのまま流すと、`export.py` が最初に `build/` を消して `enemy_build.py` は実行しないため、敵のシートが無く必ず失敗する。

`export.py` は書き出しの前に `build/` を空にして、forge の全アセットを描き直す。`sprites.json` に書いていない絵でも、1枚でも検査に通らなければ `FAIL` で止まり、何も書き出さない（原因の `FAIL` の行は標準エラーに出る。`2>&1 >/dev/null` を付けると原因の行だけが見える）。

エンジン・規約・道具を直したら、`pixel-asset-forge/.venv/bin/python -m unittest discover -s pixel-asset-forge/tests` を通し、`UPSTREAM.md` の「forge に戻す候補」に1行足す。

### ユニットの動きをページで見る

マップスプライトのアニメーションは、ゲームを動かさなくても、次のコマンドで作るページで見られる。待機・歩き・攻撃を4方向ずつ、ユニットの JSON と同じ fps で再生する（拡大と等倍・2倍、止める・1コマ送る、速さ、背景、足元の線 y=30）。

```sh
python3 tools/anim-page.py assets/units/roran.json out/anim/roran.html
```

シートは `assets/images/` に書き出した PNG を読むので、`export.py` の後に作る。ページは画像を埋め込んだ HTML 1枚で、ブラウザでそのまま開ける。依頼者に見せるときは、この HTML を Artifact として公開する。ひな形は `tools/anim-page.html`。

## コンテンツの足しかた

コードを書き換えずに足せるもの:

- **ステージ** — `assets/stages/<id>.json` を1本置く。**`parTimes`（必須）** はクリアの時間（秒）の金・銀・銅の目安で、整数・金 < 銀 < 銅（そうでなければ起動時エラー）。新しいステージは、`npm run balance` の「クリア(秒)」「急ぎ(秒)」を見て決める。直すと前の記録の評価も変わる。ファイル名と `id` を一致させ、`order` に並び順を書く（昇順に並ぶ。欠番は自由、重複は起動時エラー。10, 20, 30 と空けておくと後から間に挟める）。**並び順を決めるのは `order` だけで、`id` の数字ではない**（ガルム戦は `stage3` のまま `order: 100` で最後尾にいる。`id` はセーブデータのクリア記録が参照するので、あとから振り直さない）。マップは **16列 × 23行、`cell` は 32**。`placement.minY` より下（画面で下）の歩けるマスが配置できる範囲で、`placement.starts` に開始時の立ち位置を並べる（roster より少なければ先頭から繰り返す）。**敵と時間湧きは `placement.minY` より上（`y < minY`）に置く**。線より下はプレイヤーの配置範囲なので、置くと起動時エラーになる。敵・開始位置・時間湧き・見張りの持ち場は、足元の箱（「アセットの大きさの規約」）が通れないマスにかからない位置に置く（かかると起動時エラー）。`victory.pos` は最上段に置く（下から上へ攻める）。**`enemyLevel`（1 以上の整数、必須）** は、そのステージの敵（配置・時間湧き・説得の相手）のレベルで、敵の能力はこの値で決まる（始まりの道が 1、ガルムの最後が 16。遊ぶ順に下がらない（テストが見る））。マスの文字の意味は `legend` で決められる（`{ ".": { "tile": "tile-plain.png", "walkable": true }, "T": { "tile": "tile-tree.png", "walkable": false }, "F": { "tile": "tile-forest.png", "walkable": true, "speed": 0.5 } }` の形。キーは1文字、`tile` は `assets/images/` のファイル名か `null`。`speed` はそのマスでの移動の速さの倍率で、省略時は 1、0.1 以上 1 以下（これより遅いマスは事実上通れないので `walkable: false` にする）。通れないマスには書けない。`light` はそのマスにある明かり（たき火・燭台など）の輪の半径 px で、8 以上 160 以下の整数。歩けないマスにも書ける。ステージの `darkness`（0 より大きく 0.9 以下。画面に重ねる暗い膜の濃さ）を書いたステージだけで使え、書かないステージに `light` があると起動時エラー。膜はマップの範囲だけにかかり、`light` のあるマスのまわりを放射状に抜く。輪の大きさと明るさはゆっくり揺れ、絵は止まった 1 枚のまま。`darkness` を書かないステージは今までどおり暗くしない）。`legend` を書くと `mapRows` にはそのキーだけが使え、書かなければ `.`（歩ける）と `#`（歩けない）を単色で描く。タイル画像は 16×16 か 32×32 で、拡大せず元の大きさで敷く（16px なら1マスに 2×2、32px なら1枚。ほかの大きさだと `npm test` が落ちる）。タイルは `sprites.json` に書いて `tile-<名前>.png` として書き出す（「ドット絵の作りかた」）。地面（16px）は `tile/<名前>.png`、物（村・岩・木など、32px）は `sets/<名前>.png` を指す（forge の `build/tile/` にも同じ名前の 16px の旧版 `village` `rock` `tree` があるが、そちらを指すと1マスに4つ並ぶ。16px も 32px も `npm test` は通るので、検査では気付けない）
- **ステージ開始時の会話** — ステージの `intro` に書く。`speaker` を省略すると地の文になり、本文は `text` に直書きするか `lineId` で `assets/lines/` を参照する（両方書いても、どちらも書かなくてもエラー）
- **本拠地に到達したときの会話** — ステージの `outro` に書く。書き方は `intro` と同じ
- **味方・同行 NPC** — `assets/units/<id>.json`。`combat: false` にすると攻撃しない同行者になる。**`growth`（必須）** は、5 つの能力（`maxHp`・`power`・`guard`・`resist`・`speed`）の 1 レベルあたりの伸び（0 以上、小数可）。能力 = 初めの値（JSON の `maxHp` などの値。レベル 1 の値）+ `floor(伸び × (レベル − 1))` + 村のごほうび。毎回同じ値が上がる（運は無い）。`speed` は移動の速さ（px/秒）なので伸びは 0 にする（テストが見る）。どの仲間も、伸びが 0.5 以上の能力を 1 つ以上持つ（テストが見る）。魔法で攻撃する仲間（`attack: "magic"`）は `power` が魔力になる
- **敵** — `assets/enemies/<id>.json`。仲間と同じ `growth`（必須）を持つ。敵は戦闘の中では育たず、能力はステージの `enemyLevel` で決まる（見た目違いのファイルも同じ `growth` にそろえる）。倒したときの経験値は `xpReward + enemyLevelXp × (敵のレベル − 1)`。1 ステージの敵は、時間湧き（`spawners` の `total`）を含めて 16 体まで（`npm test` が見る）。説得の相手は数えない（`npm test` が数えるのは `enemies` と `spawners` の `total` の合計。説得の相手を入れると戦場に 17 体になるステージがある）。敵の攻撃は、そのステージに加わる頃の仲間（レベル 1 の初めの値ではなく、加わったときのレベル）が 1 発で倒れない強さにする（最も打たれ弱い ally06 は HP が低く、まじない師の魔法が痛い。敵の攻撃力は `enemyLevel` で上がるので、`enemyLevel` を上げたら見直す）。こちらはテストでは見ていない
- **敵の見た目** — 見た目ごとに別の ID の定義を持つ（今は 22 個。ならず者 14・盾持ち 2・弓兵 3・まじない師 3）。同じ種類は `kind` を同じにし、強さの数値・攻撃の型・`role`・`face` を揃える（揃っているかは `src/engine/enemy-looks.test.ts` が見る）。初対面の会話とセリフの鍵は `kind` で見る。forge の絵の書き出しは「ドット絵の作りかた」の 2 段の手順で行う（`export.py` の単独実行は敵のシートが消えて失敗する）。ステージへの割り当ては、盾持ち・弓兵・まじない師はステージ番号でずらした巡回、ならず者はステージ 1 から `enemies` の出てくる順にステージをまたいで 14 通りを続けて巡回する（同じステージで同じ ID は 2 回出ない）
- **時間湧きの敵** — ステージの `spawners` に `{ "defId": ..., "pos": ..., "firstAfter": 20, "every": 15, "total": 3 }` を並べる。`firstAfter` 秒後に1体目、以降 `every` 秒ごとに1体、合計 `total` 体まで湧く。湧いた敵の AI は `aggressive` 固定。総数上限は必須（上限がないと持久戦で詰む）
- **守備と魔法防御** — ユニットの定義の `guard` は近接と弓のダメージを、`resist` は魔法のダメージを引く。魔法系は `resist` を高く、盾・斧系は `guard` を高くする。村の上乗せ（`stat`）にも `resist` がある。`ignoresGuard: true`（省略時 false）は、通常の近接・弓の攻撃が相手の守備を 0 として計算する（斧）。`flying: true`（省略時 false）は飛行で、歩けないマスの上を一直線に飛び、森でも遅くならない。マップの外には出ない。飛行の足元には影が出る
- **ユニットの絵** — `assets/images/` に PNG を置き、`assets/units/<id>.json`（敵は `assets/enemies/<id>.json`）の `sprites` に書く。`role` はクラスアイコン、`face` は顔（下パネル・ステージ選択・会話・リザルト）。大きさは「アセットの大きさの規約」、`map` はフィールド上の姿。`map` だけはスプライトシートで、`{ "sheet": "<file>.png", "frame": 32, "idle": { "frames": 2, "fps": 4 }, "walk": {...}, "attack": {...} }` の形。シートは**列 = コマ、行 = 12（3状態 × 4方向）**で、行番号 = 状態index × 4 + 方向index、状態は `idle, walk, attack`、方向は `down, up, left, right` の順。コマは正方形。列数は最大コマ数にそろえ、余りは透明のまま置く。`map` が `null` のあいだは色つきの丸だけが出る（クラス名の文字は `role` が `null` のときに出る別のフォールバックで、`map` とは無関係）。`frame` と各状態の `frames` は1以上の整数、`fps` は1以上の数値であること。実寸と JSON が食い違うと `npm test` が落ちる（`src/engine/sheet-size.test.ts`）。コマの**下から 2px 上の行（32px のコマなら y=30）が足元**で、そこがユニットの位置に来るように描く（pixel-asset-forge の `unit` 規約と同じ）。HPバー・旗・リングは絵の中心を基準に置く
- **仮の絵の作り直し** — 今の仮の絵は、味方（ally05〜15）と説得の相手（ally06-foe・ally08-foe）と村人の顔（npc01〜06。顔だけ）の分だけ（敵の絵は forge で組んだ本番の絵）。`node tools/gen-placeholder-sprites.mjs ally05 role-yari ...`。引数に書いた ID の絵だけを書く（引数なしでは何も書かずに終わる。全部を書き直すと今の本番の絵を仮の絵で上書きするため）。本番の絵が揃ったらこの生成器は消してよい。差し替えは PNG を上書きするだけで、コマ数を変えるときだけ JSON の数値を直す
- **攻撃の種別** — `attack` は `melee` / `bow` / `magic`。ダメージ（`bow` と `magic` では飛翔体の発射）は、攻撃モーションの最後のコマが出る時刻（`(attack.frames - 1) / attack.fps` 秒後）に出る。その前に攻撃した側か相手が倒れたら、その攻撃は出ない。`map` が `null` のユニットは攻撃した瞬間に出る。`bow` と `magic` は飛翔体として飛び、届いた瞬間にダメージが出る。`bowDamageCap` が効くのは `bow` だけ
- **仲間の加入・村・説得** — ステージに `joins`・`persuasions`・`villages` を書く（どれも省略できる）。加入する仲間は `assets/units/<id>.json` に置く。
  - `joins` は、ステージ開始時に会話のあと加わる仲間。`talk` は会話（`intro` と同じ書き方）、`level` は加わるときのレベル。
    `"joins": [{ "unitId": "ally05", "level": 2, "talk": [{ "speaker": "ally05", "text": "俺も 連れて いってくれ！" }, { "text": "{ally05}が 仲間に 加わった！" }] }]`
  - `persuasions` は、`joins` の項目に `foeId`（相手の敵の ID）・`pos`（`placement.minY` より上の歩けるマス）・`ai`・`persuader`（相手に近づけば説得が始まる仲間の ID）を足したもの。
    `"persuasions": [{ "unitId": "ally06", "level": 4, "foeId": "ally06-foe", "pos": { "x": 304, "y": 176 }, "ai": { "kind": "sentry", "sightRange": 150 }, "persuader": "mist", "talk": [ ... ] }]`
  - `villages` は `id`（ステージ内で一意）・`col`・`row`（通れないマスに置く。同じマスに2つ置けない）・`text`・`effect`・`npc`・`talk`（`npc` と `talk` は省略できる）。`npc` は話す村人の ID（存在を検証する）、`talk` は村人と訪れた仲間の会話で、`intro` と同じ書き方。`speaker` に村人の ID（例 `npc01`）を書き、訪れた仲間に話させる行は `"$visitor"` と書く（`talk` の中だけ）。本文の `{visitor}` は訪れた仲間の名前に置き換わる（`talk` と `text` に直接書いた本文だけ。`lineId` で `assets/lines/` を参照する本文や、`intro` などに書くと起動時エラー）。`text` は会話の最後に地の文で出る「何が起きたか」の行で、`{visitor}` を使える。`recruit` の村は `talk` の後に加入の会話が続く。`effect` は `{ "type": "heal" }`、`{ "type": "powerUp", "amount": 2 }`、`{ "type": "xp", "amount": 10 }`、`{ "type": "stat", "stat": "guard", "amount": 1 }`、`{ "type": "talk" }`、または `recruit`（`unitId`・`level`・`talk` を `effect` の中に書き、`text` は書かない）。
    `"villages": [{ "id": "v1", "col": 11, "row": 10, "text": "村の 人が けがの 手当てを してくれた！", "effect": { "type": "heal" } }]`
  - 本文で仲間の名前を書くときは `{<ユニットID>}`（例 `{ally05}`）と書く。読み込み時に名前へ置き換わり、知らない ID は起動時エラーになる。
  - **新しい仲間の ID は名前と関係ない `allyNN`（説得の相手の敵は `allyNN-foe`）にする。** JSON のファイル名・`assets/images/` の名前・セリフのキー・セーブのキーに名前を入れない。名前が出てよいのは、ユニットの JSON の `name` と本文（`{id}` で書く）だけ。今の4人（`roran` `ines` `mist` `gau`）の ID は変えない。
  - 仲間は最大 15 人（`roster` と加入しうる仲間の合計。超えると読み込みで止まる。`MAX_MEMBERS`）。場に出るのは 8 人まで（`MAX_PARTY`）。
- **村人** — `assets/npcs/<id>.json`（`id`・`name`・`color`・`sprites.face`）。ID は名前と関係ない `npcNN`。顔は `assets/images/npcNN-face.png`（今は仮の絵で 6 人とも同じ）。本番の絵に替えるときは PNG を上書きし、JSON の `name` を直すだけで、コードは直さない。村の `talk` の `speaker` に書くと会話の話し手になる（仲間・敵・村人の順に ID を引く）
- **セリフ** — `assets/lines/*.json`
- **絆** — `assets/bonds.json`
- **成長の調整** — `assets/growth.json`。`xpPerLevel`（レベルアップの必要量。レベル n から n+1 に n × `xpPerLevel`）、`enemyLevelXp`（敵のレベルが 1 上がるごとの撃破の経験値の加算。0 以上の整数）、`hitXp` / `healXp` / `assistRatio` / `clearXp`（経験値の入り口）、`maxLevel`（30）。1 レベルの強化量は、仲間・敵それぞれの `growth`。経験値が小数にならないよう `hitXp` / `healXp` / `clearXp` は整数で検証する

コードが要るもの:

- **新しいスキル** — 今あるのは踏ん張る・狙い撃ち・おまじない・駆け抜ける・引きつける・火の雨・突き・はげます・たたき割り（守備を無視する 1 体への固定ダメージ）・結界（範囲の味方の魔法防御を一定時間上げる）・急降下（指した場所へ飛び、着いた場所の周りの敵に固定ダメージ）。足すときは `src/core/skills.ts` の `SKILL_EFFECTS` に効果を足し、`assets/skills.json` に数値を足し、`src/render/skill-fx.ts` の `SKILL_FX`（描き方）と `SKILL_FX_DURATION`（演出の秒数）に見た目を足す（11 個すべて必要で、`effects.test.ts` が見る）。効果は `out.aim`（指した所など）と `out.affected`（効いた相手の位置）に描画用の値を書く。ドット絵に替えるときは、その技の描き方だけを替える。駆け抜ける・急降下は指した所が遠すぎると、向きを保って `params.maxCells`（マス数。今は 4）で止めた所へ行く（止めた所が壁なら駆け抜けるは出ない）。ダメージを与える技（駆け抜ける・火の雨・突き・たたき割り・急降下）の `damage` と、おまじないの `heal` は基本量で、実際の量は「基本量 + 使ったユニットの攻撃力（魔力）」（`skillAmount`。はげます・村の加算は含めない）。技のダメージは守備・魔法防御を引かない。`assets/skills.json` の各スキルには `params.cooldown`（秒）と `summary`（カードに出す一言の説明。`{duration}` のように `params` のキーを書くと値に置き換わる。`params` に無いキーは起動時エラー）が必須
- **新しい AI パターン** — `src/core/ai.ts` の `AI_BEHAVIORS` に足し、`src/engine/schema.ts` の `AiDef` と `AI_KINDS` に variant を足す
- **新しい勝敗条件** — `src/engine/schema.ts` の `VictoryCond` / `DefeatCond` に variant を足し、`src/core/objectives.ts` で判定を書く

JSON が壊れていると起動時にエラー画面が出て止まる。どのファイルのどのフィールドがなぜ不正かが出るので、それを直すこと。

## デプロイ

`main` への push で GitHub Actions がビルドし、Cloudflare Workers Static Assets へデプロイする。

ビルド設定で注意する点:

- `vite.config.ts` の `base` は `/play/character-tactics/`
- `vite.config.ts` の `build.outDir` は `out/play/character-tactics`（`out` 直下にすると、パス付きルートの Workers では deploy が失敗する）
- `wrangler` は `^4` 系に固定し、CI の Node.js は 22 以上にする
